可以用度的角度来思考，16 条边一共贡献了 32 个度

也就是 4 * n 4  + 3 * n 3 + ... = 32 即 4 * 3 + 3 * 4 + ... = 32

因此对于剩下的度 < 3 的顶点来说他们所占的总度数是固定的，就是 32 - 24 = 8

为了让顶点尽可能少，那么让每个顶点的度尽可能大即可，即每个顶点 2 度，此时再增加 4 个顶点就行了

### 3 操作系统引导与磁盘的物理逻辑格式化

![image.png](https://typora-1310242472.cos.ap-nanjing.myqcloud.com/typora_img/20251204080247.png)


**物理格式化**

（1）扇区划分，划分物理扇区和磁道
（2）一般由厂家完成

**硬盘分区**

（1）将硬盘进行划分（C 盘，D 盘）
（2）每个分区创建引导扇区和分区表，便于 OS 管理

**逻辑格式化**

（1）每个分区进行文件系统格式化
（2）所有和文件系统相关的初始化工作在这一步完成，比如文件系统根目录，初始化索引结点表等等

**操作系统初始化（加载过程）**

（1）电源自检，确保所有硬件设备正常并就绪

（2）执行主板 ROM 区中的 BIOS，BIOS 负责硬件初始化，中断向量初始化工作，并进一步自检

（3）通过自检之后 BIOS 将硬盘 0 号扇区（最开始 512 字节）的主引导记录 MBR 读入，此时 MBR 接过 CPU 控制权

（4）MBR 包括磁盘引导程序和分区表两部分，具体来说此时就是 MBR 中的磁盘引导程序被执行，通过查找分区表判断操作系统在哪个分区，并将分区引导记录 PBR 调入内存执行，CPU 控制权交给 PBR

（5）具体来说就是 PBR 中的分区引导程序在执行，分区引导程序找到操作系统初始化程序，并将控制权交给操作系统初始化程序（启动管理器）

（6）操作系统初始化程序负责将 OS 加载到内存，接着 OS 正式接过 CPU 控制权，OS 启动完成

**OS 启动过程中的几个程序**

（1）ROM 中的引导程序：BIOS

（2）磁盘引导程序：在 MBR 中，负责查找分区表，调入 PBR

（3）分区引导程序：在 PBR 中，负责找到 OS 初始化程序

（4）启动管理器（OS 初始化程序）：负责加载 OS 到内存，让 OS 接过 CPU 控制权
