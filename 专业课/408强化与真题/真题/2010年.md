### 二叉树线索化的过程是什么？

其实很简单，以中序线索化为例，就是将一个结点的左儿子空指针指向中序遍历的前驱结点，将一个结点的右儿子空指针指向中序遍历的直接后续结点

基本思想就是用一个 p 指针和 pre 指针，在中序遍历的过程中对 p 进行左儿子线索化和 pre 进行右儿子线索化

### 二叉树线索化的代码是什么？中序遍历为例

```cpp

TreeNode* pre = NULL;


void dfs(TreeNode* root){
	if(!root) return;
	
	dfs(root->left);
	
	if(!root->left){
		root->left = pre;
		root->LTag = 1;
	}else LTag = 0;
	
	if(pre && !pre->right){
		pre->right = root;
		pre->RTag = 1;
	}else pre->LTag = 0;
	
	pre = root;
	
	dfs(root->right);
}
```

### 线索二叉树如何针对一个结点找到它的先序前驱和先序后继？

==找先序前驱==

对于这个结点

（1）如果这个结点的 LTag = 1，那么先序前驱就是左指针指向的结点
（2）如果这个结点的 LTag = 0

这个很复杂，二叉链表无法直接找到当前结点的先序直接前驱，只能重新先序遍历二叉树一遍

==找先序后继==

对于这个结点

（1）如果这个结点的 RTag = 1，那么先序后继就是右指针指向的结点
（2）如果这个结点的 RTag = 0，说明此时一定有右儿子
	i 如果左儿子为空，那么先序后继就是右儿子
	ii 如果左儿子不为空，那么先序后继就是左儿子

![image.png](https://typora-1310242472.cos.ap-nanjing.myqcloud.com/typora_img/20251026195553.png)

### 线索二叉树如何针对一个结点找到它的后序前驱和后序后继？

==找后续前驱==

（1）如果 LTag = 1，那么此时左儿子指向的就是后续前驱
（2）如果 LTag = 0，那么此时一定有左儿子
	i 如果右儿子为空，那么此时后续前驱就是左儿子结点
	ii 如果右儿子不为空，那么此时后去前驱就是右儿子结点

![image.png](https://typora-1310242472.cos.ap-nanjing.myqcloud.com/typora_img/20251026200028.png)


==找后续后继==

（1）如果 RTag = 1，那么此时右儿子指向的就是后续后继
（2）如果 RTag = 0，那么此时一定有右儿子

此时不好找到后续后继，只能重新后续遍历一遍二叉树

### 线索二叉树如何针对一个结点找到它的中序前驱和中序后继？

如果一个结点的 LTag 或者 RTag = 1，那么此时左儿子或者右儿子指向的就是中序前驱或者中序后继

如果一个结点的 LTag = 0，那么这个结点一定有左子树，此时它的中序前驱就是左子树中最右侧的结点（不一定是最下层，但是一定是最右的结点，这里的右是指一直往右子树延申，而不是空间位置更右的意思）

如果一个结点的 RTag =0，那么这个结点一定右右子树，此时它的中序后继就是右子树中最左侧的结点（右子树中尽可能往左子树延申的结点）

## 树的基本性质

### 结点数和度数的关系，3个基本方程（见题目）

假设总结点个数是 n，总度数是 m，n 1 表示度为 1 的结点个数，n 2 表示度为 2 的结点个数，n 0 表示叶结点

（1）总结点个数 - 1 = 总度数，即 n - 1 = m
（2）总结点个数  = n 0 + n 1 + n 2 +.....
（3）总度数 = n 1 + 2 n 2 + 3 n 3...

特别的，对于二叉树来说

n - 1 = m；
n = n 0 + n 1 + n 2；
m = n 1 + 2 n 2

根据上面三个方程联立得到：

n 2 + 1 = n 0，也就是二叉树的度为 2 的结点个数 + 1 = 叶结点个数
### 度为 m 的树和 m 叉树的区别（见题目）

说了 m 叉树，但是不一定有结点具有 m 个分支，只能说每个结点最多有 m 个分支

说了树的度为 m，说明这个树中必然有一个结点有 m 个分支

m 叉树不代表一定有结点有 m 个分支！

### 度为 m 的树第 i 层的最多结点数（见课本）

假设根结点在第 1 层

这种情况是每一层的结点都延申出 m 个分支，全部挂满

第 i 层最多 $m^{i - 1}$ 个结点

### n 个结点的 m 叉树的最小高度以及推导（见题目）

高度最小的情况就是所有结点都有 m 个孩子，如果这个树的高度是 h，那么如果想要高度 h 的树的结点个数最大的话，那显然每个结点都必须挂满 m 个子结点，第一层 1 个结点，第二层 m 个结点，第三层 m^2 个结点。。。。。

在这种情况下我们可以列出不等式：

![image.png](https://typora-1310242472.cos.ap-nanjing.myqcloud.com/typora_img/20250503145020.png)

得到：

![image.png](https://typora-1310242472.cos.ap-nanjing.myqcloud.com/typora_img/20250503145112.png)

即：
$$
\log_{m}(n(m - 1) + 1) \le h < \log_{m}(n(m - 1) + 1) + 1
$$

也就是：$h = \lceil \log_{m}(n(m - 1) + 1) \rceil$，上取整，表示大于等于这个量的最小整数


### 上取整和下取整的符号以及含义（见题目）


 $\lfloor \rfloor$ 是下取整符号，表示不大于自己的最大整数，即 $\lfloor 4.9\rfloor = 4$，$\lceil \rceil$ 是上取整符号，不小于自己的最小整数， $\lceil 4.9 \rceil = 5$，如果是一个整数，不管是向上还是向下取整结果都是数字本身

### 快速排序的最好情况和最坏情况的空间复杂度

最好情况是每次的枢轴元素将数组均匀划分为两个部分，这样递归深度是 log n 级别的，总的时间复杂度就是 nlogn 级别

最坏情况是每次枢轴元素都选择最小的元素，或者最大的元素，将数组划分极不均衡，这样递归深度是 n 级别的，总的复杂度就是 n^2 级别

### 归并排序的代码实现

```cpp

int q[n];//这里是待排的数组元素
int w[n];//这里是归并时候需要用到的辅助数组

void merge_sort(int l, int r){
    //如果l >= r说明此时递归到了只有一个元素，不用合并，直接返回即可
    if(l >= r) return;
    //首先确定划分中点
    int mid = l + r >> 1;
    //然后分别递归左右两边
    merge_sort(l, mid);
    merge_sort(mid + 1, r);//跟二分模板一样，如果mid = l + r >> 1则划分的区间是[l, mid], [mid + 1, r];
    //左右两边排好序之后进行二路归并
    int i = l;//左指针，从左边区间的第一个元素开始
    int j = mid + 1;//右指针，从右边区间的第一个元素开始
    int k = 0;//这里的k是临时数组的下标
    
    //如果左边没有走完并且右边没有走完的时候进行合并
    while(i <= mid && j <= r)
        if(q[i] <= q[j]) w[k ++] = q[i ++];//这里左边小于等于的时候将这个元素放入到辅助数组中，保持稳定性
    	else w[k ++] = q[j ++];
    //上述循环结束的时候必然是一部分走完了，然后另一部分剩下了
    //此时剩下部分直接接到辅助数组的尾部即可
    while(i <= mid) w[k ++] = q[i ++];
    while(j <= r) w[k ++] = q[j ++];
    
    //接着将临时数组的元素复制到原来的数组中，此时合并完成
    //注意我们临时数组合并的其实是q[l ~ r]部分，因此q的下标应该从l开始，然后将临时数组中的k个数据赋值回q的[l, r]部分
    for(int i = l, j = 0; j < k; j ++, i ++) q[i] = w[j];
    
}
```


### 归并排序的的时空复杂度与稳定性

这里选择中间的数进行划分，一共需要递归 logn 层，每层合并的时候都是 n 的复杂度，因此不管是最好，平均还是最坏的复杂度都是：
$$
O(nlogn)
$$

==稳定性==

归并排序的时候合并的是相邻两个区间部分

合并的时候采用的是二路归并，合并两个有序区间的通用算法，左指针元素<=右指针元素，此时将左指针元素放到辅助数组中，从而保持了相对顺序

因此**归并排序是稳定的**

## 数值转换

### 十进制小数转化位定点小数的方法

用 2 乘十进制小数，可以得到积，将积的整数部分取出，再用 2 乘余下的小数部分，又得到一个积，再将积的整数部分取出，如此进行，直到积中的小数部分为零，或者达到所要求的精度为止

比如 0.375 转化为二进制小数

乘 2，得到 0.75，得到整数 0

0.75 乘 2，得到 1.5，得到整数 1

0.5 乘 2，得到 1.0，得到整数 1

因此二进制小数就是 0.011

它跟整数转换为二进制不一样，整数的除 k 取余法是从下到上将结果余数排列，这里小数是从上到下将乘积进位排列
### 32 位机器，int 和 float 互相转化的理解

32 位机器中 int 是 32 位，能表示的范围就是 $-2^{31} \sim 2^{31} -1$，其中数值位是 31 位

32 位机器中 float 是 32 位，数符 1 位，阶码 8 位，尾数 23 位（实际表示 24 位）

从 int 转化成 float，float 的 24 位尾数不能全部表示 int 的 31 位的数值，所以会有精度的损失，但是由于 float 的阶码真值范围是-126 ~ 127，所以虽然尾数不能完全表示 int 损失精度，但是可以通过阶码达到与 int 一样的数量级，float 表示的数的范围是可以包围 int 的，所以不会溢出

反过来，从 float 转化成 int，由于 float 的范围在 int 之外，所以会有溢出可能；同时由于 float 是可以表示一个纯小数的，比如 0.11011....，而这个纯小数转化成 int 是直接下取整的，截断小数点后面的所有的数变成 0，所以就会有精度丢失

另外，无论是 float 还是 double，他们转 int 都是真值直接截断小数部分然后将整数部分变成 int 的
### 32 位机器，int 和 float 互相转换

int 转为 float，可能会有精度的丢失，但是不会溢出

float 转 int，是直接截断真值的小数部分，然后剩下的用 int 表示，可能溢出，也可能精度丢失

### double 与 float 的互相转化

float 转 double 是无精度损失，无范围溢出的转化

double 转 float 可能溢出，也可能精度丢失

### 移码的本质是什么？与真值的转换规则是什么？

移码的定义其实是：

**真值 A+ 偏置 = 另一个值 B，这个值 B 映射的范围就是就是移码的范围，然后用无符号数将值 B 表示出来就是原来的真值 A 对应的移码**
![image.png](https://typora-1310242472.cos.ap-nanjing.myqcloud.com/typora_img/20250526175802.png)

所以对于移码来说，移码本身的真值 B 一定是大于等于零的数，移码是这个值 B 的无符号二进制表示，也就是原来真值对应的移码表示

对于 8 位原码的真值范围是-127 ~ 127，偏置选择 127 映射的移码范围就是 0 ~ 254，将 0 ~ 254 用无符号二进制表示出来就是真值的移码

对于 8 位补码的真值范围是-128 ~ 127，偏置要选择 128，映射的范围就是 0 ~ 255，将 0 ~ 255 用无符号二进制表示出来就是对应的原真值的移码，此时移码的表示有规律可循，就是将补码的符号位取反，数值位不变就得到了移码

**移码与补码，原码都没有什么联系，移码始终是真值加上偏置后用无符号二进制表示的一串编码，移码是相对真值范围而言的，与真值是一一对应的**，没有要求移码必须与原码或者补码一一对应，移码就是一个无符号的二进制数，并且移码越大，原始真值就越大，并且由于移码是无符号二进制，可以直接通过不加符号的比较来判断真值大小，移码的作用就是将原始真值范围映射到正的范围，通过正数的比较来简化比较运算

### 软件实现 - 单标志法

单标志法使用了一个变量 turn 作为谦让的动作，即每个进程会在自己的代码中将 turn 设置为另一个进程来表示谦让，也就是说 turn = i 表示第 i 个进程可以访问临界资源了

在进程 P 0 中将 turn 设置为 1 表示将临界资源的访问权谦让给进程 P 1，同理，在进程 P 1 中将 turn 设置为 0 表示将临界资源的访问权谦让给进程 P 0

它的实现互斥机制的逻辑是，初始时刻 turn = 0 表示进程 P 0 可以访问临界资源，进程 P 0 进入 while 循环，while 循环是用来阻拦进程进入临界区的，这里可以直接跳出 while 循环 P 0 进入临界区

当 P 0 在临界区并发被强行停止然后调度 P 1 进程的时候，P 1 进程虽然可以占用 CPU 并且到了 while 循环执行自己的指令，发现 turn = 0 自己不能进入临界区，所以会一直执行 while 循环被循环拦住，直到自己的时间片用完，然后调度进程 P 0 继续执行临界区，然后将 turn 设置为 1，表示谦让给进程 P 1，此时进程 P 1 才可以进入临界区

这种方式的缺陷在于，当 turn = 0 的时候，P 0 迟迟不访问临界区，此时临界资源是空闲的，但是 turn 始终没有被 P 0 谦让给 P 1，那么 P 1 也无法访问临界区，所以不满足空闲让进的原则

### 软件实现 - 双标志先检查法

这种方式是对单标志法的改进，两个进程各自占用一个变量，每个变量表示了这个进程对于进入临界区的意愿，比如 `flag[0] = true` 就表示 P 0 进程想要进入临界区，while 循环仍然是作为阻拦的作用，while 循环会检查对方的意愿，如果对方有意愿进入临界区，则当前进程被阻拦：

![image.png](https://typora-1310242472.cos.ap-nanjing.myqcloud.com/typora_img/20250718172844.png)

这样就很好的解决了单标志法不满足空闲让进的原则，同时这个方法实现了互斥访问机制

但是，这种方法无法满足忙则等待的原则，也就是两个进程可能会同时进入临界区；这是因为 while () 这一行没有做到很好的阻拦作用

比如两个进程并发执行，此时两个进程都没有表达自己进入临界区的意愿，P 0 进程执行到 while，没有被阻拦，然后当 P 0 想要设置 flag[0] = true 的时候它突然被暂停，然后调度 P 1 进程执行，P 1 执行到 while 的时候也没有被阻拦，因为 P 0 还没有设置自己的意愿转去执行 P 1 了

然后 P 1 顺利进入临界区，然后又暂停 P 1 调度 P 0 执行，P 0 从 flag[0] = ture 开始执行，也可以顺利进入临界区

这样两个进程就同时可以进入临界区了，显然不满足临界区忙则等待的原则

**这种方式不能实现互斥机制**
### 软件实现 - 双标志后检查法

这种方式是对双标志先检查法的简单改进，它将表达进入临界区的意愿放在 while 阻拦的前面：

![image.png](https://typora-1310242472.cos.ap-nanjing.myqcloud.com/typora_img/20250718183930.png)

这样就不可能会出现两个进程同时进入临界区的现象了，满足了忙则等待的原则

但是，这种方式会导致两个进程都无法进入临界区的现象

比如 P 0 进程执行完第一行指令，表达了自己进入临界区的意愿，接着被暂停去执行 p 1，P 1 执行了第 5 行代码，也表达了自己进入临界区的意愿

但是往后，两者都会被 while 循环阻拦，两个都无法进入临界区，相当于两个卡 bug 被卡死了

这就不满足空闲让进和有限等待的原则了

**这种方式会让两个进制饥饿**
### 软件实现 - Peterson 算法

这种算法结合了单标志法和双标志后检查法，它用一个 turn 变量来表示进程的谦让，同时用一个变量表示进程的意愿，while 仍然表示阻拦的作用

两个进程在表达了自己的意愿的同时会做一次谦让，如果两者都表达了自己对临界区的意愿，那么遇到 while 被阻拦的时候，最后一次谦让的进程会丧失临界资源的有限访问权

然后进程调度 P 1 执行，（6）（7）它也会表达自己的意愿，同时谦让一次，执行（8）的时候双方都表达了自己的意愿，但是 P 1 是最后谦让的，所以丧失了进入临界区的权限，只能被阻拦卡死

###  基于索引的动态分区分配算法是什么？

#### 伙伴系统

##### 内存分配

伙伴系统规定，内存中无论是已分配的分区还是空闲分区一律是 2 次幂的大小

对于相同大小的分区还是连成一个单独的双向链表，这个就体现了基于索引的思想了，这个时候就可以建立索引表指向这些链表了

当一个进程所需的内存大小是 n 的时候，我们会看这个 n 是介于 $2^{i - 1} \sim 2^i$ 之间，此时给它分配 2^i 大小的空闲块，即在空闲分区大小为 2^i 的双向链表中查找，如果有，那就分给这个进程；如果没有，则向下查找空闲分区大小是 2^{i + 1 }大小的双向链表，找到了之后，将这个 2^{i + 1 }大小的空闲分区一分为二，分成**两个大小是 2^i 一样并且连续**的分区，称为一对伙伴，一个分配被这个进程被占用，另一个大小为 2^i，加入到 2^i 这个空闲分区链表中

当然，这个进程的大小 n 可能会小于 2^i，但他仍然会独占这个 2^i 的划分空间，所以伙伴算法会产生内部碎片

上面是伙伴算法的分配分区的思想



##### 内存回收


空闲分区的回收是相反的过程，当这个大小为 n 的进程所占的大小为 2^i 的分区被回收之后，这个 2^i 会与旁边的相同大小并且与他相邻的 2^i 的分区合并，形成一个 2^{i + 1}大小的空闲分区

如果这个 2^{i + 1}大小的空闲分区旁边还有一个相同大小的 2^{i + 1}大小的空闲分区，那么就会继续合并，一直到旁边没有了相同大小分区为止

#### 哈希算法

哈希算法会构造一个哈希表，这个表中的关键字是空闲分区的大小，关键字映射对应的哈希表相应位置处存放了该空闲分区链的头指针

当进行空闲分区分配的时候，所需的空闲分区大小会作为关键字使用哈希函数进行映射，映射到这个哈希表中的某个位置，获得空闲分区链表，从而分配

这里的哈希算法的含义是，当需要分配的时候会拿进程需用的分区大小作为关键字 key 进行哈希映射，映射的结果是这个分区大小连成的链的头指针

### 索引结点 inode 与索引结点编号是什么？

索引结点是外存中存放文件元数据的一块区域，我们一旦找到了索引结点，我们也就找到了这个文件的元数据，索引结点与文件是一一对应的。

FCB 也就是文件控制块，它其实也是目录文件中的一个目录项，inode 索引结点主要是将目录项中除了文件名之外的信息全部摘出来了，单独存放再外层中，保留了一个 inode 编号来找到 inode 结点

而 FCB 则是直接将 inode 中的文件元数据一股脑放在目录项中，与文件名形成一个大的目录项

可想而知，采用 FCB 的目录文件将会变得非常大

###  RIP 的工作特点是什么？和谁交换信息？交换什么信息？多久交换一次？

### traceroute 的原理是什么？

跟踪路由的基本原理是源主机首先发送一个 TTL = 1 的 ICMP 回送请求报文，这个报文到达第一个路由器 TTL 减一，此时这个路由器就会发送给源主机一个 ICMP 差错报告，类型是时间超时，这样源主机就知道了第一跳的路由器的 IP 地址

接着源主机再发送一个 TTL = 2 的 ICMP 回送请求报文，同理，得到了到达目的主机的第二个路由器的 IP 地址：
![image.png](https://typora-1310242472.cos.ap-nanjing.myqcloud.com/typora_img/20250228095840.png)

最后源主机发送一个 TTL = 3 的 ICMP 回送请求报文，这个时候目的主机 H 2 可以收到这个 ICMP 报文，所以会发送一个回送回答的 ICMP 数据报，这样 H 1 就会知道已经跟踪到了最后一个站点
![image.png](https://typora-1310242472.cos.ap-nanjing.myqcloud.com/typora_img/20250228100021.png)
### traceroute 命令中沿途路由器和目的主机发送的各是什么报文？

源主机发送的是 ICMP 回送请求报文，不过其中的 TTL 会递增

沿途路由器收到 ICMP 回送请求报文之后，由于 TTL 会减 1，所以不会转发，而是发送给源主机 ICMP 差错报告报文，通过此来发现沿途的路由器

源主机收到 ICMP 差错报告报文之后会不断递增TTL 重新发送 ICMP 回送请求报文，一直到目的主机收到这个报文，此时目的主机发送 ICMP 回送回答报文给源主机

其实这个题考察的是分区的概念，比如你这里的查 abc. xyz. com

![image.png](https://typora-1310242472.cos.ap-nanjing.myqcloud.com/typora_img/20250826184905.png)

本地域名服务器向根域名服务器发送 DNS 请求

根域名服务器告诉. com 顶级域名服务器的 IP 地址，于是本地域名服务器向顶级域名服务器发送 DNS 请求

顶级域名服务器接下来该项本地域名服务器返回一个权限域名服务器的 IP 地址了，本地域名服务器下一步需要向权限域名服务器发送 DNS 请求

一个权限域名服务器要对应一个区，这里区的划分有多种，一种划分方式是权限域名服务器将所有的 XXX. xyz. com 的 XXX 组合全部包含在了一个区中，这个权限域名服务器有所有 XXX. xyz. com 域名对应的 IP 地址，此时顶级域名服务器发送给本地域名服务器的权限域名服务器 IP 地址就是这样分区的权限域名服务器，然后本地域名服务器直接向这个权限域名服务器发送 DNS 查询，权限域名服务器就直接返回 abc. xyz. com 的 IP地址了

另一种分区方式是一个权限域名服务器包含了 XXX. xyz. com 中除了 abc. xyz. com 的可能，然后 abc. xyz. com 分在另一个区，即对应另一个权限域名服务器中

此时顶级域名返回的是 XXX. xyz. com 的权限域名服务器（这个包含的可能最多，是一个更大的权限域名服务器），然后这个权限域名服务器再返回给本地域名服务器 abc. xyz. com 对应的权限域名服务器，然后本地域名服务器再去向这个小点的分区的权限域名服务器发送 DNS 查询，然后这个小点的权限域名服务器就返回给本地域名服务器 abc. xyz. com 的 IP 地址了


那么对于 www.abc.xyz.com 的DNS查询过程就是：

本地域名服务器向根域名服务器发送 DNS 查询，根域名服务器返回顶级域名服务器 .com的 IP

本地域名服务器向顶级域名服务器发送 DNS 查询，顶级域名服务器返回大一点的 XXX. xyz. com 的权限域名服务器 IP

本地域名服务器向大一点的 XXX. xyz. com 权限域名服务器发送 DNS 查询，这个权限域名服务器返回 abc. xyz. com 权限域名服务器的 IP（小一点的分区）

本地域名服务器向 abc. xyz. com 权限域名服务器发送 DNS 查询，这个权限域名服务器进一步分区的话它对应的是 XXX. abc. xyz. com 的大一点的权限域名服务器，它返回的就是 www.abc.xyz.com 的服务器 IP 地址，这个 IP 地址就是用户想要访问的 IP 地址，返回给本地域名服务器的时候查询就结束了

所以一共最多就是本地域名服务器发出 4 次 DNS 查询

==也可以这样理解==

本地->根，根域名服务器知道所有`. XXX` 的顶级域名服务器，它告诉本地域名服务器去找`. com` 的顶级域名服务器

本地 ->` .com `顶级域名服务器，`. com` 顶级域名服务器知道所有 `XXX. com` 权限域名服务器地址，它告诉本地去找 `xyz. com` 权限域名服务器

本地-> `xyz. com` 权限域名服务器，这个权限域名服务器知道所有 `XXX. xyz. com` 权限域名服务器地址，它告诉本地与找 `abc. xyz. com` 权限域名服务器

本地-> abc. xyz. com 权限域名服务器，这个权限域名服务器知道所有` XXX. abc. xyz. com` 服务器地址，它告诉本地` www.abc.xyz.com` 服务器地址，这个地址即为用户所求

接着指令执行之后 R 5 的内容发生改变，+1，R 5 内容变成 5679 H
