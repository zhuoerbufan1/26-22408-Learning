虚拟地址 1234 5678 H 的页号是 048 H
它对应的物理地址 BAB 4 5678 H 对应的页框号是 2 EAH

这个页号，实际上就是页表中的下标，将页表看成一个数组，页号就是数组下标，所以这个页所对应的是第 048 H 个页表项

第 0 个页表项的虚拟地址是 B 8 C 0 0000 H
第 1 个页表项的虚拟地址是 B 8 C 0 0004 H
所以第 048 H 个页表向的虚拟地址是 B 8 C 0 0000 H + 048 H * 4 D 

这里将 048 H 转换成 2 进制，左移两位，然后再转成 16 进制，与 B 8 C 0 0000 H 相加即可，结果就是 **B 8 C 0 0120 H**，这个是页表项所在的虚拟地址，同理页表在内存中也是连续存放的，页表的起始物理地址是 6540 0000 H，还是按照数组的思想来处理，页号就是页表中数组下标，所以这个页表项所对应的物理地址就是 **6540 0120 H**

虚拟地址 1234 5678 H 的页号是 048 H，页号作为页表中数组的下标，数组内容就是这个页号所对应的内存中的页框号，因此页表项中页框值就是 2 EAH

### 关于为什么页表也会对应一个虚拟地址

这是因为进程有自己的一个虚拟地址空间，这个虚拟地址空间中有一个内核区，这个内核区对应了 OS 物理内存中的内核区，两者之间存在映射关系，内核区在主存中只有一份，它都会映射到进程的虚拟地址空间的内核区，这样在进程看来就好像自己独占了内核区一样

而页表每个进程对应一份，存放在 OS 的物理内存中的内核区，这个内核区在进程的虚拟地址空间中有映射，所以页表当然也会对应进程虚拟地址空间中的一个虚拟地址

只是这个虚拟地址可能进程无法直接使用，因为虚拟地址空间中的内核区对进程不可见

根据此，由于页表中每个页表项都会对应进程中的一个页，所以页表本身所在的页也一定会在页表中对应一个页表项（页表相当于一个数组，进程虚拟地址空间中的页号相当于数组下标，数组内容就是这个页在内存中的页框号）

### 如何根据页号计算这个页在页表中的页表项？

页表相当于一个数组，进程虚拟地址空间中的页号相当于数组下标，数组内容就是这个页在内存中的页框号
