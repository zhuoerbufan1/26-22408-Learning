
## IO 控制方式-中断
### 中断控制器的基本结构

中断控制器本身也是一个 IO 设备，CPU 可以访问其 IO 接口配置其功能，比如设置其中断屏蔽字寄存器 IMR，它也被称为可编程中断控制器，其基本结构如下所示：

![image.png](https://typora-1310242472.cos.ap-nanjing.myqcloud.com/typora_img/20250629184225.png)

下面依次说明这个中断控制器的各个结构

==IRR，中断请求寄存器==

它用于暂存每个外部设备的中断请求，IRR 的每一位对应一个外部设备，其值为 1 的时候表示外部设备发出了中断请求，IRR 中的内容又称为中断字，中断处理的时候就通过中断字来确定中断源，从而转到对应的中断处理程序

==IMR，中断屏蔽字寄存器==

IMR 的每一位对应一个设备中断源，中断源为 1 的时候表示屏蔽这个中断源发送的中断请求，为 0 的时候表示允许发送

对于不同的外部设备，他们由 CPU 设置不同的中断屏蔽字，**当执行他们的中断服务程序的时候会将中断屏蔽字写入到 IMR 中，此时所有其他设备发送的中断请求都会先与自己的中断屏蔽字的每一位进行一个与操作，没有被屏蔽的中断请求再送到中断响应电路中进行请求优先级排序**

中断屏蔽字可以动态的改变中断优先级；但是中断屏蔽字只有在 CPU 运行服务程序的时候才能设置，当 CPU 执行主程序的时候仍然采用的是中断响应的优先级

==优先级排队电路==

这个优先级排队电路的输入是多个通过了屏蔽的中断请求信号，输出是优先级最高的中断编号和中断请求信号

中断编号通过数据总线 DBUS 反馈给 CPU，而中断请求号 INTR 则通过控制总线 CBUS 传输给 CPU，同时通过控制总线接收来自 CPU 的中断应答信号 INTA

==ISR，中断服务寄存器（不深入了解）==

它用来存放多重中断中所有得到中断响应但是中断服务程序还没有结束的中断请求，每一位对应一个设备

一般来说，在多重中断中，低响应优先级的中断可以设置屏蔽字来屏蔽掉高响应优先级的中断，从而避免自己被打断嵌套；但是如果此时是一个高响应优先级的中断服务在执行，低优先级哪怕没有被屏蔽，它也不能去打断高优先级的中断服务；即普通的屏蔽模式下，只能是高响应优先级去打断嵌套低响应优先级中断

一个新的中断请求通过了屏蔽电路，它会在排队电路中不仅仅与别的通过了屏蔽的请求排队，还要与当前的 ISR 中的中断请求排队，从而决定这个中断请求是否被送给 CPU，只有一个通过了屏蔽，并且响应优先级最高，并且比当前 ISR 中的中断请求的优先级还高的中断请求才会被送给 CPU，才会打断当前的服务程序，进行中断嵌套

一般 408 中不考虑 ISR 中的排序，只要中断信号没有被屏蔽，那就可以通过响应优先级排序，打断当前的中断服务程序进行嵌套（408 认为只要开中断，有中断请求，就可以响应中断）

==中断使能位和标志位 IF/IE==

这个一般在 CPU 内部，会放在 PSW 寄存器中，它如果为 1 表示开中断，为 0 表示关中断

关中断表示此时 CPU 不会响应任何中断请求，CPU 可以通过开/关中断指令来设置它


### 中断向量，中断向量表，向量地址，中断指针 

（1）中断向量是中断服务程序的入口地址以及中断服务程序的初始程序状态字 PSW

（2）中断向量表是一堆中断服务程序的入口地址和 PSW 的数组

（3）向量地址是中断向量表的地址，也称为中断指针

### 完整的单级中断过程总结


**（1）中断请求与中断判优**

IO 设备设置中断控制器中的中断请求寄存器 IRR，通过了屏蔽字（此时 CPU 运行的是主程序，没有屏蔽情况）和中断判优电路之后，中断控制器将中断请求 INTR 和中断号分别通过 CBUS 和 DBUS 送给 CPU

 **（2）中断响应**

在中断响应中 CPU 主要执行三个操作，这三个操作是由硬件自动执行的，就好像有默认的指令一样，所以称为隐指令：

 **i 关中断**

设置 IF = 0 关中断，这一步是 CPU 为例避免在后面保存信息的时候被别的中断过来打断导致信息丢失中断除了完了无法返回

 **ii 保护程序断点**

将当前程序计数器 PC 和当前程序状态字 PSW 入栈保存，这是为了能够在中断执行完毕之后可以返回；如果是外部中断，保存的是当前执行程序指令的下一条地址；如果是内部异常，中断就是由当前指令引起的，所以保存的就是当前指令的地址，中断处理完毕之后要重新执行当前指令

 **iii 中断识别**

获得当前中断源的中断号，然后根据中断号去查找中断向量表，在中断向量表中得到当前中断源对应的中断服务程序地址，然后跳转到中断服务程序处理中断（这一步是判断产生中断的类型，由硬件完成）



**（3）保护现场**

这一步也可以称为中断服务的预处理，一般在中断服务程序的开头

由于中断服务程序可能会修改寄存器的值，所以这一步需要将源主体程序中可能被修改的寄存器的值压入到栈中保存


**（4）执行中断服务**

进行传数据等操作

**（5）恢复现场**

这一步与保护现场是逆操作，将保存的各个寄存器的值出栈恢复


**（6）开中断**

此时 CPU 设置 IF 为 1，允许 CPU 响应新的中断请求

**（7）中断返回**

保存的主程序的 PC 和状态字 PSW 出栈，返回到主程序继续执行了

## 多重中断
### 完整的多级中断过程总结

**（1）中断请求和中断判优**

当当前中断源通过了中断屏蔽字，并且优先级最高，此时中断控制器将其中断号和中断请求 INTR 发送给 CPU，如果 CPU 内部 IF  = 1 处于开中断，则接着 CPU 就会响应这个中断

**（2）中断响应**

与单级中断完全一样

**i 关中断**

**ii 保存断点**

**iii 中断识别**

**（3）保护现场**

由于是多级中断，此时中断服务程序还会写入自己的中断屏蔽字到中断屏蔽寄存器中，所以这里还需要保存上一个中断服务程序的中断屏蔽寄存器的值；在保护现场的时候同时保护通用寄存器和中断屏蔽寄存器的值

**（4）开中断**

当多重中断中某个中断请求被响应跳转到自己的中断服务程序，然后保护完了上一个中断源的中断服务程序的端点和现场之后就可以直接开中断了

此时意味着这个中断可以被另一个中断进行嵌套了

**（5）执行中断服务**

在执行中断服务中，当前中断服务程序可以被另外的中断请求嵌套

**（6）关中断**

当前终端执行完自己的中断服务之后要回到上一个中断服务程序，这里关中断是为了保证返回操作的完整性

**（7）恢复现场**

此时要连着上一个中断的中断屏蔽字一起恢复

**（8）CPU 发送 EOI**（408可以不用考虑这一步）

CPU 发送当前中断结束命令 EOI 给中断控制器，中断控制器清除 ISR 中当前中断的中断源，表示当前中断执行完毕，这里必须要清除 ISR 中的这个中断源，因为 ISR 中的中断源也会参与中断响应优先级电路的排序，当前执行完毕的中断源是最高优先级的中断源，它在 ISR 中不被清除后续优先级比它低的中断请求再次到来的时候将永远不会被 CPU 响应

**（9）开中断，中断返回**

### 一个关于多重中断的典型例题（中断源同时到达，不考虑 ISR 寄存器排序）

![image.png](https://typora-1310242472.cos.ap-nanjing.myqcloud.com/typora_img/20250921151950.png)

![image.png](https://typora-1310242472.cos.ap-nanjing.myqcloud.com/typora_img/20250629184225.png)
![image.png](https://typora-1310242472.cos.ap-nanjing.myqcloud.com/typora_img/20250629202635.png)
在主程序执行的过程中 ABCD 四个中断同时到达，此时 IMR 中没有任何屏蔽字，所以这 4 个中断按照优先级排队项响应优先级进行响应

很显然，A 在排队电路中的优先级最高，因此优先响应，A 响应的时候会进行关中断，保护主程序断点设置屏蔽字，然后开中断

![image.png](https://typora-1310242472.cos.ap-nanjing.myqcloud.com/typora_img/20250921151950.png)

A 开了中断之后设置了屏蔽字，此时 ABD 的中断源都无法进入排队电路，只有 C 可以进入，所以 A 会被 C 打断，CPU 会转而响应执行 C

C 进行响应，保存的是 A 的断点，C 设置自己的屏蔽字，此时四种中断全被屏蔽，所以 C 可以顺利执行完自己的所有处理程序，然后恢复现场，由于 C 是保护 A 的断点和现场，所以回到继续执行 A 的处理程序，并且 A 的屏蔽字也被恢复，BD 中断信号都被屏蔽，A 处理程序结束的时候，由于 A 之前保存的是主程序的断点和现场，所以 A 的处理程序结束之后回到的应该是主程序

主程序是没有屏蔽字的，并且此时 A 和 C 已经处理完毕，所以此时 BD 两种中断信号进入排队电路进行优先级排队，先响应 B，设置 B 的中断屏蔽字，B 的屏蔽字设置之后无法屏蔽 D 的中断信号，所以 B 开中断之后 D 的中断信号进入 CPU，CPU 转而响应 D，保存 B 的断点和现场，设置 D 的屏蔽字

D 的屏蔽字可以屏蔽 B 的中断信号，所以哪怕 D 开了中断，B 的中断信号也无法进入 CPU，所以 D 会一直执行完毕，然后恢复 B 的断点和现场，执行 B 的服务程序

B 的服务程序执行完毕，回到主程序


### 一个关于多重中断的例题（中断源先后到达，不考虑 ISR 寄存器）

![image.png](https://typora-1310242472.cos.ap-nanjing.myqcloud.com/typora_img/20250921154913.png)


一开始只有中断源 D，所以 CPU 会响应 D，设置 D 的屏蔽字，保存主程序的断点和现场，然后开中断

接着 A 来了，由于 D 不能屏蔽 A，所以 A 的中断信号会进入 CPU，CPU 会转而响应 A

CPU 保存 D 的断点和屏蔽字保存 D 的现场，然后设置 A 的屏蔽字以及继续执行 A 的服务程序

然后 B 中断到达，但是 A 的屏蔽字可以屏蔽 B，所以 B 的信号无法进入排队电路，也无法进入 CPU，所以不影响

然后 C 到达，A 无法屏蔽 C，所以 C 可以进入排队电路，CPU 转而响应 C

CPU 保存 A 的断点和现场以及屏蔽字，设置 C 的屏蔽字，然后开中断，此时 ABD 虽然都有中断信号，但是都被 C 的屏蔽字屏蔽，无法进入排队电路，因此无法进入 CPU，所以 C 会完整执行完毕，然后恢复 A 的断点，现场和屏蔽字，继续执行 A

A 的屏蔽字恢复之后继续屏蔽 B 和 D，所以 A 会执行完毕，A 当时保存的是 D 的断点和现场以及屏蔽字，所以 A 会恢复 D 的断点，现场和屏蔽字，转而执行 D

D 的屏蔽字恢复之后可以屏蔽 B，所以 D 的中断服务程序会执行完毕，然后恢复主程序的断点，现场，回到主程序

主程序没有屏蔽字，此时只有 B 的中断信号了，所以 CPU 会响应 B 的信号将 B 执行完毕

然后再回到主程序

### 中断响应加入的一些过程

 （1）CPU 变态，由用户态变为核心态

 （2）切换内核栈，主要是从用户空间切换到内核空间

## 进程切换全流程

### 一个完整的切换过程

对于一个处于运行状态的进程 A 和一个就绪状态的进程 B，这两个进程都是用户态进程

#### A 某一时刻时钟中断到达

#### A 在中断周期完成中断响应

包括：
（1）关中断
（2）保存断点
（3）切换内核栈
（4）中断向量寻址
（5）CPU 变态

**此时进入内核态**
#### 执行中断处理程序

##### 保存现场以及屏蔽字

保存到内核栈中

##### 调用进程切换的函数（调用调度程序）

这个函数完成的工作是：

（1）保存当前进程 A 的现场到 PCB 中
（2）根据 PCB-B 恢复进程 B 的现场到 CPU 中，此时切换到了 B 执行

#### 继续执行 B 发生阻塞的时候所执行的内核函数代码

比如 B 执行的 IO 操作阻塞，此时继续执行 B 发生阻塞的时候的 IO 程序，完成一些收尾工作

#### 切换回 B 的用户态，B 继续执行

**这个过程切换回用户态**

### 在切换回 A 的时候如何恢复 A 的用户态现场？

（1）在 A 进行中断的过程中保存 A 的断点以及现场是保存到 A 所对应的内核栈中
（2）在切换的时候会将内核栈中的这些数据保存到 A 的 PCB 中
（3）在恢复的时候直接根据 PCB 内容恢复内核栈，然后在 A 中断返回的时候进而恢复 A 的用户现场

## 键盘调用全流程

### （1）用户程序调用库函数 scanf ()

### （2）scanf () 调用 sys_read () 系统调用

下面就是系统调用的全流程

#### （1）寄存器传参

这里传参的时候是 C 语言内嵌汇编，利用寄存器传参，传递的参数主要包括

（1）系统调用号
（2）输入长度
（3）具体外设

寄存器传参的一些代码指令在 scanf () 函数中实现，scanf 函数具体实现中先进行寄存器传参，然后执行软中断指令
#### （2）通过 INT 80 陷入内中断

在这个过程中是硬件完成的，在转到中断处理程序之前，会执行
（1）关中断
（2）保存断点，PC/PSW 寄存器
（3）切换 CPU 特却级，完成变态
（4）中断向量寻址
（5）切换内核栈

其实就是响应中断的过程

#### （3）执行中断处理程序

这里通过 INT 80 陷入软中断中断类型号（中断向量号）是固定的 80，在中断处理程序中再利用上文传递的系统调用号，转到具体的系统调用程序执行

#### （4）执行 sys_read () 系统调用

这个程序负责具体的数据传递，操作包括

##### （1）执行驱动程序初始化 IO 接口，并发送命令

##### （2）如果用户没有输入，此时阻塞，进行进程切换

下面是进程切换的全流程，假设发起系统调用的是进程 P 1

（1）此时系统处于内核态，调用调度程序，保存 P 1 的内核线程等到 PCB 中，P 1 阻塞，此时是主动阻塞
（2）切换一个就绪的 P 2 进程，将 P 2 的 PCB 中的信息放到 CPU 上
（3）开始执行进程 P 2（刚开始的时候 CPU 仍然处于内核态，执行 P 2 的时候可能是用户态，也可能是内核态，具体看 P 2 是什么样的进程）

##### （3）在执行 P 2 的情况下，如果用户敲击了键盘

（1）IO 控制器将 IO（键盘） 中的数据放到 IO 接口中的 IO 端口中（IO 接口中的数据寄存器）
（2）IO 控制器向 CPU 发送中断请求，这里是外中断
（3）CPU 进行中断响应并调用中断处理程序，中断处理程序调用驱动程序
（4）驱动程序会完成 IO 端口中的数据移入**内核区**的操作，此时不可能直接将数据直接交付到进程 P 1 的现场中，因为此时还是 P 2 的背景下，所以只能先移入到所有进程共享的内核区
（5）将进程 P 1 **由阻塞态变成就绪态**
（6）经过一段时间，调度进程 P 1，此时 P 1 仍然处于系统调用中，这个时候完成一些后续处理，OS 移交数据，P 1 的系统调用返回

P 执行系统调用之后
首先是 2，自己被阻塞，调度别的进程执行
然后是 6，用户输入了一个字符，此时由 IO 控制器放到了 IO 端口中，并发起外中断
然后是 4，启动中断处理程序，中断处理程序调度键盘驱动程序
然后是 3，键盘驱动程序完成从 IO 端口中取数据到内核区的操作
然后是 1，进程 P 所等待的外设数据就绪，所以 P 切换为就绪态
最后是 5，等待一段时间 P 被调度执行的时候，继续 P 的系统调用过程，移交数据，然后系统调用返回，P 继续回到用户态执行

这里的题中操作顺序是：
2 6 4 3 1 5

显然 P 就绪之后才能调度 P 执行，所以是 1 操作
