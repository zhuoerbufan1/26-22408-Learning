## 原码一位乘的硬件原理（其实计算机里面只有无符号乘）

### 硬件结构

原码进行操作时只是数值位参与运算，符号位进行异或操作

此时数值位就是绝对值参与运算了，所以可以直接用无符号的硬件来实现原码的数值位运算

最后的结果再加上符号位异或的结果即可

在进行无符号乘法的时候，计算机硬件主要包含下面几个结构：

![image.png](https://typora-1310242472.cos.ap-nanjing.myqcloud.com/typora_img/20250528153736.png)


MQ 是乘商寄存器，用于存放乘数以及乘积结果的低位

ACC 是累加寄存器，用于存放中间结果，以及乘积结果的高位，中间结果会作为一个操作数送入 ALU

x 是 ALU 的另一个操作数，存放的是被乘数

Cout 是加法器执行加法之后的进位信号

ALU 算数逻辑单元，这里用于加法

控制逻辑计数器 Cn 用于控制加法，右移的次数以及右移操作，Cn 的大小取决于乘数 y 的数值位位数


课本的硬件电路如下，这里其实就是倒了过来 P 就是 ACC

这里是无符号数，不用存放符号位，乘商寄存器和 ACC 都是 4 位

y 是乘数，x 是被乘数

### 初始化：

初始化时乘数 y 数值位放入乘商寄存器中，x 放入 ALU 的操作数中，根据 y 的位数，Cn 初始化为 4；存放 ALU 运算中间结果的 ACC 和 Cout 初始化为 0：

然后是右移操作，这里是连着进位 Cnout 和 ACC 和 MQ 一起逻辑右移，高位补零，MQ 的最右侧一位移出丢弃

### 继续执行后续 3 次

注意只有 MQ 的最低位为 1 的时候才会执行加一次操作，然后右移一位，MQ 最低位为 0 的时候控制逻辑只会控制右移一位，经过四次操作之后，Cn = 0 表示操作结束，此时 ACC 就是乘积结果的高四位，MQ 就是乘积结果的低四位

最后结果就是 `0.1001111` 了，这里是无符号小数的乘法运算过程，这个过程只针对数值位进行了操作，所以无符号整数的操作也是这样的，不管是小数还是整数，他们的数值部分都是进行这样的操作，至于最后的小数点点在哪里则根据这个数的性质截决定

### 溢出判断

**手算判断**

对于 n 位的无符号数乘 n 位的无符号数，如果最后结果用 2 n 位保存，一定不会溢出（1111 乘 1111 结果是 225，但是 8 位保存结果的话最大可以保存 255）

如果最后结果用 n 位保存，则直接进行十进制验算即可，比如 1111 乘 1111 结果是 225，显然范围超出了 4 位二进制无符号数的范围（0 ~ 15）

**机器判断**

像这样 n 位乘 n 位，最后结果用 2 n 位保存，那肯定不会溢出

但是如果这里用 2 n 位保存中间结果，最后截取后面 n 位作为结果的话，如果前面前 n 位不全为 0，那就是有溢出（很显然，因为是无符号数，不存在符号位，n 位结果超了那数值就是超了）

首先所有的与门进行运算生成这些全加器的输入，需要一个时间延迟T

然后对于每一行的全加器来说下一行需要上一行的进位依赖，所以下一行必须等到上一行计算完毕自己才能执行，并且每一行的全加器之间是并行执行的

每个全加器的执行延迟是6T，因此中间三行的全加器的执行时间就是18T

然后是最后一行的全加器，他们是3位串型全加器，对于m位串型全加器来说他们的延迟是2m + 4 T，所以最后一行的延迟就是10T

## 补码一位乘的硬件原理


在补码运算中符号位也是要参与运算的，并且都是双符号位参与运算，所以 ACC，操作数 x 都应该比原本的位数多两位，数值位默认为两位后面的位，下图黑点所示：
![image.png](https://typora-1310242472.cos.ap-nanjing.myqcloud.com/typora_img/20250528164015.png)

上图各个运算部件的功能如下：

控制逻辑（控制器）：用于控制进行移位和控制 ALU 进行加法操作

MQ：乘商寄存器，存放带一位符号的乘数，最后一位是辅助位，以及最后运算结果的低位部分

ACC：用于存放中间结果，并且作为 ALU 的另一个操作数参与下一轮的运算，同时保存最后结果的高位

译码器：根据 MQ 的最低两位结果来输出 001，010，100 三种信号，来控制选择器选择一轮操作中的一个操作数

选择器：由于要根据乘数的最低两位的差值每一轮需要进行不同的运算，所以选择器会根据移码器的结果进行三种情况的选择

反相器：x 中存放的是 $[x]_{补}$，当 MQ 的最后两位的差值是-1 的时候应该用 ACC 中的中间结果加上 $[-x]_{补}$，根据 $[x]_{补}$ 求 $[-x]_{补}$ 的快速求法就是每一位按位取反再加一，这里的反相器就是按位取反的意思，然后与译码器控制的+1 信号一起，保证 ACC 加的是 $[-x]_{补}$

这里以下图的运算来分析整个硬件执行过程，红色是初始化的辅助位：

### ==溢出判断==

**手算判断**

如果是 n 位乘 n 位，用 2 n 位保存就不会发生溢出

如果是 n 位乘 n 位，用 2 n 位保存中间结果，截取后 n 位作为最后的结果，由于是补码运算，我们直接手算两个补码的真值相乘的结果真值，看这个真值是否可以用 n 位的补码表示，n 位补码的范围是 $[-2^{n - 1}, 2^{n - 1} - 1]$，如果乘积真值超过了这个范围，则会溢出

**机器判断**

如果是 n 位乘 n 位，用 2 n 位保存就不会发生溢出

如果是 n 位乘 n 位，用 2 n 位保存中间结果，截取后 n 位作为最后的结果，那么只有当前 n + 1 位全是 1 或者 0 的时候才没有发生溢出

这是因为取后n bit作为补码乘法的结果的时候，这n位的范围是 $[-2^{n-1}, 2^{n-1} -1]$

因此对于从前往后的第n + 1位，它是截断的后n位的符号位，如果前n + 1位不是全0或者全1，那就超过了这n位的范围是 $[-2^{n-1}, 2^{n-1} -1]$，所以溢出
