
## 理解

### 进程与线程

OS 中的进程，即正在进行的程序，他可以看作是代码动态执行的整个过程，包含了静态的代码和各种资源的变化，**它是 OS 分配资源的基本单位**，是一个具有实际功能的程序在一个数据集合上的一次动态执行过程，**同时也是 OS 资源分配的调度的独立单位**

进程中的线程，线程是进程中的一个子执行任务，负责进程中的实际程序执行，一个进程至少含有一个线程，当然一般进程含有多个线程，可以简单认为线程是进程程序中部分功能代码模块的执行动态过程，**线程也可以简略的认为是轻量级进程，线程是 OS 调度的基本单位**

进程和线程的区别如下：

![image.png](https://typora-1310242472.cos.ap-nanjing.myqcloud.com/typora_img/20250709083215.png)

线程自己独有的资源如下：

（1）程序计数器，表示线程自己正在执行的代码地址

（2）寄存器集合，包含线程当前自己的工作状态

（3）栈，每个线程自己独享的，用于存放局部变量，以及函数调用的上下文信息

上述这些就是线程自己的上下文

### 用户级线程以及切换过程

用户级线程其实就是用户自己的程序管理的线程，它的创建，调度和切换都是用户程序进行的，不存在 OS 干预的过程（分配 TCB 可能需要系统调用，但是 TCB 的修改都是用户态下的程序指令完成的）

==用户线程的创建==

用户可以直接在自己的进程代码中调用线程库函数创建两个线程：
![image.png](https://typora-1310242472.cos.ap-nanjing.myqcloud.com/typora_img/20250709102837.png)

上图的 `pthread_create()` 函数就创建了一个线程，并将功能模块 GetData 或者 Show 与这个功能模块关联起来，这样这个进程就包含了两个线程，这两个线程分别负责 GetData 和 Show 这两个模块的执行

线程的创建主要就负责三个部分，一个是线程自己的栈的创建，一个是线程自己的 TCB 的创建，一个是初始化 TCB，与线程的栈联系起来，这个就是 `pthread_create()` 函数负责的功能

假设一个进程有两个线程：

![image.png300*300](https://typora-1310242472.cos.ap-nanjing.myqcloud.com/typora_img/20250709103406.png)

这两个线程可以看成两者执行序列的执行过程

在 `pthread_create()` 函数中的具体实现如下：

```cpp
void ThreadCreate(A) {
    TCB *tcb = ma11oc();       // 分配TCB内存
    *stack = ma11oc();         // 分配线程栈内存
    *stack = A;                // 将函数地址存入栈顶，这里是A的地址，100
    tcb.esp = stack;           // 设置TCB的栈指针
}
```

这里就是向 OS 申请了两块内存，分别当作线程的 TCB 和栈，然后程序将线程对应模块函数的地址放到栈中，同时让此时的 stack 的栈顶地址放到 TCB 的 ESP（相当于栈顶指针），这样就完成了一个线程的创建，这里 TCB 和用户栈都是用户态程序可以直接修改的，这里的 TCB 和用户栈其实都有点像用户程序自己创建的数组了，完全是用户态下直接控制的

![image.png](https://typora-1310242472.cos.ap-nanjing.myqcloud.com/typora_img/20250709104018.png)

==用户级线程的切换==

用户级线程的切换是通过用户态使用 yield () 函数进行的，他的切换过程很像过程调用的时候的切换，也是压栈弹栈的过程，只是线程都有自己的用户栈，所以切换的时候要完成自己栈的切换

一个具体的例子如下：

![image.png](https://typora-1310242472.cos.ap-nanjing.myqcloud.com/typora_img/20250709110036.png)


A, B 分别是一个线程负责的功能模块；C，D 是另一个线程负责的功能模块，在这个例子中，函数 A 调用函数 B，然后在函数 B 中切换到另一个线程，这个线程执行函数 C，然后调用函数 D，然后 D 中执行 Yield () 函数再切换回第一个线程，然后 B 返回，继续执行 A

它的过程是这样的，这里为了简化，不考虑函数调用过程中用户栈上的栈帧的切换，就先存放返回地址（其实栈帧也是压入栈存放）

创建了左右两个线程之后他们的用户栈中都会存放一个自己模块的地址，左侧存放 100 右侧存放 300，放到栈的底部

然后执行线程 A，从 A 函数开始执行，调用函数 B，此时 B () 的下一条指令地址 104 压入用户栈保存

然后执行 B 函数，调用 Yield () 进行线程切换，此时 Yield () 下面一条指令地址 204 压入左侧线程的用户栈保存，然后执行 Yield（）函数，这里的 Yield () 函数的具体实现如下：

```cpp
void Yield(){
	TCB1.esp = esp;//保存第一个线程的栈顶指针到自己的TCB中
	esp = TCB2.esp;//将第二个栈的栈顶指针赋给esp寄存器，完成了栈的切换
	
}//Yield()函数返回会执行ret指令，自动弹栈，这里esp指向了第二个用户栈，弹栈是将C的函数地址弹出了，让其赋给IP从而此时指向了C函数，开始执行C函数，完成了线程的切换
```

切换了线程的用户栈以及线程负责的模块代码，此时线程 2 接过 CPU 的控制权，开始执行自己的指令

线程 2 执行函数 C，调用函数 D，将 304 压栈，然后执行 D 函数，D 函数中执行 Yield () 函数将 404 压栈，在这个 Yield 中执行与线程 1 类似的操作，切换用户栈（这里分辨两个线程的 TCB 可能需要在 Yield 函数中加入一些参数，这里细节不多说了），然后 Yield () 执行完毕之后从线程 1 的用户栈中弹出 204，即 B 函数中 Yield () 的后面一条指令，所以完成了线程 2 切换到线程 1 的工作，继续执行线程 1 后面的指令了

以上就是用户级线程互相切换的过程了

==用户级线程切换的优缺点==

**优点：**

（1）从上面的过程可以看到，用户级线程的控制几乎不怎么麻烦 OS 内核，那么用户级线程切换就可以做到非常的快，线程操作的效率更高，只用简单切换一下用户栈和 PC 指令指向即可

（2）每个线程都有自己的用户栈和 TCB 块，这些都是由用户程序自己维护的（线程库函数）

（3）并且用户线程完全可以根据自己的需求自定义自己的线程调度策略，因为线程调度也是用户线程自己决定并操作的，不会麻烦内核，这样就非常灵活

**缺点：**

根据上述过程分析，用户级线程的切换，创建其实都是一个进程的程序的执行过程，那么当一个用户级线程需要 IO 而进行阻塞的时候，它陷入了内核，它就无法执行后续的 Yield () 函数了，那么别的不需要 IO 操作的线程也就无法执行，这就相当于整个进程全部阻塞了

同时，这些线程执行过程本质就是进程的执行一部分，他们的 TCB 和用户栈都是用户进程自己管理的，OS 无法明确感知他们，OS 只会将这个进程看作一个整体，发生陷入的时候 OS 不能分辨是哪个线程，那么 OS 也就不能调度他们到不同的 CPU 内核上去执行了，所以用户级线程无法利用处理器的并行能力

以上是两个最大的缺点，当然因为是用户程序管理线程，也会出现程序复杂度过高的现象

### 内核级线程以及切换过程

线程就是进程的部分功能模块执行的动态整体，所以内核级线程跟用户级线程一样，也是一个进程的一个局部的动态过程，包含自己模块的代码的执行还有自己的栈和 TCB 等

内核级线程与用户级线程的区别在于内核级线程的 TCB 是由内核程序控制的，并且线程的创建，终止和创建都是由内核处理的

这样做的好处在于，内核可以通过线程的 TCB 块来感知线程的存在，这样内核就可以对线程进行调度，那么当一个进程的某个线程阻塞的时候内核就可以调度这个进程其他的线程继续执行，不至于整个进程阻塞；那为什么用户级线程不能在某个线程阻塞的时候调度别的线程运行呢？这是因为根据上文，用户级线程调度切换还是依赖用户进程程序，那么你现在用户程序整个都暂停了，当然就不能调度了；而内核级线程的调度是依赖内核程序，某个线程等待 IO 的时候阻塞，这个时候触发中断，由内核中断处理程序来调度内核中这个进程的别的 TCB 块，即别的线程继续执行，进程的线程程序被阻塞，但是内核程序没有，所以可以由内核完成调度

为了实现这个功能，内核级线程就需要有两个栈，一个用户栈在用户空间由用户程序控制，一个内核栈在内核空间由内核程序控制，并且线程的 TCB 也是在内核空间由内核程序进行管理

==内核栈与用户栈的关联==

当一个线程想要访问 IO 的时候，它就会通过陷入指令进入内核态，将一些断点保存在内核栈中，这个过程就是内核栈与用户栈对应的过程，举一个例子如下所示：

![image.png](https://typora-1310242472.cos.ap-nanjing.myqcloud.com/typora_img/20250709154727.png)


这个线程在用户态执行的时候执行函数 A，调用函数 B，将返回地址 104 压入用户栈，然后执行函数 B，在 B 中进行系统调用，将 204 压入用户栈保存

系统调用接口函数中其实还有一些传参的过程，这里省去了，直接用软中断 INT 触发自陷进入内核态，进入内核态就是由中断触发的

此时硬件会进行中断响应，保存程序的断点，比如用户栈的栈底和栈顶指针，PSW 标志寄存器，触发中断的指令的返回地址 304，还有线程的起始地址 cs 都保存在一个对应的内核栈中

然后转入中断处理程序 system_call: 执行，这个中断处理程序再调用一个具体的过程 sys_read () 函数来处理线程想要调用外设的操作，所以还得保存一下中断处理程序调用 sys_read 的返回地址 1000 到内核栈中（这里先不考虑保护现场，简单起见）

然后接着就是 sys_read () 来调用外设进行处理了，这就是一个内核级线程的用户栈和内核栈的关联过程

==内核级线程的切换==

当调用 sys_read () 的时候就是启动磁盘，然后当前线程阻塞，然后调度别的线程进行：
![image.png](https://typora-1310242472.cos.ap-nanjing.myqcloud.com/typora_img/20250709160646.png)

上述的 switch_to 就是切换调度的函数，这里的参数 cur 和 next 就是当前线程的 TCB 和目标线程的 TCB

这里的具体过程就是根据 next 的 TCB 找到要切换的线程的内核栈的栈顶指针，然后保存当前的栈顶指针 esp 到 cur 的 TCB 中，然后让当前的 esp 指向 next 线程对应的内核栈的栈顶

然后再根据这个栈顶返回到 B 的用户态的线程代码中继续执行

我们以一个连续的两个线程切换来详细说明这个切换过程（大概有 5 段）

（1）首先是 B 线程触发中断陷入内核：

![image.png300*300](https://typora-1310242472.cos.ap-nanjing.myqcloud.com/typora_img/20250709163727.png)

在之前的中断响应中，就已经将 B 的断点保存到了 B 对应的内核栈中将内核栈与 B 的用户栈关联起来了，细节不说了

这里进入中断入口之后先保存 B 的现场到内核栈中，然后调用中断处理程序，此时会将 call 下面的指令地址保存到内核栈中，这里细节不表

（2）B 的具体中断处理过程，引发 B 的阻塞，并进行线程调度：

![image.png](https://typora-1310242472.cos.ap-nanjing.myqcloud.com/typora_img/20250709164138.png)
```Assembly
; 线程 B 的代码启动磁盘或者其他IO，线程B阻塞
...
call schedule   ; 地址 0x5000
; 下一条指令地址: 0x5004
```

这里是具体的中断处理程序，启动响应 IO 之后 B 阻塞，然后进行线程调度，转到执行 schedule 函数，当然也会将下一条指令的地址 0 x 5004 压栈保存

（3）进行进程调度找到下一个需要执行的线程，这里假设找到了 A 进行执行

```Assembly
schedule:
    mov eax, [next_thread]  ; 0x6000
    call switch_to          ; 0x6004
    ; 返回点地址: 0x6008
    ret                     ; 0x600C
```

这里找到了线程 A 之后，调用 switch_to 函数，然后继续将下一条指令 0 x 6008 压入到内核栈保存

此时 B 的内核栈的栈顶是指向 0 x 6008 的：

```Assembly
(栈顶) 0x6008  <-- ESP 指向这里
...其他寄存器...
```

（4）执行 switch_to 函数，切换内核栈：

```Assembly
switch_to:
    ; 保存当前线程(B)的栈指针
    mov [B_TCB.esp], esp  ; 0x7000
    
    ; 切换到线程A的栈
    mov esp, [A_TCB.esp]  ; 0x7004
    
    ret                   ; 0x7008
```

注意，这里虽然是 B 线程的处理程序，但是你已经将内核栈的 esp 指针指向了 A 的内核栈了，因此这里的 ret 弹栈弹出的应该是 A 对应的内核栈的内容，为了具体说明这个过程，我们假设切换完了 A 之后 A 又进行了阻塞，此时调度 B，看看 switch_to 函数到底是怎么切换回线程的用户态程序的

上述都是 B 切换的历史过程，当线程 A 想要进行切换的时候也是执行上面相同的步骤

（5）当 A 执行到 switch_to 函数的时候：

```Assembly
switch_to:
    ; 保存线程A的栈指针
    mov [A_TCB.esp], esp  ; 保存当前ESP (指向0x9008)
    
    ; 切换到线程B的栈
    mov esp, [B_TCB.esp]  ; 加载B之前保存的ESP (指向0x6008)
    
    ret  ; 关键切换点！
```

此时 esp 指向了 B 的内核栈，然后执行 ret 实际弹出的是 B 的内核栈的栈顶元素：
![image.png](https://typora-1310242472.cos.ap-nanjing.myqcloud.com/typora_img/20250709165743.png)

（6）线程 B 的内核程序层层返回：

A 的 switch_to 函数执行了 ret 之后先返回到 B 的 schedule 函数，然后 B 的 schedule 继续返回，返回到调用 B 的具体中断处理程序（启动 IO让 B 阻塞的那个程序）：

![image.png](https://typora-1310242472.cos.ap-nanjing.myqcloud.com/typora_img/20250709164138.png)

这个中断处理继续 ret 返回，返回到保存线程 B 用户态程序线程的地方即中断入口：

![image.png300*300](https://typora-1310242472.cos.ap-nanjing.myqcloud.com/typora_img/20250709163727.png)

然后在这里，恢复现场，执行 iret 指令，弹出线程 B 在用户态中的断点，然后继续执行 B 在用户态中的程序，完成了线程的切换

这里在内核中切换的过程与用户级线程的切换比较类似，关键在于，当更改了 ESP 指针之后，就已经完成了栈的切换，那么接下来弹出的东西就是另外一个线程之前保存在自己的栈的东西了

上述就是内核级线程 B 触发中断，切换到 A，然后再切换回自己继续执行的全部过程了

### 对多线程模型的理解


![image.png](https://typora-1310242472.cos.ap-nanjing.myqcloud.com/typora_img/20250709171707.png)


**多对一模型：**

其实就是通常是用户进程程序的线程库来完成线程的创建调度，当这个线程需要进行 IO 的时候就被阻塞，分配一个内核栈给它，这个过程可以理解是用户级线程与内核级线程的对应起来过程

但是这种模型你只有一个内核栈，只能对应一个线程，线程的切换还是上层用户进程实际的 Yield () 函数处理的，当这个线程阻塞的时候虽然对应了内核线程，具有了内核线程的结构特点，内核感知到了这个线程，但是内核无法切换到别的线程，因为没有别的线程栈，内核只能感知一个线程，那就不能切换了，线程阻塞之后还是无法执行 Yield() 函数了，无法进行线程切换，本质上还是整个进程代码都停掉了

**一对一模型：**

这个模型其实就是通常意义上的内核级线程了，不多说，它的切换需要反复从用户态进入内核态再进入用户态，时间花了很多，而且每个线程都需要内核栈和内核中的 TCB，这也会占用更多的资源

**多对多模型：**

这种模型不必深究，可以理解为线程通常在用户态执行的好好的，当需要 IO 的时候需要内核，然后内核给他分配一个内核栈，让其对应起来，当然它执行完了之后这个内核栈也可以用给其他的线程，这里不用深究具体实现细节；很可能是用户程序和内核各有 TCB 块，当阻塞切换的时候就分配一个内核栈对应起来切换到别的线程；别的切换的时候就直接用户程序切换（瞎猜的）

这里其实只用知道用户级线程和内核级线程的含义和区别就行了

### 进程的创建

==进程的创建==

除了第一个进程，操作系统中的进程均是由另一个进程创建的，创建进程的进程和被创建的进程互为父进程和子进程。父进程是在自己的内核空间创建子进程的。

在操作系统中，**终端用户登录系统、作业调度、系统提供服务、用户程序的应用请求等都会引起进程的创建**。操作系统创建一个新进程的过程如下：

1. **为新进程分配唯一进程标识号（pid）**，并申请空白PCB（进程控制块）。若PCB申请失败，则创建失败。
2. **为进程分配运行所需资源**（如内存、文件、I/O设备、CPU时间等）。资源可能来自操作系统或父进程。若资源不足（如内存），进程进入“创建态”，阻塞父进程等待资源。
3. **初始化PCB**：
    - 初始化标志信息（如进程状态）。
    - 初始化处理机状态信息（如寄存器值）。
    - 初始化处理机控制信息（如调度参数）。
    - 设置进程优先级。
4. **将新进程加入就绪队列**，等待被调度运行。

这些创建过程是由一段原语执行的，称为创建原语，其特点就是执行的过程中不允许中断

### 虚拟地址空间

虚拟地址空间是 OS 为每个进程分配的虚拟内存视图，他是进程看到的内存世界，每个进程都认为自己独占整个内存，但是实际上 OS 通过 MMU 将虚拟地址空间与实际物理地址映射对应起来

虚拟地址空间包括：

```
+---------------------+
| 栈（向下增长）        | ← 局部变量、函数参数
+---------------------+
|         ↓           |
|        空           |
|        间           |
+---------------------+
|         ↑           |
| 堆（向上增长）        | ← 动态分配的内存（malloc）
+---------------------+
| 未初始化数据（BSS）   | ← 初始值为0的全局变量
+---------------------+
| 已初始化数据（DATA）  | ← 初始值非0的全局变量
+---------------------+
| 代码段（TEXT）       | ← 程序指令（只读）
+---------------------+
| 内核空间             | ← 操作系统内核（所有进程共享）
+---------------------+
```


### 子进程与父进程 + fork () 函数与 exec () 函数（暂定，等看完 HIT 的 OS 课再进行详细总结）

==fork() 函数==

子进程是由父进程创建的进程，父进程通过调用 `fork()` 函数来创建一个子进程，子进程和父进程是两个不同的进程，他们的 PID 和 PCB 都是不同的，也不会共享虚拟地址空间

当父进程调用 `fork()` 函数之后，子进程会得到一个父进程的虚拟地址空间的副本，即子进程会独立的有一个虚拟地址空间，但是这个地址空间的映射关系与父进程完全一样：

![image.png](https://typora-1310242472.cos.ap-nanjing.myqcloud.com/typora_img/20250710200101.png)
子进程和父进程此时拥有的代码段，数据段，堆，栈等完全相同

而当子进程试图修改某个页的数据的时候，就会触发这个页的复制，生成这个页的副本，这样父子进程就不会共享同一个物理页了：

![image.png](https://typora-1310242472.cos.ap-nanjing.myqcloud.com/typora_img/20250710200303.png)

这个称为写时复制技术，举一个例子如下：

```cpp
#include <unistd.h>
#include <stdio.h>

int global = 10; // 全局变量（数据段）

int main() {
    int local = 20; // 局部变量（栈）
    printf("[main start] PID=%d\n", getpid());
    
    pid_t pid = fork();
    
    if (pid == 0) {
        printf("[child] global=%d local=%d\n", global, local);
        global = 100;
        local = 200;
        printf("[child modified] global=%d local=%d\n", global, local);
    } else {
        sleep(1); // 确保子进程先执行
        printf("[parent] global=%d local=%d\n", global, local);
    }
    
    return 0;
}
```

这里父进程调用了 `fork()` 函数之后就创建了一个子进程，这时子进程独立拥有一个虚拟地址空间，这个地址空间与父进程的地址空间映射到完全相同的代码段，数据段，堆，栈；

并且此时子进程和父进程同时从 fork () 之后的代码段开始执行，此时就是两个进程并发执行了，两者的执行顺序未知；不过代码段都是可读的，一般不会触发写时复制

当子进程修改变量的时候，就会触发写时复制，变量会实际复制到实际的物理空间中，然后子进程的虚拟地址空间的映射会发生改变，这样此时父进程和子进程其实对应的是物理空间中实际的两个不同的变量 

运行结果如下所示：

```cpp
[main start] PID=1234      // 父进程执行
[child] global=10 local=20 // 子进程初始值
[child modified] global=100 local=200
[parent] global=10 local=20 // 父进程值未变
```

==exec() 函数==

这个函数一般用于子进程换掉原有的父进程程序，让子进程对应一个全新的程序执行，这个函数的功能就是换掉当前进程执行的程序

具体来说，他会先摧毁原进程的虚拟地址空间的映射关系，然后将新的程序二进制装入内存，然后建立新的虚拟地址空间映射关系，此时进程就会对应全新的代码段，数据段，堆和栈

然后设置 PC 从新程序的入口开始执行
