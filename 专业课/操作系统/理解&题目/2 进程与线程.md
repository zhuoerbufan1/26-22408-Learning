### 进程的虚拟地址空间是什么？

虚拟地址空间是 OS 为每个进程分配的虚拟内存视图，他是进程看到的内存世界，每个进程都认为自己独占整个内存，但是实际上 OS 通过 MMU 将虚拟地址空间与实际物理地址映射对应起来

每个进程所看到（假想的）地址空间都是一样的，如下所示，都是这样的模板：

![image.png](https://typora-1310242472.cos.ap-nanjing.myqcloud.com/typora_img/20250923160425.png)

当程序调入内存运行的时候就构成了进程的内存映像，也就是虚拟地址空间，这里虚拟地址空间的东西，其实就是进程存放在实际内存的东西，只不过进程以为自己独占了整个内存，但是实际上不是，实际上是 OS 帮内存做了一个映射，将内存存放在自己以为存放在整个内存的东西映射到了实际的物理地址

进程用自己假想的虚拟地址空间中的地址去访问数据，这个地址就是虚拟地址，OS 的 MMU 对这个地址做变换来映射到真实的物理地址，然后让进程访问到各种数据

### 进程的内存映像中有什么东西？

![image.png](https://typora-1310242472.cos.ap-nanjing.myqcloud.com/typora_img/20250923160622.png)

代码段可以共享，虽然每个进程所访问代码段的时候使用的地址可能不一样，但是对于共享的代码段来说 OS 会将这些虚拟地址映射到同一个物理地址处

### 进程映像中的 OS 内核区是什么？

进程假想的地址空间中同时还会有 OS 内核区，在进程看来它可以通过系统调用访问这个区域，事实上最后还是由 OS 做了转换来访问这个区域，进程只知道可以通过系统调用，利用这个部分的逻辑地址访问这个区域，但是这里面具体是什么进程无法得知

### 共享库存储映射区是什么？

这个区域映射的实际物理内存中的数据实际上各个进程都会使用，所以这里物理内存中就保留一份

### fork 函数和 exce 函数功能是什么？

#### ==fork () 函数==

子进程是由父进程创建的进程，父进程通过调用 `fork()` 函数来创建一个子进程，子进程和父进程是两个不同的进程，他们的 PID 和 PCB 都是不同的，也不会共享虚拟地址空间；但是子进程会继承父进程对 OS 的某些全局资源，比如文件，管道，设备的访问权

当父进程调用 `fork()` 函数之后，子进程会得到一个父进程的虚拟地址空间的副本，即子进程会独立的有一个虚拟地址空间，但是这个地址空间的映射关系与父进程完全一样：

![image.png](https://typora-1310242472.cos.ap-nanjing.myqcloud.com/typora_img/20250710200101.png)
子进程和父进程此时拥有的代码段，数据段，堆，栈等完全相同

而当子进程试图修改某个页的数据的时候，就会触发这个页的复制，生成这个页的副本，这样父子进程就不会共享同一个物理页了：

![image.png](https://typora-1310242472.cos.ap-nanjing.myqcloud.com/typora_img/20250710200303.png)

这个称为写时复制技术，举一个例子如下：

```cpp
#include <unistd.h>
#include <stdio.h>

int global = 10; // 全局变量（数据段）

int main() {
    int local = 20; // 局部变量（栈）
    printf("[main start] PID=%d\n", getpid());
    
    pid_t pid = fork();
    
    if (pid == 0) {
        printf("[child] global=%d local=%d\n", global, local);
        global = 100;
        local = 200;
        printf("[child modified] global=%d local=%d\n", global, local);
    } else {
        sleep(1); // 确保子进程先执行
        printf("[parent] global=%d local=%d\n", global, local);
    }
    
    return 0;
}
```

这里父进程调用了 `fork()` 函数之后就创建了一个子进程，这时子进程独立拥有一个虚拟地址空间，这个地址空间与父进程的地址空间映射到完全相同的代码段，数据段，堆，栈；

并且此时子进程和父进程同时从 fork () 之后的代码段开始执行，此时就是两个进程并发执行了，两者的执行顺序未知；不过代码段都是可读的，一般不会触发写时复制

当子进程修改变量的时候，就会触发写时复制，变量会实际复制到实际的物理空间中，然后子进程的虚拟地址空间的映射会发生改变，这样此时父进程和子进程其实对应的是物理空间中实际的两个不同的变量 

运行结果如下所示：

```cpp
[main start] PID=1234      // 父进程执行
[child] global=10 local=20 // 子进程初始值
[child modified] global=100 local=200
[parent] global=10 local=20 // 父进程值未变
```

#### ==exec () 函数==

这个函数一般用于子进程换掉原有的父进程程序，让子进程对应一个全新的程序执行，这个函数的功能就是换掉当前进程执行的程序

具体来说，他会先摧毁原进程的虚拟地址空间的映射关系，然后将新的程序二进制装入内存，然后建立新的虚拟地址空间映射关系，此时进程就会对应全新的代码段，数据段，堆和栈

然后设置 PC 从新程序的入口开始执行

### 进程与线程的区别是什么？

OS 中的进程，即正在进行的程序，他可以看作是代码动态执行的整个过程，包含了静态的代码和各种资源的变化，**它是 OS 分配资源的基本单位**，是一个具有实际功能的程序在一个数据集合上的一次动态执行过程，**同时也是 OS 资源分配的调度的独立单位**

进程中的线程，线程是进程中的一个子执行任务，负责进程中的实际程序执行，一个进程至少含有一个线程，当然一般进程含有多个线程，可以简单认为线程是进程程序中部分功能代码模块的执行动态过程，**线程也可以简略的认为是轻量级进程，线程是 OS 调度的基本单位**

进程和线程的区别如下：

![image.png](https://typora-1310242472.cos.ap-nanjing.myqcloud.com/typora_img/20250709083215.png)

**线程自己独有的资源如下：**

（1）程序计数器，表示线程自己正在执行的代码地址

（2）寄存器集合，包含线程当前自己的工作状态

（3）栈，每个线程自己独享的，用于存放局部变量，以及函数调用的上下文信息；理论上每个线程都有自己的栈，但是实际上线程可以修改别人的栈，虽然这样会导致 bug 而不被运行，线程之间并没有什么保护措施，一个线程有自己独有的内核栈和用户栈，设置内核栈的原因就是防止别的线程来访问系统调用时保存在栈中的各种数据



上述这些就是线程自己的上下文

### 低级调度的具体过程是什么？

![image.png](https://typora-1310242472.cos.ap-nanjing.myqcloud.com/typora_img/20250911194604.png)



（1）当进程 A 想要进行 IO 请求或者时间片到期了之后，进程 A 就会发出一个系统调用，让 CPU 进入内核态

（2）CPU 进入内核态之后会修改进程的状态为阻塞态，此时 CPU 执行内核代码中的系统调用有关的程序，或者执行中断服务程序（进程 A 通过中断处理阻塞态）

（3）上述无论是系统调用函数还是中断处理程序，他们都会调用 schdule () 函数，即调度程序，调度程序会根据某种策略调度决定下一个上处理机运行的进程是谁，然后这个 schedule 函数会调用一个分派程序，告诉这个分派程序下一个应该执行的进程是谁

（4）这个分派程序会负责具体的进程上下文切换，分派程序负责保存进程 A 的程序到 A 的 PCB 中：

![image.png](https://typora-1310242472.cos.ap-nanjing.myqcloud.com/typora_img/20250911194443.png)

然后将下一个需要 CPU 执行的进程 B 的上下文放入到 CPU 中执行：

![image.png](https://typora-1310242472.cos.ap-nanjing.myqcloud.com/typora_img/20250911194515.png)

然后 CPU 就可以开始执行进程 B 了

### 对多线程模型的理解


![image.png](https://typora-1310242472.cos.ap-nanjing.myqcloud.com/typora_img/20250709171707.png)


**多对一模型：**

其实就是通常是用户进程程序的线程库来完成线程的创建调度，当这个线程需要进行 IO 的时候就被阻塞，分配一个内核栈给它，这个过程可以理解是用户级线程与内核级线程的对应起来过程

但是这种模型你只有一个内核栈，只能对应一个线程，线程的切换还是上层用户进程实际的 Yield () 函数处理的，当这个线程阻塞的时候虽然对应了内核线程，具有了内核线程的结构特点，内核感知到了这个线程，但是内核无法切换到别的线程，因为没有别的线程栈，内核只能感知一个线程，那就不能切换了，线程阻塞之后还是无法执行 Yield() 函数了，无法进行线程切换，本质上还是整个进程代码都停掉了

**一对一模型：**

这个模型其实就是通常意义上的内核级线程了，不多说，它的切换需要反复从用户态进入内核态再进入用户态，时间花了很多，而且每个线程都需要内核栈和内核中的 TCB，这也会占用更多的资源

**多对多模型：**

这种模型不必深究，可以理解为线程通常在用户态执行的好好的，当需要 IO 的时候需要内核，然后内核给他分配一个内核栈，让其对应起来，当然它执行完了之后这个内核栈也可以用给其他的线程，这里不用深究具体实现细节；很可能是用户程序和内核各有 TCB 块，当阻塞切换的时候就分配一个内核栈对应起来切换到别的线程；别的切换的时候就直接用户程序切换（瞎猜的）

这里其实只用知道用户级线程和内核级线程的含义和区别就行了

### 进程的创建

==进程的创建==

除了第一个进程，操作系统中的进程均是由另一个进程创建的，创建进程的进程和被创建的进程互为父进程和子进程。父进程是在自己的内核空间创建子进程的。

在操作系统中，**终端用户登录系统、作业调度、系统提供服务、用户程序的应用请求等都会引起进程的创建**。操作系统创建一个新进程的过程如下：

1. **为新进程分配唯一进程标识号（pid）**，并申请空白PCB（进程控制块）。若PCB申请失败，则创建失败。
2. **为进程分配运行所需资源**（如内存、文件、I/O设备、CPU时间等）。资源可能来自操作系统或父进程。若资源不足（如内存），进程进入“创建态”，阻塞父进程等待资源。
3. **初始化PCB**：
    - 初始化标志信息（如进程状态）。
    - 初始化处理机状态信息（如寄存器值）。
    - 初始化处理机控制信息（如调度参数）。
    - 设置进程优先级。
4. **将新进程加入就绪队列**，等待被调度运行。

这些创建过程是由一段原语执行的，称为创建原语，其特点就是执行的过程中不允许中断

### 进程的上下文切换

进程的上下文切换（Context Switching）是操作系统在多任务环境中实现进程调度的核心机制，指CPU从一个进程切换到另一个进程时，​**保存当前进程的运行状态（上下文）并恢复新进程状态的过程**

它涉及保存当前任务（**例如：进程、线程**）的状态（包括 CPU 寄存器、程序计数器、栈指针等），然后恢复下一个任务的状态，最终交给 CPU 执行。

主要的步骤如下：

1、**保存当前任务**的上下文：操作系统内核会保存当前任务的状态信息，包括 CPU 寄存器信息、程序计数器、堆栈指针等。这些信息通常会被保存在任务的进程控制块（PCB）中。

2、**根据调度策略**选择下一个任务：操作系统内核会根据调度算法选择一个合适的任务来执行。

3、**恢复新任务的上下文，按照保存的信息**：操作系统内核会加载新任务的状态信息，包括 CPU 寄存器、程序计数器等。这样，新任务就可以**从上次中断的地方**继续执行。

4、**运行新任务**：操作系统内核会**将 CPU 的控制权交给新任务**，新任务开始执行

### 临界资源，临界区，内核临界区

**临界区（Critical Section** 是操作系统中并发编程的核心概念，指**进程中访问共享资源（如变量、文件、硬件设备等）的代码段**。这段代码在执行时可能引发**数据竞争（Data Race）**，因此必须保证**互斥访问**——即同一时刻仅允许一个进程/线程进入临界区；

临界资源也就是一个时间段中只允许一个进程使用的资源，各个进程需要互斥的访问临界资源，一个进程中访问临界资源的代码就是临界区

**内核临界区（Kernel Critical Section）** 是操作系统内核中访问共享数据结构或硬件资源的代码段，这些资源必须被**严格互斥访问**以防止竞态条件（Race Condition）。内核临界区的特殊性在于其执行环境的高敏感性和高风险性——任何同步失败都可能导致系统崩溃、数据损坏或安全漏洞

![image.png](https://typora-1310242472.cos.ap-nanjing.myqcloud.com/typora_img/20250712210111.png)


在进程内核临界区中不能进行进程的调度和切换，但是进程在普通的临界区中则可以进行进程的调度和切换；这是因为内核临界区可能访问的是调度队列这些内核临界资源，当其访问这个临界资源的时候就会上锁，因此别的触发调度的程序就无法访问就绪队列了，也就无法完成调度和进程切换了

在内核临界区的程序绝对禁止休眠，这个是操作系统的一条铁律（目前先不管为什么，可能 408 不考）

### 各种调度的含义功能

==中级调度==

也就是内存调度，就是将暂时不能运行的进程调到外存去等待，此时这些进程的状态就称为挂起态，如果具备了运行的条件并且内存是空闲的，那么这个时候就由中级调度来决定将外存上的进程再次调入内存并修改状态为就绪态，并挂到就绪队列上等待

==低级调度==

也就是进程调度，它是根据某种算法来决定就绪队列上的哪个进程上处理机执行

==高级调度==

也就是作业调度，它决定将外存上处于后备队列的几个作业调入内存，创建进程，进程被创建之后首先处于创建态，然后系统会给其分配所需要的资源，然后修改其状态为就绪态


### 各个进程调度算法对于 IO 繁忙和 CPU 繁忙的进程的适用性（暂定，待继续总结）

IO 繁忙进程：这个进程大部分时间都在进行 IO 操作
CPU 繁忙进程：这个进程大部分时间都在进行 CPU 操作

==FCFS 算法==

不利于 IO 繁忙型进程，因为这类进程会大部分时间进行 IO 操作，只要 IO 操作它就会阻塞，然后放弃 CPU，OS 就会调度别的进程顶掉它；而相反的对于同时到达的 CPU 繁忙型进程它会一直占用，直到自己执行完毕；IO 繁忙型每次 IO 操作会被反复顶掉，因此周转时间就会很长

==短作业优先算法==

更有利于 IO 密集型进程，因为短作业优先的定义就是 CPU 更短的更优先调度，IO 密集型作业相对 CPU 密集型进程天然就在 CPU 上执行更短，所以更优先调度

==高响应比优先算法==



==优先级调度算法==

这个 IO 密集的进程优先级是更高的，因为这类进程可以先执行，然后阻塞，调度 CPU 密集的进程执行，这样 IO 和 CPU 就可以并行工作，省了很多时间

并且 IO 密集的进程往往与用户体验相关，所以应该被赋予更高的优先级

所以优先级调度算法更有利于 IO 密集进程

==时间片轮转算法==

这个调度算法对于任何进程都是一视同仁

### 短作业优先的平均周转时间和平均等待时间最少的理解

因为对于一串进程，只有执行时间更短的放在前面执行，总体的等待时间才会更少（可以用反证法证明）

这样平均周转时间是加上了等待时间的总执行时间除以进程个数，那当然就是最少的

同理平均等待时间也是最少的

当然抢占式的 SJF 的平均等待时间和平均周转时间更少

### 对用户临界资源不能同时访问的理解

对于单个 CPU 来说，这里的不能同时访问的意思其实就是并发访问，指的就是不能在一段时间中多个进程同时访问临界资源

具体来说，如果一个进程正在访问用户临界资源，它是可以并发的，即可以被阻塞暂停然后 CPU调度别的进程去 CPU 执行，但是这个别的进程不能访问这个临界资源，即对于单 CPU 的不能在一段时间内同时访问临界资源

这个才是不能同时访问临界资源的意思，而不是两个进程在同一时刻并行访问临界资源（当然多核 CPU 也得做到并行的进程不能同时访问临界资源）

### 28 进程转换与 CPU 状态切换（等看完 HIT 的 OS 课程详细总结 OS 切换进程状态的具体过程）

![image.png](https://typora-1310242472.cos.ap-nanjing.myqcloud.com/typora_img/20250712191648.png)

A：
阻塞进程是由操作系统将进程 PCB 插入到阻塞队列的，这个是阻塞的过程是由 OS 完成的，开始执行以及完成的时候仍然处于内核态，OS 下一步就该去进行进程调度了，而不是返回到用户态，并且哪怕没有可以调度的线程了，OS 也可能停留在内核态继续执行这个被阻塞进程的一些 IO 中断处理，也不一定返回到用户态

B：

C：
唤醒进程也是 OS 完成的，执行唤醒进程的时候仍然在内核态，OS 完成将进程的 PCB 块塞到就绪队列中，但是下一步 CPU 也不一定会回到用户态；因为下一个就绪的进程可能是内核的进程；并且哪怕下一个就绪队列头部的进程不是内核进程， OS 完成唤醒之后也不一定立刻就回到了用户态，OS 可能还需要跳转执行一些别的内核函数呢

### 40 各个调度算法的系统开销分析

![image.png](https://typora-1310242472.cos.ap-nanjing.myqcloud.com/typora_img/20250716212507.png)

这里的系统开销包括，维护调度算法的数据结果，比如维护多个反馈队列等；计算优先级响应比等信息进行调度判断；以及更换进程带来的上下文切换开销等等

高响应比：需要实时更新每个进程的等待时间，然后计算每个进程的响应比，进行调度判断，这个开销不算小

多级反馈队列：需要维护多个反馈队列，需要更改维护每个进行的优先级，需要将进程进行队列调整，如果每个反馈队列是时间片轮转的话还有切换开销，多级反馈队列调度开销是比较大的

时间片轮转：需要频繁上下文切换，这个开销也不少

你显然 C 开销是最小的，它不用什么维护数据队列（多级反馈），也不用计算什么东西进行调度判断（高响应比，多级反馈队列），也不用频繁切换进程（时间片轮转）
