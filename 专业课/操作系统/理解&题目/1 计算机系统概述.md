### 单道批处理系统和多道批处理系统的区别是什么？

单道批处理系统和多道批处理系统都是批处理系统

批处理系统是与最开始的人工操作相对的，批处理系统是指将用户的多个任务​**​成批打包​**​处理，通过自动调度顺序执行，解决早期人工操作的低效问题

==单道批处理系统==

这个系统是指内存中只能有一个进程执行，只有这个进程执行完毕，才能去执行其他的进程，进程之间的执行是严格串型的，这样会因为等到进程的 IO 操作而浪费大量的 CPU 时间

==多道批处理系统==

多道批处理系统实际上是将 A，B，C 三个程序打包给计算机，此时计算机的内存中可以同时存在这三个程序，然后由系统决定什么时候执行 A，当 A 访问 IO 阻塞的时候系统再切换执行 B，就这样并发执行，直到三个程序全部执行完毕，然后用户再看结果

### 多道批处理系统和分时系统的区别是什么？

这两者其实都存在程序的切换

但是多道批处理系统实际上是将 A，B，C 三个程序打包给计算机，此时计算机的内存中可以同时存在这三个程序，然后由系统决定什么时候执行 A，当 A 访问 IO 阻塞的时候系统再切换执行 B，就这样并发执行，直到三个程序全部执行完毕，然后用户再看结果；如果结果出错，用户只能重新一遍上述过程

分时系统则是将 CPU 执行过程强制切分为时间片，比如 20 ms 一个时间片，然后程序 A，B，C 轮流使用时间片，并且这些程序是用户可以自己登录系统提交的，比如用户 2 提交了程序 B，然后在轮流使用时间片执行的过程中，程序 B 执行了一部分发现报错，那么用户 2 就可以实时修改程序 B，修改了之后继续交给计算机执行，继续使用时间片即可；因为延迟很小，这样用户 2 就好像自己在独占计算机一样；分时系统具有很强的交互性

这就是两者的区别了

# 理解

### OS 的并发和共享概念（最基本特征）

OS 的并发：是指两个或者多个事件在同一时间间隔内发生，这里的时间间隔是一个宏观的时间段，在这个时间段中看似多个事件是同时执行的，但是在时间段的内部的微观视角这些事件仍然是利用分时进行交替进行的

OS 的共享：是指 OS 中的资源可以被多个并发的进程共同使用

有了并发才有共享，因为假如没有并发，一个程序执行到底，那共享就没意义了

有共享才能进行并发，你资源不能共享的话，当一个进程占用这个资源不放手，切换到别的进程的时候不能使用资源，也就无法交替进行，也就没有并发的概念了

### 访管指令，特权指令，非特权指令

访管指令是在用户态执行的指令，比如 INT 0 x 80 指令，应用程序可以通过执行访管指令来让 CPU 切换到内核态，具体来说，当执行 INT 0 x 80 这样的指令之后，计算机硬件会自动切换 CPU 的特权级，切换到内核态（当然 CPU 切换到内核态的方法不止一种），这个称为自陷，是 CPU 内部异常的一种

特权指令是只能在 CPU 内核态才能执行的指令，它直接控制计算机的关键硬件资源，比如关中断指令 cli 等

非特权指令是可以在用户态也可以在内核态执行的指令，比如常用的 ADD 指令等

### 内核程序与应用程序

应用程序就是常见的电脑上运行的程序，比如微信等等，运行在用户态的程序就是用户程序

内核程序是直接运行在内核态的程序，各种各样的内核程序整体组成了操作系统的内核，它是最接近硬件的部分


### 内核态（管态）与用户态（目态）

内核态与用户态是 CPU 的两种状态；CPU 中有一个状态寄存器 PSW，其中有一位用来表示是内核态还是用户态比如 1 表示内核态，0 表示用户态

内核态切换到用户态：内核程序通过执行一条特权指令，这个指令会将 CPU 的标志位设置为用户态，接着 OS 内核程序就会让出 CPU 的使用权，让应用程序在 CPU 上运行

用户态切换到内核态：从用户态切换到内核态一定是靠“中断”执行的，这里“中断”包括内部异常和外部中断，当 CPU 检测到异常或者外部中断之后，硬件就会自动切换成内核态，然后操作系统内核夺回 CPU 的控制权（这一步一般发生在中断响应的时候，由硬件自动完成，可以不了解细节）

### 内核程序与"中断" (内部异常和外部中断)

中断的大部分都属于内核程序，不过也有部分不是内核程序中，**中断（异常和外中断）是操作系统内核夺回 CPU 控制权的唯一途径**，只要发生中断，CPU 就会切换到内核态，操作系统内核夺回 CPU 控制权

以外部中断为例，发出中断请求以及 CPU 响应中断的过程是硬件自动完成的，当然不属于内核程序；不过 CPU 响应中断之后就进入了内核态

（中断向量法）接着 CPU 识别中断源获得中断号，然后计算中断向量地址，然后根据中断向量地址访问中断向量表，从中读出中断处理程序的地址和状态字 PSW，然后跳转到中断处理程序，这个也是硬件完成的，所以也不属于内核程序

然后中断服务程序的执行就属于内核程序了

在中断服务程序的末尾，服务程序会让 CPU 发送 EOI 给中断控制器，中断控制器收到 CPU 发过来的 EOI 信号之后会清除 ISR 寄存器中该中断请求，表示中断处理完毕，接着服务程序开中断，以及中断返回，这些过程是 OS 内核与硬件共同的作用，也不完全属于内核程序

### 系统调用与库函数

系统调用是操作系统内核提供给上层应用程序的接口，也可以看作是应用程序可以使用的特殊函数

操作系统内核程序中实现了系统调用的实例，应用程序可以通过系统调用来请求操作系统内核的服务，来帮助完成一些特殊的功能

库函数则是高级语言中的东西，库函数可以将系统调用接口进一步封装来方便程序员的使用，程序员通过使用库函数来使用系统调用接口；当然有的库函数也不一定涉及系统调用，比如取绝对值函数

### 系统调用的过程与访管指令（一个具体的自陷异常的例子）

以 C 语言调用封装函数 open () 为例来说明这个过程，用户程序打开一个文件的代码如下：

```d
// 用户程序 (user_program.c)
#include <fcntl.h>

int main() {
    int fd = open("/tmp/test.txt", O_RDWR | O_CREAT, 0644);
    // fd 为文件描述符
    return 0;
}
```

这个 open 函数是库函数，封装了一个系统调用接口 syscall () 函数：

```c
// glibc 的 open() 封装
int open(const char *pathname, int flags, mode_t mode) {
    return syscall(SYS_open, pathname, flags, mode);
}
```

如果从汇编层面来看，这个 syscall () 函数的汇编层面如下，它是先在用户态执行一些非特权指令给 CPU 传递一些参数，然后执行一个 syscall 访管指令（陷入指令）触发 CPU 中断：

```c
mov rax, 2        ; 系统调用号 SYS_open → rax
mov rdi, path     ; 参数1: 路径字符串地址 → rdi ("/tmp/test.txt")
mov rsi, 0x242    ; 参数2: 标志位 O_RDWR|O_CREAT → rsi
mov rdx, 0644o    ; 参数3: 文件权限 → rdx
syscall           ; 触发系统调用 (替代传统的 int 0x80)
```

下面是标准的中断过程，CPU 响应中断（自陷异常），保存断点，切换到内核态，然后 CPU 识别中断，找到中断入口程序，然后执行中断服务处理程序

这里的中断服务程序，就是库函数中封装的系统调用接口 syscall () 的具体实现，这就是内核程序，然后 CPU 根据传递给它的参数执行这个系统调用的具体处理过程

处理完毕之后返回原来的程序，切换回用户态，操作系统内核交出 CPU 的控制权，然后继续执行用户程序

### 硬件定时器与操作系统的时钟中断（具体学了进程回头补充）

硬件定时器是一个精密的时钟定时电路，它的最主要的作用就是让操作系统拥有时间观念

硬件定时器由 OS 设置初始值，比如如果 CPU 的时钟周期是 1 ns，那么操作系统如果设置间隔为 10 ms 的话，他就会让硬件定时器每过 10 000 000 个时钟周期触发一次中断，这个中断就是时钟中断

时钟中断是外部中断，CPU 检测到时钟中断之后就会像别的外部中断一样，转到中断服务程序进行执行

不过这里时钟中断的服务程序非常重要，它主要包括下面几个功能

（1）更新系统时间，每次中断发生的时候 ISR 就会更新维护系统时间变量，让系统准确反应当前时间

（2）时间片管理和进程调度，在多任务的操作系统中，每个进程会分配一个时间片，时钟中断会检查当前进程的时间片是否用完，如果用完，则会进行进程调度将 CPU 分配给其他进程

时钟中断会更新当前进程占用的时间，并且，一个进程占用 CPU 的时间只能靠时钟中断来确定，因为当一个进程开始执行的时候操作系统只能通过时钟中断来判断它用了多少 CPU 时间，中断一次就相当于这个进程用了一个时钟中断间隔的时间，操作系统就根据这个来确定进程占用 CPU 的时间（具体如何实现的等学完进程再来总结）

同时，操作系统还会给每个进程分配一些时间片，判断时间片还剩下多少也是通过时钟中断进行的，中断一次，这个进程占据的时间片就减少一个中断间隔，然后决定是否进行进程调度，操作系统只能通过时钟中断的间隔来处理与时间有关的操作

时钟中断功能是实时操作系统时间片轮转的基础；以及多任务操作系统中合理分配时间片，防止某个进程长时间占据 CPU 的功能实现基础

（3）系统计时，主要用于分析记录当前系统运行的时长，这样可以执行一些延时操作和定时任务
（4）性能监控，用于记录 CPU 的运行时间，统计系统负载等等

时钟中断是非常重要的功能，决定 OS 的最核心的功能，所以硬件定时器的设置指令当然是特权指令，禁止用户可以直接使用

### 系统调用和过程调用

过程调用其实就是普通的函数调用，系统调用需要执行中断过程，调用内核中的系统服务实例

两者的区别如下：

（1）过程调用需要保存 PC，即 PC 需要压栈，但是不用保存 PSW 状态；但是系统调用必须保存 PSW，并且系统调用保存 PC 和 PSW 是在中断响应阶段由隐指令完成的（硬件自动完成）；而过程调用则是利用 Call 指令将 PC 的值压栈保存

这里过程调用之所以不用保存 PSW 是因为过程调用的函数是用户自己知道的，过程调用的处理结果（后果）也是用户可预知的，如果过程调用改变了 PSW 的值，那这也是用户自己需要的，那么当然之前的 PSW 就不应该保存并在返回的时候恢复，否则这过程调用就没有意义了；而中断则是一个意外事件，是用户不可预知的，用户并不知道中断会不会发生，以及什么时候发生，你中断假如改变了 PSW，如果返回的时候不恢复，那用户的程序还是按照以前的 PSW 的东西进行执行，当然就会出错了

（2）过程调用和系统调用都得保存通用寄存器的值，因为过程调用主函数本身的一些参数可能会放在通用寄存器中，过程调用的子程序可能用到这些这些寄存器，如果被修改的话就会出错，这个与 PSW 还是有区别的

### 计算机启动的基本过程

==（1）第一阶段：BIOS==

CPU 上电之后首先进行复位，此时 CS = 0 xFFFF，IP = 0 x 0000 ，通过 CS 左移一位 + IP，（或者说PC 指向 0 xFFFF 0，CS: IP 是 x 86 下实现了 PC 具体物理功能的部件，是 PC 的具体物理表现形式，PC 一般指的所有架构的通用的一个程序计数器） ，此处不是 BIOS，而是一个 jump 指令，即先执行一个长跳转指令，直接跳转到固化的 ROM 中的启动代码处读取（即 BIOS，基本输入输出系统，也可以称为自举程序，他是存放在 ROM 中的引导程序），然后将 BIOS 程序加载到 RAM，然后执行 BIOS 程序，即 BIOS 获得 CPU 的控制权

![image.png](https://typora-1310242472.cos.ap-nanjing.myqcloud.com/typora_img/20250706161325.png)

BIOS 会首先加载硬件 IO 的驱动程序和中断向量表，然后才能检查硬件，因为硬件检查自己的状态必须用到 IO 驱动程序和中断服务，调用中断服务处理程序来完成自己的检查

通过硬件自检之后，BIOS 接着就会将磁盘的主引导记录（MBR）读入到内存中，这个是 BIOS 的最后一个任务了，这个也就是 BIOS 将 CPU 控制权交给相应磁盘程序过程

具体来说，BIOS 程序将硬盘的最开始的 512 字节读入到内存的 0 x 7 c 00 处，并设置 PC 指向 0 x 7 C 00，也就是 CS = 0 x 07 c，IP = 0 x 0000，然后执行装入的程序指令（MBR），MBR 接过控制权

当然，具体是读哪个磁盘或者 U 盘的 MBR 这个其实用户可以进入 BIOS 界面自己设置，也可以默认先启动 C 盘


==（2）第二阶段：主引导记录==

BIOS 会将硬盘的主引导记录（MBR）读入内存，CPU 就开始执行 MBR 的代码，这个时候就是这个硬盘的 MBR 接过了控制权；具体来说，BIOS 会将对应硬盘的最开始的 512 字节数据读入内存，这最前面的的 512 字节，就是这个硬盘的主引导记录（MBR）

这个 MBR 的基本结构如下：

![image.png](https://typora-1310242472.cos.ap-nanjing.myqcloud.com/typora_img/20250706162544.png)

调用操作系统的机器码，CPU 就通过执行这部分程序指令，这部分就是磁盘引导程序，然后转到这个硬盘的操作系统存放的分区位置去将分区引导记录 PBR 调入内存，让 PBR 接管 CPU 的控制权

分区表，分区表是记录了这个硬盘的各个分区信息，它的长度是 64 B，最多分为 4 项，每一项是 16 B，这 16 B 的数据记录了硬盘一个分区的关键信息，这 16 B 的数据如下所示：

整个硬盘最多分为 4 个一级主分区，比如常说的C，D，E，F 盘
![image.png](https://typora-1310242472.cos.ap-nanjing.myqcloud.com/typora_img/20250706163210.png)

主引导记录的程序通过分区表中的每个区的信息来分辨哪个区是激活的，说明就需要调用这个区中存放的操作系统程序，主引导记录同时还要根据分区表中的分区信息知道这个激活分区在硬盘的具体位置

然主引导记录就会将这个分区的第一个扇区内容加载到内存，开始执行分区第一个扇区程序，即这个扇区开始接过 CPU 的控制权，这个分区的第一个扇区，称为卷引导记录（VBR）或者分区引导记录（PBR）

==（3）操作系统，启动！==

CPU 的控制权交给了硬盘的某个分区后，执行 PBR（分区引导记录）中的程序，这个程序称为分区引导程序

分区引导记录的功能是，找到激活分区根目录下的用于初始化操作系统的程序，即启动管理器，将启动管理器加载到内存执行，此时启动管理器接过控制权

![image.png](https://typora-1310242472.cos.ap-nanjing.myqcloud.com/typora_img/20250706171713.png)

启动管理器会执行一系列操作系统初始化的工作，启动管理器也称为操作系统初始化程序，启动管理器会加载操作系统的内核，以及各种关键模块，服务，让操作系统接过控制权，于是操作系统正式启动（启动管理器执行的过程，就是电脑界面开始转圈的过程，转圈完毕操作系统正式启动，用户开始输入密码进入桌面）

主要看上面那道真题的定义

（1）ROM 中的引导程序，其实就是 BIOS 中的引导程序，位于固化的 ROM 中，他会让 CPU 跳转到硬盘的 MBR，让 MBR 程序接过控制权

（2）磁盘引导程序，其实就是硬盘主引导记录 MBR 中的程序，它位于硬盘的最开始 512 字节中，硬盘引导程序会根据分区表选择哪个分区的操作系统，然后将控制权转交给分区引导程序

（3）分区引导程序，其实就是分区的引导记录 PBR 中的程序，它位于分区的第一个扇区中，它用于找到根目录中的操作系统初始化程序，即启动管理器，然后将控制权交给启动管理器

（4）启动管理器，也就是操作系统初始化程序，其用于真正的将操作系统加载到内存，接着操作系统正式接过控制权

（5）操作系统初始化程序，也就是启动管理器，他会负责正式将操作系统内核装入内存，让操作系统接过控制权
### 宏内核和微内核

宏内核是将系统的主要功能全部塞进内核，然后这些功能作为一个主要的整体运行在核心态，目前的主流操作系统都是大内核的结构

微内核是只保留内核最基本的功能，其他的服务功能放在上层移动到用户态执行，从而降低内核的复杂性
![image.png](https://typora-1310242472.cos.ap-nanjing.myqcloud.com/typora_img/20250707163706.png)

==两者的优缺点：==

（1）**性能方面**，宏内核的性能是比微内核要高的，因为宏内核的各个功能杂糅在一起，互相调用的时候就很方便，但是微内核的各个功能分开放在用户态，他们之间调用通信的时候需要反复从用户态陷入内核态，利用微内核帮助通信，所以性能较差，比不上大内核

（2）**移植性**，大内核移植比微内核困难，因为大内核的所有功能杂糅一起，移植到别的机器的时候可能这个机器需要的上层功能不一样，那么大内核就得重新改写；而微内核只保留一些最基本的功能，各个机器的基本功能需求差不多都是一样的，所以可以直接移植到别的机器，只用重新写一下上层的服务功能就行了

（3）**稳定性和安全性**，大内核的所有功能杂糅一起，那么一旦某个功能崩溃，就会影响其他的功能，整个系统就会崩溃，它不稳定；微内核的最基本功能运行在核心态，其他的功能都分模块运行在用户态，依靠微内核进行互相通信，那么某个上层功能服务模块崩溃之后只是它自己崩溃，整个系统的微内核仍然是好好运转的，也不会影响其他的服务模块，所以可靠性安全性微内核比大内核要强

（4）**扩展性和灵活性**，微内核比大内核更灵活，因为如果想要在微内核中加入一些功能，只用自己写一下服务器的功能放到用户态即可，扩展容易；但是大内核的各个功能杂糅在一起，想要再加入一个新功能就得考虑与其他功能之间的联系，不容易改写

### 微内核提供的服务

微内核主要负责一些与硬件相关的最基本功能，以及负责上层各个服务模块之间的通信：
![image.png](https://typora-1310242472.cos.ap-nanjing.myqcloud.com/typora_img/20250707170626.png)
所谓最基本的功能，即微内核主要负责各个功能中的机制问题，而策略问题则交给上层的服务器实现；

所谓机制，就是指怎么做的问题，是指操作系统各种功能的**通用操作步骤和硬件交互能力**，比如 CPU 如何才能切换到另一个进程问题，机制不关系你具体切换到哪个进程，它只关心你确定好了进程之后接下来实际切换的步骤

所谓策略，就是指做什么以及为什么做的问题，它主要负责基于什么条件来选择什么对象，以及怎么配置这些对象和怎么使用它们，比如策略负责的就是下次中断的时候该切换到哪一个进程？或者给这个进程分配多少时间片？

而微内核主要就是负责机制，策略交给上层的服务器处理，这个就是微内核的策略-机制分离思想

具体来说微内核负责：

（1）**进程管理**，微内核主要负责，进程切换和进程调度的实际步骤，以及多个处理机之间同步的实现，这些都属于机制；而用户进程的分类，以及各自的优先级，这些属于策略，一般放在上层服务器中处理

（2）**中断和陷入处理**，这一块与硬件联系非常紧密，以及是实现各种功能的通用步骤，所以放在微内核中

（3）**低级存储器管理**，微内核负责实现逻辑地址和物理地址之间的转换等页表机制和地址转换机制，这一块是通用固定步骤，且与硬件联系紧密，放到微内核中；而实际虚存的管理，采用什么页面置换算法，采用何种内存分配和回收方法，这些属于策略，放到服务器中

### 第一类虚拟机管理程序

第一类虚拟机管理程序更像是一个操作系统，他是唯一运行在最高权限等级的程序，它运行在裸机之上并拥有多道程序功能

这个虚拟机管理程序向上提供了多个虚拟机器，这些虚拟机器实际上是软件，是模拟这个裸机硬件的软件，相当于多个裸机的复制品，所以在这个虚拟机器之上可以运行多种操作系统：

![image.png](https://typora-1310242472.cos.ap-nanjing.myqcloud.com/typora_img/20250707194928.png)

虚拟机上的用户程序认为自己运行在用户态，实际上也的确是裸机的用户态，他会调用虚拟机上的操作系统执行内核服务，虚拟机上的操作系统会认为自己处于内核态，这个称为虚拟内核态（实际上不是裸机的内核态）

当虚拟机之上执行了一条特权指令的时候会直接陷入到虚拟机管理程序，即虚拟机管理程序接过 CPU 的控制权

这个虚拟机管理程序会检查这条特权指令是虚拟上谁执行的

如果是用户执行的，按正常来讲这个就是内部异常，那么虚拟机管理程序就会模拟真实硬件面对这个异常的反应，也就是内部异常中断中的硬件反应，来处理这个敏感事件，通常是抛出异常或者进行错误处理

如果特权指令是虚拟机上的操作系统执行的，那么虚拟机管理程序就会控制硬件安全的执行这条指令，执行完毕之后再转到虚拟机上的操作系统执行，即将控制权还给虚拟机上的操作系统，继续进行操作系统的工作

### 第二类虚拟机管理程序

第二类虚拟机管理程序像是一个在宿主操作系统之上的一个普通的程序，这个程序同样伪装成了完整的具有各种 CPU 和硬件的计算机，大部分运行在裸机的用户态，少部分运行在内核态，比如 Virtual Box 和 VMWare 就是这一类虚拟机管理程序，VMware Workstation 也是，并且是 x 86 首个虚拟机管理程序

这个 VMM 之上的操作系统称为客户操作系统：

![image.png](https://typora-1310242472.cos.ap-nanjing.myqcloud.com/typora_img/20250707201236.png)
这一类的虚拟机管理程序想要给它之上的客户操作系统提供硬件服务资源，它只能请求它之下的宿主操作系统给他分配硬件资源，然后它再分配给它之上的客户操作系统

### 两类 VMM 的区别（学了文件系统回头来看）

（1）硬件控制，第一类 VMM 直接运行在裸机之上，直接可以控制硬件；第二类 VMM 需要请求宿主 OS 给他提供硬件服务

（2）客户操作系统的资源分配方式，第一类 VMM 分配给客户 OS 的是没有经过抽象的实际的硬件资源，比如就是实际的硬盘中的 0~1024 B 字节给第一个客户 OS，硬盘中 1015 ~ 2048 B 给第二个宿主 OS，分配资源的方式有点像外核，但是实际控制这些资源的还是 VMM，只是分配给他们的是这些；第二类 VMM 分配的实际上是一个大文件，比如第二类 VMM 需要 10 G 的存储空间，他会向宿主 OS 申请创建一个 10 GB 的大文件，这 10 GB 的大文件是完全由宿主机决定的，属于文件系统中被宿主机包装一次的文件，他甚至在实际的磁盘中都不一定是连续的（具体学了文件系统再回头来看），然后这个第二类的 VMM 继续将这 10 GB 的文件划分给客户 OS，客户 OS 得到的实际是被包装了两次的文件资源，这些都是虚拟的，不是实际的磁盘硬件

（3）性能，第一类 VMM 直接控制硬件，第二类还需要请求宿主 OS 提供硬件服务，显然第二类 VMM 性能更差；并且第一类 VMM 可以支持的客户 OS 更多，因为第一类 VMM 占用了全部的硬件资源；但是第二类 VMM 本身只是宿主 OS 上的一个程序，需要跟宿主 OS 上的别的程序抢资源，当然自己可以支配的硬件资源就少，可以支持的客户 OS 就少一些

（4）虚拟机的可迁移性，第二类 VMM 更好，因为第二类 VMM 之上的虚拟机（操作系统）所获得的资源是被层层打包的，实际的硬件是由宿主 OS 决定的，这个客户 OS 的各种地址都是虚拟的，需要宿主 OS 映射才能对应实际的硬件地址，那么这个客户 OS 迁移的时候只要对面的宿主 OS 差不多就行，由宿主 OS 接着给他分配硬件；但是第一类 VMM 之上的客户 OS 是实际占用了硬件资源，他的地址全都根据当前机器的硬件情况分配好了是固定的，你迁移到另一台机器，人家有可能这个实际地址有别的数据或者压根就没有这个地址，当然迁移就差很多

（5）运行模式，第一类 VMM 完全运行在最高权限状态；第二类 VMM 大部分运行在用户态，少部分运行在内核态，第一类 VMM 可以使用最高特权指令；第二类 VMM 几乎全部在用户态，当第二类的 VMM 之上的客户 OS 进行系统调用的时候 VMM 会代替这个客户 OS 向宿主 OS 发起调用，由宿主 OS 控制硬件提供服务

### 6 对批处理系统的理解

![image.png](https://typora-1310242472.cos.ap-nanjing.myqcloud.com/typora_img/20250703160739.png)

I:
单程程序系统中 CPU 执行程序是顺序的，当这个程序进行 IO 操作的时候 CPU 就会空转，等待 IO，此时 CPU 就被浪费了

而多道程序系统当某个程序需要等待 IO 的数据的时候 CPU 就可以切换执行别的程序，这样 CPU 就被充分利用起来了

II:
你多道需要管理很多程序并发执行，需要用堆栈保存别的程序的断点啊，现场啊之类的，还得硬件支持中断，当然系统开销比单道系统要大才对

III:
正确，因为多道将某个程序等待 IO 的时间利用起来了，可以用于执行别的程序，当然相同时间完成的任务就更多，所以吞吐量必然更大

IV:
与 I 的分析是一致的，对于一个不使用 IO 的程序来说，如果是单道系统，那么在执行这个程序的时候 IO 就是完全空闲的，不能与 CPU 并行执行

但是对于多道系统，在执行一个不使用 IO 的程序的时候可以做到 CPU 和 IO 并行工作，这样完全可以做到适当的安排下在 CPU 运行的同时让 IO 也不停下，IO 设备当然利用率就高了

IV 和 I 其实是对称的

可以举一个例子来理解，对于同样的两个程序：

![image.png](https://typora-1310242472.cos.ap-nanjing.myqcloud.com/typora_img/20250703162349.png)

如果是串型的单程序系统，那么总的执行时间就是 50 ms，其中 IO 执行了 30 ms，CPU 执行了 20 ms，那么各自的利用率就是 IO：0.6 和 CPU: 0.4

但是如果是多道程序系统，由于任务 A 在 IO 的时候 CPU 可以执行任务 B

这样系统执行完毕所花的总时间一定小于 50 ms，但是 CPU 和 IO 他们各自运行所花的时间是不变的，他们还是干了那么多活，只是他们两个是可以并行干活的，即 CPU 仍然执行了 20 ms；IO 仍然执行了 30 ms；只是这些时间有重叠

显然利用率变高了

设备驱动程序就是管理硬件资源的最直接的内核程序

### 20 中断向量表的数据结构

![image.png](https://typora-1310242472.cos.ap-nanjing.myqcloud.com/typora_img/20250705185651.png)

中断向量就是每个服务程序的入口地址和初始状态字 PSW

中断向量表就是所有类型中断的入口地址和初始状态字 PSW 堆在一起存放的位置

向量地址就是这个中断向量表的地址，也成为中断指针

CPU 在拿到中断号之后是由硬件自动计算出这个中断的中断向量所在的位置的，然后从这个位置取出服务程序的入口地址给 PC

那显然硬件只能通过乘或者加得到中断向量的地址，所以中断向量表必须得支持随机存取，所以不能是链表这样的结构（硬件无法遍历链表）
