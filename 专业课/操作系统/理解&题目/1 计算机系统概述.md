## 理解

### OS 的并发和共享概念（最基本特征）

OS 的并发：是指两个或者多个事件在同一时间间隔内发生，这里的时间间隔是一个宏观的时间段，在这个时间段中看似多个事件是同时执行的，但是在时间段的内部的微观视角这些事件仍然是利用分时进行交替进行的

OS 的共享：是指 OS 中的资源可以被多个并发的进程共同使用

有了并发才有共享，因为假如没有并发，一个程序执行到底，那共享就没意义了

有共享才能进行并发，你资源不能共享的话，当一个进程占用这个资源不放手，切换到别的进程的时候不能使用资源，也就无法交替进行，也就没有并发的概念了

### 多道批处理系统和分时系统的区别

这两者其实都存在程序的切换

但是多道批处理系统实际上是将 A，B，C 三个程序打包给计算机，此时计算机的内存中可以同时存在这三个程序，然后由系统决定什么时候执行 A，当 A 访问 IO 阻塞的时候系统再切换执行 B，就这样并发执行，直到三个程序全部执行完毕，然后用户再看结果；如果结果出错，用户只能重新一遍上述过程

分时系统则是将 CPU 执行过程强制切分为时间片，比如 20 ms 一个时间片，然后程序 A，B，C 轮流使用时间片，并且这些程序是用户可以自己登录系统提交的，比如用户 2 提交了程序 B，然后在轮流使用时间片执行的过程中，程序B 执行了一部分发现报错，那么用户 2 就可以实时修改程序 B，修改了之后继续交给计算机执行，继续使用时间片即可；因为延迟很小，这样用户 2 就好像自己在独占计算机一样；分时系统具有很强的交互性

这就是两者的区别了

### 访管指令，特权指令，非特权指令

访管指令是在用户态执行的指令，比如 INT 0 x 80 指令，应用程序可以通过执行访管指令来让 CPU 切换到内核态，具体来说，当执行 INT 0 x 80 这样的指令之后，计算机硬件会自动切换 CPU 的特权级，切换到内核态（当然 CPU 切换到内核态的方法不止一种），这个称为自陷，是 CPU 内部异常的一种

特权指令是只能在 CPU 内核态才能执行的指令，它直接控制计算机的关键硬件资源，比如关中断指令 cli 等

非特权指令是可以在用户态也可以在内核态执行的指令，比如常用的 ADD 指令等

### 内核程序与应用程序

应用程序就是常见的电脑上运行的程序，比如微信等等，运行在用户态的程序就是用户程序

内核程序是直接运行在内核态的程序，各种各样的内核程序整体组成了操作系统的内核，它是最接近硬件的部分


### 内核态（管态）与用户态（目态）

内核态与用户态是 CPU 的两种状态；CPU 中有一个状态寄存器 PSW，其中有一位用来表示是内核态还是用户态比如 1 表示内核态，0 表示用户态

内核态切换到用户态：内核程序通过执行一条特权指令，这个指令会将 CPU 的标志位设置为用户态，接着 OS 内核程序就会让出 CPU 的使用权，让应用程序在 CPU 上运行

用户态切换到内核态：从用户态切换到内核态一定是靠“中断”执行的，这里“中断”包括内部异常和外部中断，当 CPU 检测到异常或者外部中断之后，硬件就会自动切换成内核态，然后操作系统内核夺回 CPU 的控制权（这一步一般发生在中断响应的时候，由硬件自动完成，可以不了解细节）

### 内核程序与"中断" (内部异常和外部中断)

中断的大部分都属于内核程序，不过也有部分不是内核程序中，**中断（异常和外中断）是操作系统内核夺回 CPU 控制权的唯一途径**，只要发生中断，CPU 就会切换到内核态，操作系统内核夺回 CPU 控制权

以外部中断为例，发出中断请求以及 CPU 响应中断的过程是硬件自动完成的，当然不属于内核程序；不过 CPU 响应中断之后就进入了内核态

（中断向量法）接着 CPU 识别中断源获得中断号，然后计算中断向量地址，然后根据中断向量地址访问中断向量表，从中读出中断处理程序的地址和状态字 PSW，然后跳转到中断处理程序，这个也是硬件完成的，所以也不属于内核程序

然后中断服务程序的执行就属于内核程序了

在中断服务程序的末尾，服务程序会让 CPU 发送 EOI 给中断控制器，中断控制器收到 CPU 发过来的 EOI 信号之后会清除 ISR 寄存器中该中断请求，表示中断处理完毕，接着服务程序开中断，以及中断返回，这些过程是 OS 内核与硬件共同的作用，也不完全属于内核程序

### 系统调用与库函数

系统调用是操作系统内核提供给上层应用程序的接口，也可以看作是应用程序可以使用的特殊函数

操作系统内核程序中实现了系统调用的实例，应用程序可以通过系统调用来请求操作系统内核的服务，来帮助完成一些特殊的功能

库函数则是高级语言中的东西，库函数可以将系统调用接口进一步封装来方便程序员的使用，程序员通过使用库函数来使用系统调用接口；当然有的库函数也不一定涉及系统调用，比如取绝对值函数

### 系统调用的过程与访管指令（一个具体的自陷异常的例子）

以 C 语言调用封装函数 open () 为例来说明这个过程，用户程序打开一个文件的代码如下：

```d
// 用户程序 (user_program.c)
#include <fcntl.h>

int main() {
    int fd = open("/tmp/test.txt", O_RDWR | O_CREAT, 0644);
    // fd 为文件描述符
    return 0;
}
```

这个 open 函数是库函数，封装了一个系统调用接口 syscall () 函数：

```c
// glibc 的 open() 封装
int open(const char *pathname, int flags, mode_t mode) {
    return syscall(SYS_open, pathname, flags, mode);
}
```

如果从汇编层面来看，这个 syscall () 函数的汇编层面如下，它是先在用户态执行一些非特权指令给 CPU 传递一些参数，然后执行一个 syscall 访管指令（陷入指令）触发 CPU 中断：

```c
mov rax, 2        ; 系统调用号 SYS_open → rax
mov rdi, path     ; 参数1: 路径字符串地址 → rdi ("/tmp/test.txt")
mov rsi, 0x242    ; 参数2: 标志位 O_RDWR|O_CREAT → rsi
mov rdx, 0644o    ; 参数3: 文件权限 → rdx
syscall           ; 触发系统调用 (替代传统的 int 0x80)
```

下面是标准的中断过程，CPU 响应中断（自陷异常），保存断点，切换到内核态，然后 CPU 识别中断，找到中断入口程序，然后执行中断服务处理程序

这里的中断服务程序，就是库函数中封装的系统调用接口 syscall () 的具体实现，这就是内核程序，然后 CPU 根据传递给它的参数执行这个系统调用的具体处理过程

处理完毕之后返回原来的程序，切换回用户态，操作系统内核交出 CPU 的控制权，然后继续执行用户程序

### 6 对批处理系统的理解

![image.png](https://typora-1310242472.cos.ap-nanjing.myqcloud.com/typora_img/20250703160739.png)

I:
单程程序系统中 CPU 执行程序是顺序的，当这个程序进行 IO 操作的时候 CPU 就会空转，等待 IO，此时 CPU 就被浪费了

而多道程序系统当某个程序需要等待 IO 的数据的时候 CPU 就可以切换执行别的程序，这样 CPU 就被充分利用起来了

II:
你多道需要管理很多程序并发执行，需要用堆栈保存别的程序的断点啊，现场啊之类的，还得硬件支持中断，当然系统开销比单道系统要大才对

III:
正确，因为多道将某个程序等待 IO 的时间利用起来了，可以用于执行别的程序，当然相同时间完成的任务就更多，所以吞吐量必然更大

IV:
与 I 的分析是一致的，对于一个不使用 IO 的程序来说，如果是单道系统，那么在执行这个程序的时候 IO 就是完全空闲的，不能与 CPU 并行执行

但是对于多道系统，在执行一个不使用 IO 的程序的时候可以做到 CPU 和 IO 并行工作，这样完全可以做到适当的安排下在 CPU 运行的同时让 IO 也不停下，IO 设备当然利用率就高了

IV 和 I 其实是对称的

可以举一个例子来理解，对于同样的两个程序：

![image.png](https://typora-1310242472.cos.ap-nanjing.myqcloud.com/typora_img/20250703162349.png)

如果是串型的单程序系统，那么总的执行时间就是 50 ms，其中 IO 执行了 30 ms，CPU 执行了 20 ms，那么各自的利用率就是 IO：0.6 和 CPU: 0.4

但是如果是多道程序系统，由于任务 A 在 IO 的时候 CPU 可以执行任务 B

这样系统执行完毕所花的总时间一定小于 50 ms，但是 CPU 和 IO 他们各自运行所花的时间是不变的，他们还是干了那么多活，只是他们两个是可以并行干活的，即 CPU 仍然执行了 20 ms；IO 仍然执行了 30 ms；只是这些时间有重叠

显然利用率变高了
