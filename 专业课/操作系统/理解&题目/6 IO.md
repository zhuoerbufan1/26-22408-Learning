## 用户层软件部分
### 假脱机技术的最基本原理是什么？（脱机技术 -> 假脱机技术的原理？）

![image.png](https://typora-1310242472.cos.ap-nanjing.myqcloud.com/typora_img/20250926165416.png)

虚拟设备就是将一台物理设备虚拟出多台供进程独立使用的逻辑设备，这个就是 SPOOLing 实现的东西

虚拟设备主要靠 SPOOLing 技术实现，它可以让多个进程在一段时间内都去申请打印机，都去提交自己的打印任务，但是这些打印任务并没有提交给真实的打印机，而只是提交给了磁盘，然后由系统去协调调度打印任务上打印机打印，但是用户会认为他自己独占了打印机

SPOOLing 技术的主要目的就是将独占的物理设备虚拟成多个共享设备，从而提高独占设备的利用率

如果没有 SPOOLing，那么就是 A 使用打印机打印，然后 B 也想使用打印机，但是 B 阻塞，打印机打印完 A 的任务，然后空闲等待 B 提交自己的任务，然后打印 B 的任务

而有了 SPOOLing 技术，A 和 B 都会提交自己的任务到磁盘中，然后由系统调度这些任务上打印机打印，此时 A 和 B 都认为自己打印完了，可以继续执行他们后面的事情不用等待（实际上没有被打印，只不过提交磁盘了 AB 认为打印完成了）打印机统一打印系统调度的任务，不存在等待提交的情况，没有空闲，这当然就提高了打印机的利用率了

SPOOLing 技术是典型的空间换时间的技术

（1）增加了一些输入和输出的空间，将独占的设备虚拟成多个共享的设备，提高设备利用率

### SPOOLing 技术是怎么提高 IO 速度的？

进程在输入或者输出的时候可以不用一直阻塞等待低速的 IO 硬件，进程直接将数据交付到输出井，或者直接从输入井取走数据就行了，此时进程就认为自己完成了输出或者拿到了数据，然后进程就可以干别的事情了，剩下的负责输入输出井与实际 IO 设备的交互则由输入输出进程负责，主要是减少了进程阻塞等待 IO 的时间


简单来说就是不用阻塞等待 IO，而是直接交给输出井存起来，自己就可以干别的事情了
### 假脱机技术是怎么实现虚拟设备的功能的？

磁盘的输入输出井中有很多个作业输入或者输出的空间，那么对于不同的作业，它们不直接与 IO 设备打交道，而是放到磁盘的各个作业的输入输出空间中，所以它们两个就可以同时输入输出数据，因此它们都会认为是自己独占了设备，从而实现了设备的共享，以及设备的虚拟；实际上它们只是独占了磁盘中的井文件，后续由输入输出进程负责磁盘井文件与 IO 外设的交互，而这些操作对于进程来说都是透明的



（1）对于进程来说自己输入输出井中的空间是独占的，每个进程只是与这些空间打交道，于是进程就误以为自己独占了 IO 设备
（2）实际上在内部由输入输出进程负责处理这些空间的数据与 IO 的交互

## 设备独立性软件部分-缓冲区
### 引入缓冲区的目的是什么？

![image.png](https://typora-1310242472.cos.ap-nanjing.myqcloud.com/typora_img/20250926184123.png)

如果生产者的生产速度比消费者快，在没有引入缓冲区之前生产者生产完数据之后必须等待消费者消费才能继续生产；但是引入缓冲区之后生产者可以直接将数据放到缓冲区，然后生产者就可以继续生产东西，这样就解决了两者速度不匹配带来的效率底下的问题

### 缓冲区问题中的 M, T, C 分别是什么？

T 是从 IO 设备传递数据到缓冲区的时间

M 是从缓冲区移动数据到 CPU 的时间


C 是 CPU 处理数据的时间
### 单缓冲传输和处理连续两个数据的时间是多少？

![image.png](https://typora-1310242472.cos.ap-nanjing.myqcloud.com/typora_img/20250811143406.png)

缓存区每次只能执行一个动作，要么接收输入，要么传送，不能传送和输入同时进行

工作区每次只能执行一个动作，要么接收输入，要么执行，不能执行和接收输入同时进行

工作区的执行处理和 IO 设备输入到缓存是可以并行的

第一个阶段：IO 向缓存输入数据，时间为 T，这个时间不能省

第二个阶段：缓存向工作区输入数据，此时 IO 不能向缓存输入，所以必须花费 M 时间，不能省略

第三个阶段：工作区处理数据，以及 IO 向缓存区输入数据，这个可以并行，但是无论哪个先完成，都必须等待另外一个完成，比如 C 的时间大于 T，那么 IO 输入到缓存花费 T 先完成，但是工作区还在处理数据，此时 IO 无法向缓存继续输入数据，缓存也无法输入数据到工作区；同理如果 T > C 也是这样，工作区的数据处理完了之后必须等待 IO 输入数据到缓存区才行，因此这个阶段的时间必须是 Max (C, T），第三阶段结束，缓存区有了第二个数据

第四个阶段：缓存区输入数据到工作区，M 时间

第五个阶段：工作区处理，C 时间

所以连续处理两个数据的时间就是 T + M + Mac (C, T) + M + C

### 单缓冲传输和处理连续 n 个数据的时间是什么？

![image.png](https://typora-1310242472.cos.ap-nanjing.myqcloud.com/typora_img/20250811143406.png)

第一个阶段：IO 向缓存输入数据，时间为 T，这个时间不能省

第二个阶段：缓存向工作区输入数据，此时 IO 不能向缓存输入，所以必须花费 M 时间，不能省略

第三个阶段：工作区处理数据，以及 IO 向缓存区输入数据，这个可以并行，但是无论哪个先完成，都必须等待另外一个完成，比如 C 的时间大于 T，那么 IO 输入到缓存花费 T 先完成，但是工作区还在处理数据，此时 IO 无法向缓存继续输入数据，缓存也无法输入数据到工作区；同理如果 T > C 也是这样，这个阶段工作区的数据处理完了之后必须等待 IO 输入数据到缓存区才行，因此这个阶段的时间必须是 Max (C, T），第三阶段结束，缓存区有了第二个数据

由于接下来 IO 设备仍然想要继续传数据，所以此时的情况实际是回到了第一个阶段的结束，下面的过程就是第二个阶段和第三个阶段周期循环

再经过 M + Max (C, T)，第二个数据处理完毕，并且第三个数据进入缓存区

再经过 M + Max (C, T)，第三个数据处理完毕，并且第四个数据进入缓存区

如果画图的话如下所示（下图是 T > C）：

![image.png](https://typora-1310242472.cos.ap-nanjing.myqcloud.com/typora_img/20250811145848.png)

所以第 n 个数据传输到缓冲区的时间是 $T + (n - 1) * (M + Max (C, T))$，然后再由缓冲区传送到工作区，然后执行，再需要 M + C 的时间，按照上图的 T > C，所以 n 个数据的传输执行时间就是：

$$
T + (n - 1) (M + T) + M +C
$$

第一个阶段：IO 向某个缓冲区传数据，假设向缓冲区 1 传数据，这个时间必须得花费，所以是 T

第二个阶段：缓冲区 1 向工作区传数据以及工作区处理数据，还有 IO 设备向缓冲区 2 传数据，这两个可以并行，并且不管谁先结束，都得等到另外的一方结束；比如缓冲区 1 向工作区传数据以及工作区处理数据先结束，即 C + M < T，那么还是得等到 IO 向缓冲区 2 传送完数据才能进行下一步操作；所以这个阶段的时间就是 T；当 M + C > T 的时候，此时由于只传两个数据，第二个数据传送到缓冲区 2 之后 M + C 仍在执行，所以得等到工作区执行完毕，缓冲区 2 才能继续向工作区传送数据，所以这个阶段的时间就是 M + C，这个阶段结束缓冲区 2 有了一块数据

第三个阶段：缓冲区 2 向工作区传数据，M 时间

第四个阶段：工作区处理数据，C 时间

所以总的时间就是 T + Max (M + C, T) + M + C

==假设 M +C < T==

第一个阶段：IO 向某个缓冲区传数据，假设向缓冲区 1 传数据，这个时间必须得花费，所以是 T

第二个阶段：缓冲区 1 向工作区传数据以及工作区处理数据，还有 IO 设备向缓冲区 2 传数据，这两个可以并行，缓冲区 1 向工作区传数据以及工作区处理数据先结束，即 C + M < T，那么还是得等到 IO 向缓冲区 2 传送完数据才能进行下一步操作；所以这个阶段的时间就是 T


那么当第二阶段结束的时候，缓冲区 2 满了，缓冲区 1 空了，又回到了第一阶段结束的情况，然后剩下的时间就是不停循环第二阶段了：

![image.png](https://typora-1310242472.cos.ap-nanjing.myqcloud.com/typora_img/20250811153507.png)

因此 n 个数据传输并处理完毕是，首先 IO 花费 T 传送第一个数据到第一个缓冲区，然后经过 (n - 1) T 个循环保证前 n - 1 数据处理完毕，并且最后一个数据被送到一个缓冲区，接着最后一个数据只用缓冲区传送到工作区，然后执行的时间 M + C 即可：

T + (n - 1) T + M + C

==假设 M + C > T==

这种情况下上文的循环思想就不行了，此时必须画图来进行分析

第一个阶段：IO 向某个缓冲区传数据，假设向缓冲区 1 传数据，这个时间必须得花费，所以是 T

假设从此时开始画图，缓冲区 1 向工作区传输数据以及工作区执行可以并行

![image.png](https://typora-1310242472.cos.ap-nanjing.myqcloud.com/typora_img/20250811154920.png)

上图中第一个 T 结束表示 IO 设备向缓冲区 2 传输数据结束，由于此时缓冲区 1 是空的，所以 IO 可以紧接着继续传输数据到缓冲区 1 中

上图中第一个 C 结束表示工作区处理完毕第一个数据，此时由于缓冲区 2 是满的所以缓冲区 2 可以向工作区传输第二个数据

**不过不管怎样，上图的一个 M + C 表示执行完毕一个数据**

所以第一阶段结束之后，每经过 M + C 表示处理完毕一个数据， n 个数据就是：

T + (n - 1) (M + C) + M + C

==综上==

传输 n 个数据并执行的时间就是：

$$
T + (n - 1)  *max(T, M + C) + M + C
$$

# 理解






### 用户缓冲区与内核缓冲区

对于中断方式的 IO 控制，中断服务程序会先将数据读入到 CPU 的通用寄存器，然后再将数据放入到内核缓冲区，此时中断服务例程结束

当用户进程需要数据的时候再从内核缓冲区中取数据，此时需要 CPU 变态才能访问内核中的数据

为了避免频繁的 CPU 变态，引入了用户缓冲区，当内核缓冲区的数据写入到用户缓冲区的时候会提前写入一些用户当前不需要但是可能后续需要的数据，这样当用户后面再需要数据的时候就不用 CPU 变态再去访问内核缓冲区了，只用访问用户缓冲区即可


### 设备独立性的概念（设备无关性）

是指 OS 可以不依赖于硬件设备的具体实现细节的情况下，给用户提供一个统一的标准化访问设备接口

只要有了设备独立性，那么这个用户就可以通过这个同样类型的接口来访问不同类型的硬件设备，用户或者进程不需要关心设备的实现细节，用户通过 IO 系统（OS）提供的抽象，自己访问设备的时候与具体的设备无关，用同一的访问方法进行访问，然后 IO 系统根据用户的访问，再进行转换来访问不同的设备


### 设备独立性软件的概念以及与设备驱动程序的一些区别

设备独立性软件有两个重要的功能：

（1）管理外设，实现设备的分配与回收

（2）缓冲区的管理


设备独立性软件与实际硬件外设之间还隔了一层设备驱动程序，设备驱动程序才是根据外设不同的结构来发送具体命令的程序

### 设备驱动程序

设备驱动程序是 OS 中管理外设的一些代码，它负责配置硬件设备，告诉外设执行一些操作，负责处理与设备相关的中断处理过程等，所有与具体的硬件操作有关的，比如磁盘的调度，他都是设备驱动程序完成的

设备驱动程序会注册处理外设所需的中断处理程序，这些处理程序的入口地址会被 OS 编到中断向量表中，中断处理程序由设备驱动程序注册和调用，可以认为外设的中断处理程序就是由设备驱动程序提供的

驱动程序大部分是 C 语言编写的，设备驱动程序会在上层与 OS 内核有接口，不同的操作系统接口是不一样的，设备驱动程序不能混用在各种操作系统中

### 设备驱动程序与 IO 控制方式的阻塞情况

如果是程序查询方式，CPU 会反复执行查询查询设备控制器的指令，此时当前进程不会被阻塞

如果是中断方式，外设在准备数据的过程中，当前进程就会被阻塞转去执行别的任务，然后数据准备好了之后由中断处理程序传输数据到存储器中

### 缓冲池概念以及引入缓冲池的原因

缓冲池其实是由很多的内存缓冲块构成的，这些缓冲块是由操作系统来分配和管理的，缓冲池与通常意义的缓冲区的区别在于，缓冲区一般都是一个进程独有的，为单独一个进程开辟的一块区域，而缓冲池则是由 OS 软件来分配给各个进程缓冲块的一片共享的区域

对于单缓冲或者双缓冲或者循环缓冲，他们其实只针对单个特定的任务而创建的缓冲；如果这个系统是一个多任务系统，那么每个任务都会分配一个缓冲，这样会导致缓冲区过多；于是这样就引入了缓冲池，OS 划分了一片共享的内存区域，每个任务按序索取里面的内存块作为缓冲即可

缓冲区是一定放在内存的，只有放在内存才能让 CPU 取数据加速，如果缓冲区放在外存，那完全毫无意义

### 双缓冲区在双向传送设备中的意义

双缓冲区，一个缓冲区用于接收数据，一个缓冲区用于发送数据

比如网卡设备，他的缓冲区就设置在内存，一个发送缓冲区和一个接收缓冲区

当 CPU 处理好了数据之后就把数据放到发送缓冲区即可，CPU 就可以转头执行别的操作，等到网卡有空取走数据即可；同理当网卡受到数据时先放到接收缓冲区中，然后 CPU 有空取走即可

这样 CPU 与网卡之间不仅仅可以并行工作，实现数据的并行传输，同时 CPU 取数据从内存中取，也大大减少了 IO 等待时间，

### 设备的一些分配方式（静态分配和动态分配）

独享分配：只能将设备分配给一个进程让其独占，等到进程完成自己的操作才释放设备

共享分配：比如磁盘的分配，可以有多个进程在同一段时间并发访问，进程并不独占设备，在一段时间内通过分时来进行并发访问设备

虚拟分配：将一台物理设备变成几个逻辑设备，然后分配给进程

静态分配：也就是固定的把某个设备分配给某个进程，在进程完成它的任务之前都不会释放这个设备或者分配给其他的进程，因此对于独占设备往往采用的就是静态分配（其实就是独享分配）

动态分配：对于磁盘来说，进程 A 的磁道请求可能是 100 200 500，进程 B 的磁道请求可能是 300 150 160；对于磁盘的调度算法来说，它可能先响应 100 的磁道请求，然后再响应 150 的磁道请求，这样磁盘其实是在两个进程请求之间轮转，这个就是动态分配；而静态分配则是先将 A 进程的请求 100 200 500 处理完再去处理 B 的请求；对于磁盘这样的共享设备往往就采用动态分配方式
### 设备分配的各个表数据结构以及过程

首先是访问SDT 表，这个表会记录所有外设的信息，是设备管理的入口，根据进程请求设备的名称去找这个表

在 SDT 表中，找到设备对应的 DCT 表，这个是设备自己的控制表，会记录设备自己的状态信息，此时会检查这个设备是否是忙的，根据情况是让进程排队还是分配给进程

如果进程成功分配到了这个设备，此时就会顺着 DCT 上的指针，找到 COCT 表，下面就是找到设备对应的控制器，控制器通过 COCT 表来对设备进行控制和管理，从 COCT 中的状态字段来判断这个控制器是否忙碌，从而决定是否分配给进程

如果进程分配到了控制器，下面就是找 CHCT，即通道控制表，来找这个通道，利用通道技术来进行 IO 操作（设备分配默认使用通道技术）

### 虚拟设备与SPOOLing 技术

虚拟设备就是将一台物理设备虚拟出多台供进程独立使用的逻辑设备，这个就是 SPOOLing 实现的东西

虚拟设备主要靠 SPOOLing 技术实现，它可以让多个进程在一段时间内都去申请打印机，都去提交自己的打印任务，但是这些打印任务并没有提交给真实的打印机，而只是提交给了磁盘，然后由系统去协调调度打印任务上打印机打印，但是用户会认为他自己独占了打印机

SPOOLing 技术的主要目的就是将独占的物理设备虚拟成多个共享设备，从而提高独占设备的利用率

如果没有 SPOOLing，那么就是 A 使用打印机打印，然后 B 也想使用打印机，但是 B 阻塞，打印机打印完 A 的任务，然后空闲等待 B 提交自己的任务，然后打印 B 的任务

而有了 SPOOLing 技术，A 和 B 都会提交自己的任务到磁盘中，然后由系统调度这些任务上打印机打印，此时 A 和 B 都认为自己打印完了，可以继续执行他们后面的事情不用等待（实际上没有被打印，只不过提交磁盘了 AB 认为打印完成了）打印机统一打印系统调度的任务，不存在等待提交的情况，没有空闲，这当然就提高了打印机的利用率了

SPOOLing 技术是典型的空间换时间的技术

磁盘扇区的三元组中柱面其实也就是磁道号，柱面是每个磁盘相同的磁道形成的一个圆柱面

磁盘读取数据的时候，首先磁头会向着磁盘的圆心或者远离圆心移动定位到相应的磁道，其实也就是定位到期望的柱面，这个时间称为寻道时间

### 计算机中的编址规律

这里以一个含有 8 个物理块，每个物理块中有 8 个存储单元的内存为例

他的地址格式是 AAA BBB

AAA 表示物理块号，BBB 表示块内的存储单元号

最开始的存储单元号一定是 000 000，它在第 0 个物理块中，当其不断递增，变成了 000 111，这是第 0 个物理块的最后一个存储单元号，然后再+1，地址变成了 001 000，变成了第 1 个物理块的第 0 个存储单元

这样的情况下，可以发现地址递增的过程中，前 3 位刚好与物理块号完全一样，后 3 位刚好与块内存储单元编号一样，也可以说是块内偏移

这个就是规律，在指明某个存储单元在整个内存的地址的时候完全可以用物理块号和块内偏移拼接在一起

对于磁盘也是这样，假设磁盘有 8 个柱面，每个柱面有 8 个磁道，即对应 8 个盘面，一个盘面有 8 个磁道，每个磁道有 8 个扇区

磁盘地址格式是【柱面号，盘面号，扇区号】，或者【磁道号，盘面号，扇区号】

那么总体第 9 个扇区的地址是 000 001 001，它就在第 0 号磁道，第 1 个盘面，第 1 个扇区上了

### 提前读和延迟写

这两个都是内存缓冲区的特性

提前读是指在读磁盘的时候提前将磁盘附近的数据读入内存的缓冲区，这样进程在下次访问的时候可以不用访问磁盘，直接访问缓冲区就可以了

延迟写是指进程需要写入磁盘的数据延迟写入磁盘，而是先写入到缓冲区中；这样做有两个好处，第一个是进程下次访问的数据可能是这些需要写入磁盘的数据，那么访问这些延迟写入的数据的时候就不用进行 IO 操作了；另外一个好处是延迟写入的数据可以攒在一起统一写入磁盘，这样进一步减少了 IO 次数

提前读和延迟写都可以减少访问文件的时间以及 IO 次数

### 6 整个 DMA 的传输过程
