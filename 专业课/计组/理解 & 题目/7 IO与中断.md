## 理解
### 数据传输控制方式与总线定时方式的区别

数据传输控制方式是 CPU 如何与外设协调完成一次数据传输；主要是 CPU 如何知道外设准备好了数据待传送交给 CPU，或者 CPU 如何知道外设准备好了接收数据

比如一个典型的数据传输控制方式是程序查询方式，CPU 会反复查询 IO 接口的状态寄存器来获取 IO 的状态，当 IO 准备好了数据之后 CPU 会取读数据，这就是数据传输控制方式中的程序查询方式的大致思想

而总线定时方式是更底层的物理电气信号，它规定了你程序查询方式的每一次 CPU 读或者写操作是如何发生的，比如同步定时方式，CPU 的每次读操作都是在每个时钟周期做规定好了的操作，CPU 读 IO 接口的状态寄存器的时候第一个时钟周期获得总线控制，第二个时钟周期送地址，第三个时钟周期送数据等等

### 程序查询方式的理解和一个例题

程序查询方式的 IO 接口基本结构如下所示：

![image.png](https://typora-1310242472.cos.ap-nanjing.myqcloud.com/typora_img/20250629144522.png)

这里以 CPU 从外设读一个数据为例来说明数据传送的过程

（1）CPU 执行 IO 指令向状态寄存器中写入启动外设控制命令，比如 OUT 指令，具体来说，CPU 通过地址线指明此时的控制命令要输出的 IO 端口地址，然后通过控制线指明 CPU 执行写操作，接着这个启动命令通过数据线写入到状态寄存器中；

（2）IO 接口中的控制逻辑将状态控制寄存器（IO 端口）中的启动命令发送给外设，外设开始启动，准备数据；接着控制逻辑将状态寄存器设置为外设忙的信号，这个状态信息会覆盖控 IO 端口原来的控制信息，不过这个控制信息已经发出去了，不用再保存

之后 CPU 通过不断的执行 IN 指令来读取状态寄存器端口中的状态，来看看 IO 是否准备好了数据

（3）外设准备好一个数据，通过数据线写入到 IO 接口中的数据缓存寄存器端口中

（4）外设准备好了数据之后通过状态线反馈给 IO 控制逻辑，IO 控制逻辑将状态寄存器设置为 ready

（5）CPU 通过读取状态端口寄存器发现数据准备完毕，于是再通过 IN 指令从数据缓存寄存器中取走数据

以上就是 CPU 通过程序查询方式从外设取走一个数据的具体过程

在 CPU 查询 IO 接口中的状态端口的时候有两种方式，一种是 CPU 完全停下现在自己正在做的事情，一直反复的查询这个端口，这个方式称为**独占查询**，CPU 将所有的时间都用来 IO 操作；

另一种方式是**定时查询**，即 CPU 会隔一段时间查询一次 IO 端口，在这些时间间隔 CPU 会去干别的事情

### 中断控制器的基本结构

中断控制器本身也是一个 IO 设备，CPU 可以访问其 IO 接口配置其功能，比如设置其中断屏蔽字寄存器 IMR，它也被称为可编程中断控制器，其基本结构如下所示：

![image.png](https://typora-1310242472.cos.ap-nanjing.myqcloud.com/typora_img/20250629184225.png)

下面依次说明这个中断控制器的各个结构

==IRR，中断请求寄存器==

它用于暂存每个外部设备的中断请求，IRR 的每一位对应一个外部设备，其值为 1 的时候表示外部设备发出了中断请求，IRR 中的内容又称为中断字，中断处理的时候就通过中断字来确定中断源，从而转到对应的中断处理程序

==IMR，中断屏蔽字寄存器==

IMR 的每一位对应一个设备中断源，中断源为 1 的时候表示屏蔽这个中断源发送的中断请求，为 0 的时候表示允许发送

对于不同的外部设备，他们由 CPU 设置不同的中断屏蔽字，**当执行他们的中断服务程序的时候会将中断屏蔽字写入到 IMR 中，此时所有其他设备发送的中断请求都会先与自己的中断屏蔽字的每一位进行一个与操作，没有被屏蔽的中断请求再送到中断响应电路中进行请求优先级排序**

中断屏蔽字可以动态的改变中断优先级；但是中断屏蔽字只有在 CPU 运行服务程序的时候才能设置，当 CPU 执行主程序的时候仍然采用的是中断响应的优先级

==优先级排队电路==

这个优先级排队电路的输入是多个通过了屏蔽的中断请求信号，输出是优先级最高的中断编号和中断请求信号

中断编号通过数据总线 DBUS 反馈给 CPU，而中断请求号 INTR 则通过控制总线 CBUS 传输给 CPU，同时通过控制总线接收来自 CPU 的中断应答信号 INTA

==ISR，中断服务寄存器==

它用来存放多重中断中所有得到中断响应但是中断服务程序还没有结束的中断请求

一般来说，在多重中断中，低响应优先级的中断可以设置屏蔽字来屏蔽掉高响应优先级的中断，从而避免自己被打断嵌套；但是如果此时是一个高响应优先级的中断服务在执行，低优先级哪怕没有被屏蔽，它也不能去打断高优先级的中断服务；即普通的屏蔽模式下，只能是高响应优先级去打断嵌套低响应优先级中断

一个新的中断请求通过了屏蔽电路，它会在排队电路中不仅仅与别的通过了屏蔽的请求排队，还要与当前的 ISR 中的中断请求排队，从而决定这个中断请求是否被送给 CPU，只有一个通过了屏蔽，并且响应优先级最高，并且比当前 ISR 中的中断请求的优先级还高的中断请求才会被送给 CPU，才会打断当前的服务程序，进行中断嵌套

==中断使能位和标志位 IF/IE==

这个一般在 CPU 内部，会放在 PSW 寄存器中，它如果为 1 表示开中断，为 0 表示关中断

关中断表示此时 CPU 不会响应任何中断请求，CPU 可以通过开/关中断指令来设置它

### 中断识别与中断号

以上述中断控制器为例，中断识别是 CPU 识别中断源，获得中断源对应的中断号的过程，CPU 需要拿着这个中断源的中断号去找这个中断的服务程序地址从而执行中断服务

中断号是计算机统一分配的，对于可屏蔽的中断源，其中断号由中断控制器提供，通过数据总线传给 CPU 的，对于不可屏蔽的中断源以及异常的中断号是集成在 CPU 中预先设置好的


### 中断向量，中断向量表，向量地址，中断指针 + CPU 获得中断服务程序入口地址的过程

中断向量是中断服务程序的入口地址以及程序状态字 PSW

中断向量表是一堆中断服务程序的入口地址和 PSW 的数组

![image.png](https://typora-1310242472.cos.ap-nanjing.myqcloud.com/typora_img/20250629193326.png)

向量地址是中断向量表的地址，也称为中断指针

CPU 拿到中断号之后通过中断号计算该中断源对应的向量表的向量地址，根据向量地址访问向量表，从中读出该中断源的入口地址和程序状态字 PSW，并将两者载入到 PC 和状态寄存器中，于是 CPU 就可以跳转到中断服务程序执行了
### 完整的单级中断过程总结


**（1）中断请求与中断判优**

IO 设备设置中断控制器中的中断请求寄存器 IRR，通过了屏蔽字（此时 CPU 运行的是主程序，没有屏蔽情况）和中断判优电路之后，中断控制器将中断请求 INTR 和中断号分别通过 CBUS 和 DBUS 送给 CPU

 **（2）中断响应**

在中断响应中 CPU 主要执行三个操作，这三个操作是由硬件自动执行的，就好像有默认的指令一样，所以称为隐指令：

 **i 关中断**

设置 IF = 0 关中断，这一步是 CPU 为例避免在后面保存信息的时候被别的中断过来打断导致信息丢失中断除了完了无法返回

 **ii 保护程序断点**

将当前程序计数器 PC 和当前程序状态字 PSW 入栈保存，这是为了能够在中断执行完毕之后可以返回；如果是外部中断，保存的是当前执行程序指令的下一条地址；如果是内部异常，中断就是由当前指令引起的，所以保存的就是当前指令的地址，中断处理完毕之后要重新执行当前指令

 **iii 中断识别**

获得当前中断源的中断号，然后根据中断号去查找中断向量表，在中断向量表中得到当前中断源对应的中断服务程序地址，然后跳转到中断服务程序处理中断


**（3）保护现场**

这一步也可以称为中断服务的预处理

由于中断服务程序可能会修改寄存器的值，所以这一步需要将源主体程序中可能被修改的寄存器的值压入到栈中保存


**（4）执行中断服务**

进行传数据等操作

**（5）恢复现场**

这一步与保护现场是逆操作，将保存的各个寄存器的值出栈恢复


**（6）开中断**

此时 CPU 设置 IF 为 1，允许 CPU 响应新的中断请求

**（7）中断返回**

保存的主程序的 PC 和状态字 PSW 出栈，返回到主程序继续执行了

### 完整的多级中断过程总结

**（1）中断请求和中断判优**

当当前中断源通过了中断屏蔽字，并且优先级最高，此时中断控制器将其中断号和中断请求 INTR 发送给 CPU，如果 CPU 内部 IF  = 1 处于开中断，则接着 CPU 就会响应这个中断

**（2）中断响应**

与单级中断完全一样

**i 关中断**

**ii 保存端点**

**iii 中断识别**

**（3）保护现场**

由于是多级中断，此时中断服务程序还会写入自己的中断屏蔽字到中断屏蔽寄存器中，所以这里还需要保存上一个中断服务程序的中断屏蔽寄存器的值；在保护现场的时候同时保护通用寄存器和中断屏蔽寄存器的值

**（4）开中断**

当多重中断中某个中断请求被响应跳转到自己的中断服务程序，然后保护完了上一个中断源的中断服务程序的端点和现场之后就可以直接开中断了

此时意味着这个中断可以被另一个中断进行嵌套了

**（5）执行中断服务**

在执行中断服务中，当前中断服务程序可以被另外的中断请求嵌套

**（6）关中断**

当前终端执行完自己的中断服务之后要回到上一个中断服务程序，这里关中断是为了保证返回操作的完整性

**（7）恢复现场**

此时要连着上一个中断的中断屏蔽字一起恢复

**（8）CPU 发送 EOI**

CPU 发送当前中断结束命令 EOI 给中断控制器，中断控制器清除 ISR 中当前中断的中断源，表示当前中断执行完毕，这里必须要清楚 ISR 中的这个中断源，因为 ISR 中的中断源也会参与中断响应优先级电路的排序，当前执行完毕的中断源是最高优先级的中断源，它在 ISR 中不被清除后续优先级比它低的中断请求再次到来的时候将永远不会被 CPU 响应

**（9）开中断，中断返回**

这里通信总线是连接计算机系统之间的总线，一个具体的例子是手机通过数据线连接到 USB 接口上，USB 接口就是 IO 接口，其通过数据线这样一个通信总线连接另外一个计算机设备：手机
