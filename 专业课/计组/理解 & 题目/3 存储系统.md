### DRAM 的刷新间隔是什么？

DRAM 存储器能维持的信息的最长时间称为最大刷新间隔，一般为 2 ms, 8 ms, 64 ms 等，最大刷新间隔其实也就是某个存储元两次刷新时间的最大间隔，对于一堆的存储元整体来看，一个最大刷新时间间隔中一个存储体的所有存储元至少要被刷新一次，在这个刷新间隔中刷新之外的时间可以对存储体进行读写操作

### DRAM 的异步刷新是什么？

![image.png](https://typora-1310242472.cos.ap-nanjing.myqcloud.com/typora_img/20250907110106.png)

将所有行的刷新操作平均分配在一个刷新间隔中，使得在一次最大刷新间隔中，每一行都会被刷新并且只被刷新一次

这样做首先就不存在时间的浪费了，因为每行都只刷新了一次，并且由于是分散到一个刷新间隔中，也就不存在有一整块时间不能读写使用的死时间问题了

## Cache 映射方式
### Cache 与主存的直接映射方式是什么？tag 位确定方式是什么？

![image.png](https://typora-1310242472.cos.ap-nanjing.myqcloud.com/typora_img/20250907153520.png)

这种映射方式下假设 Cache 有 2^c 行的话，这里是用主存中的块号除以 2^c 取模得到这个块应该放到 Cache 中的行号

因此根据模运算规则，Cache 的行号其实就是主存块号中的后 c 位

![image.png](https://typora-1310242472.cos.ap-nanjing.myqcloud.com/typora_img/20250907153946.png)

在这种方式下，如果将主存块号的前 m - c 位移动到 Cache 的 tag 的 m - c 位中，此时这个 Cache 地址就和主存地址是完全相同的了

因此如果题目如果采用了这种映射方式，并且给出了一个主存地址，那么这个主存地址的块号的后 c 位，再加上块内地址，就是 Cache 地址了

注意这里的 tag 以及上文的有效位会出现在 Cache 的行内（存放在 Cache 行中），**由一个行的所有数据共用 tag 和有效位**，并且一整个 Cache 行只有一个 tag 位和有效位（这是因为一整个行的所有数据对应在主存中的地址的 tag 是一样的）

但是上图的 Cache 行号和块内地址组合起来只是地址，并不会存放到 Cache 行中，Cache 行中是数据，这里 Cache 行号和块内地址组合起来只是这些数据的地址

而 tag 和有效位出现在行中其实是因为还有别的作用

### Cache 行中的地址映射表是什么？（附加位）

地址映射表其实就是标记阵列，其实就是 Cache 每一行除了数据之外的标记位的总和：

![image.png](https://typora-1310242472.cos.ap-nanjing.myqcloud.com/typora_img/20250907160226.png)

每一行的这些标记位只有一份，由一行的所有数据共享（一个 Cache 行共享）

地址映射表是所有行的标记位总和，其实就是 Cache 行数 * 每一行的标记位位数 = 地址映射表的大小

### Cache 总容量的计算方式是什么？

就是上文的地址映射表大小 + Cache 的所有行的数据容量大小
### 直接映射方式下计算地址映射表大小的一个例子

![image.png](https://typora-1310242472.cos.ap-nanjing.myqcloud.com/typora_img/20250907160426.png)

Cache 的地址格式是行号 + 块内地址

主存的地址格式按照上文，在直接映射方式下就是 tag + Cache 行号 + 块内地址

所以这种方式下 tag 就是主存容量除以 Cache 容量，然后取个 2 的对数

**做这种题目最重要的就是思考怎么将主存地址解释成 Cache 地址**，这里是直接相联映射，因此就将主存的块号解释成 tag 位 + cache 行号

### Cache 与主存的全相连映射方式是什么？

![image.png](https://typora-1310242472.cos.ap-nanjing.myqcloud.com/typora_img/20250907161059.png)

这里的 tag 与上文的 tag 功能是完全一样的

仍然是 Cache 的每一行有一个 tag 位，这里的 tag 位有 m 位，主存的这个块可以随意放在 Cache 的某一行，然后将这一行的标记位设置为主存的块号
### Cache 与主存的组相联映射方式是什么？

![image.png](https://typora-1310242472.cos.ap-nanjing.myqcloud.com/typora_img/20250907161655.png)

这种方式是对 Cache 的行进行分组

内存中的块映射到 Cache 中的哪个组是直接映射方式；这个块映射到组内的哪个行则是全相联映射方式

4 路组相联映射是指 Cache 中一个组有 4 个行

这里一个组中的 Cache 行组号是一样的，但是每个 Cache 行的 tag 位并不一样，tag 位仍然是每行对应一个

比如主存块号如果是 4 位，并且 Cache 有 4 个组的话，那么 0011，1011，1111，0111 这些都会映射到第 3 个 Cache 组中（从 0 开始计数 Cache 组），然后 00，10，11，01 作为映射进去后每一行的 tag 位

这些 tag 位就用于给出了一个主存地址之后可以知道 Cache 组号，然后在这个组中通过对比主存的 tag 和 Cache 行的 tag 来确定是哪一个 Cache 行存放了这个主存的块


### 一个组相联计算 tag 位的例子


![image.png](https://typora-1310242472.cos.ap-nanjing.myqcloud.com/typora_img/20250907164450.png)

还是按组相联的映射方式下解释主存地址的格式

Cache 的组号与 Cache 中的组的个数相关

此外，这里有一个易错点就是如果主存是按字编址，那么主存地址的一个地址对应的一个存储单元的长度是 2 B（一个字长 2 B）

而 Cache 一行是 16 B 所以主存中的一块也就是 16 B，所以主存中的一块就是 8 个存储单元

因此在按字编址的情况下主存的块内地址就是 3 位，而不是这里的按字节编址的 4 位了

这种易错点主要还是注意两点：

（1）Cache 的一个行的大小与主存中的一个块的大小相等，根据这一点以及编址方式，算出主存中的一个块中的存储单元的个数
（2）主存中的一个地址对应一个存储单元，因此块内地址的位数对应存储单元的个数，根据这一点算出块内地址的位数

### Cache 中的关联度是指什么？


![image.png](https://typora-1310242472.cos.ap-nanjing.myqcloud.com/typora_img/20250908150342.png)


组相联映射的关联度是每个组中的路数

关联度越低命中率越低的原因是关联度越低主存中的某一块存放在 Cache 中的可能位置越少，当然命中率越低

### TLB 的组相联映射是什么？

在全相联映射中一个虚拟地址它与实页号的映射关系可以存放在 TLB 的任意一个表项处，所以需要 tag 位进行一一比较（其实是并行的，但是仍然将 TLB 的所有表项进行比较才能找到对应的表项）

在组相联映射中，TLB 被划分了组，每个组对应一些表项，比如 2 路组相联映射，那就是 TLB 中一个组有两个表项

那么对于一个虚拟地址，根据它的虚页号，它与物理地址的实页号的映射关系只能存放在固定的组中；然后在这个组中可以在任意的表项处存放它的映射关系

此时虚拟地址的虚页号由 tag + 组号构成，虚页号模整个 TLB 的组的个数得到这个虚拟地址的映射关系应该存在的组，即组号

在这个组中，再根据 tag 位确定到底哪个表项存放了映射关系

一个组中有组的大小个数个比较器，当拿到虚拟地址，并知道这个虚拟地址的映射关系存在哪个组之后，在这个组中通过并行比较表项的 tag 位和虚拟地址虚号中的 tag 位来确定到底是哪个表项是映射关系

![image.png](https://typora-1310242472.cos.ap-nanjing.myqcloud.com/typora_img/20250908201233.png)

### TLB的映射与 Cache 的映射有什么联系和区别？

TLB 中的基本单位是表项，Cache 中的单位是行，Cache 的行中实际存放数据，对应实际物理内存中的一个块，但是 TLB 只是一个用于索引的东西，它的表项并不存放实际的数据，而是存放虚拟地址对应数据的页在内存中的页框号


TLB 是利用虚拟地址进行映射，Cache 是利用物理地址进行映射，TLB 映射成功之后可以找到虚拟地址所对应数据的物理地址，Cache 映射成功之后，可以访问到实际的物理数据


利用虚拟地址访问 TLB 的时候，虚拟地址划分为页号 + 页内偏移，利用页号来找到 TLB 中对应的表项；利用物理地址访问 Cache 的时候，物理地址划分为块号 + 块内偏移，利用块号来找到 Cache 中对应的块

所谓的一些映射关系，在 TLB 中就是页号与 TLB 表项的对应关系；在 Cache 中就是物理块号与 Cache 每一行的对应关系，这里的映射关系的对应法则两者都是相同的

以组相联映射为例，在 TLB 中，如果划分了 8 个组，每个组三个表项，这个就是 3 路组相联映射，TLB 的页号假如是 10 bit，那么后 3 bit 就是组号，表示哪个组存放了虚拟地址对应的页和页框的关系，7 bit 就是 tag 位，找到这个组之后对比虚拟地址页号中的 7 bit 的 tag 位与这个组中 3 个表项的 tag 位，从而找到是哪一个表项存放了对应关系，然后再将表项中的页框换掉页号，得到物理地址

在 Cache 中，如果划分了 8 个组，每个组 3 个行，这个就是 3 路组相联映射，物理地址假如是 10 bit，那么后 3 bit 就是组号，表示那个组存放了这个数据所在的块，10 bit 中的 7 bit 就是 tag 位，通过对比组中三个行的 tag 与 7 bit 的 tag，找到数据所在是哪一行，然后利用物理地址的块内偏移来访问真实的数据

（以上假设 TLB 和 Cache 都命中）

### 缺页与 Cache 缺失的区别是什么？

缺页是进程的某个页对应的 TLB 命中失败，页表也命中失败，说明这个页不在主存中

此时触发缺页异常，OS 将页调入主存，更新页表项和 TLB 表项，然后重新执行访存指令

Cache 缺失是根据页表转换得到物理地址后然后去访存的过程，此时主存中一定有要访问的内容，但是可能 Cache 中没有

### 段式虚拟存储的虚拟地址格式是什么？物理地址格式是什么？以及地址转换是什么？

![image.png](https://typora-1310242472.cos.ap-nanjing.myqcloud.com/typora_img/20250909102227.png)


虚拟地址中的段号是用来找到段表中的某个用于地址转换的项的，这里的段号相当于段表中的偏移

段表基址寄存器中的段表长度需要与段号进行一个比较，来避免段号越界

然后通过段表起始地址  + 段号找到段表中对应的段表项

段表项中存放的是这个段在内存中的起始地址和段长

这里通过段内地址 + 段的起始地址得到实际的物理地址

注意这里并不是将段内地址与段的起始地址进行拼接，而是相加，在分页式的地址转换中是进行拼接，因为分页式中页表给出的是物理页框号，整个物理内存被划分成一个个页框，每个页框的大小一样，这样就可以很方便对物理地址进行划分

但是分段式物理内存没有划分段，因此物理地址没有段号这一说法，所以不能拼接，而是直接相加

### 段页式虚拟存储器的地址转换过程是什么？（也就是段页式的转换虚拟无所谓）

所谓段页式，就是对进程逻辑地址空间分段的同时段内进行分页，一个进程对应一个段表，每个段对应一个页表；同时内存也是分页的，本质上还是将进程按照页为单位离散的存放在内存中

![image.png](https://typora-1310242472.cos.ap-nanjing.myqcloud.com/typora_img/20250909103532.png)

首先，每个进程都会有一个段表，起始地址放在段表基址寄存器中

通过段表起始地址 + 段号得到段表中的一个表项，这个表项记录了这个虚拟地址数据所在段的页表的位置和大小

然后通过这个段表项去查页表，根据虚拟地址中的段内页号找到对应的这个页的页表项，通过页表项找到这个虚拟地址对应的数据的页存在在内存中的页框号

然后将页框号与虚拟地址中的页内偏移进行拼接就得到了物理地址了，这里内存也是分页的，有固定的页号和页大小，所以这里只用知道页框号即可，然后直接拼接


![image.png](https://typora-1310242472.cos.ap-nanjing.myqcloud.com/typora_img/20250909163705.png)


**在上文的所有逻辑地址结构中，段号就是在段表中的段表项偏移，页号就是页表项在页表中的偏移**

### 磁盘的基本读写单位是什么？这里以扇区为基本读写单位是什么含义？

但是这2KB的数据继续往下，实际驱动程序知道这2KB只占了一个扇区，所以它其实只会操作一个扇区进行写入，即磁盘的基本读写单位是一个扇区，哪怕写入的数据小于一个扇区

但是在逻辑上，相邻的两个扇区都是属于这2KB的文件的

以上就是逻辑磁盘块与扇区的区别的联系

所以静态磨损效果往往比动态更好













# 理解


### 低电平有效的含义

低电平有效的含义就是输入低电平的时候这个信号发挥作用，有效

比如一个存储芯片的片选信号是 $\bar{CS}$，意思就是如果片选信号的输入是一个低电平，那就说明这个片选信号有效，这个芯片被选中了

低电平有效的 $\bar{CS}$ 通常与输出低有效的译码器同步使用，输出低有效的译码器是普通译码器的输出口取反，输出为 0 的时候表示译码器输出了这个信号：

![image.png](https://typora-1310242472.cos.ap-nanjing.myqcloud.com/typora_img/20250605145112.png)

其实低电平有效本质还是高电平，只不过在高电平后面取了一个反，那么输出低电平有效就是本来输出高电平，取反后变成了低电平；输入低电平有效就是本来输入是低电平，取反后变成了高电平；本质还是高电平对元器件的作用


### 存储器的大小的写法

存储器的总容量：存储单元个数 * 存储字长（一个存储单元的二进制位数）

如果是按字节编址的话，可以简写成：存储单元个数 B，比如 8 KB，其实就是 8 K * 8 bit 的意思


不管是对单个存储芯片，还是主存储器的整体，都是采用这种写法

对于单个存储芯片，这里的存储字长指的就是三维位平面相同行列地址的二进制位组成的一串二进制存储单元

对于经过字位扩展之后的存储器，比如 4 块4 k * 8 芯片扩展成 8 k * 16 的存储器，这里的存储字长 16，就是两个 4 k * 8 芯片各自的 8 个位平面相同行列地址处的 8 个二进制组成的 16 个二进制构成的整个存储器的一个存储单元

这里可以简单将 4 k * 8 理解成一个 64 * 64 的位平面，每个行列地址交叉处有 8 个位，这 8 个位构成存储芯片的一个存储单元，两个存储芯片的 8 个位构成的 16 个位就是整个存储器的一个存储单元



### 多模块存储器的编址与字位扩展的编址的区别

多模块存储器编址是对完整存储器而言的，是将这个存储器的某些存储单元放到一个模块中，**不同的模块有独立的 MAR, MDR，读写电路**

而字位扩展则还没有形成一个存储器，字扩展，增加存储器的存储单元个数，位扩展，增加存储单元的宽度，通过字位扩展形成一个完整的存储器，此时先不考虑多模块，整个存储器用同一个 MAR, MDR，读写电路

两者编址也是有区别，以低位交叉编址为例，并且一个存储器由 4 块 4 k * 8 的 DRMA 经过字位扩展成 8 k * 16 的存储器，那么地址位数就是 13 位
![image.png](https://typora-1310242472.cos.ap-nanjing.myqcloud.com/typora_img/20250606185031.png)

那么这 13 位的地址就可以按照模来解释，分成 4 个模块，那么地址的后两位就用来分模块，前 11 位就用来选择模块内部的存储单元：
![image.png](https://typora-1310242472.cos.ap-nanjing.myqcloud.com/typora_img/20250606185225.png)
同样，13 位地址也可以按照片选和芯片内部地址来解释：
![image.png](https://typora-1310242472.cos.ap-nanjing.myqcloud.com/typora_img/20250606185448.png)



虽然整个存储器的某些存储单元是属于不同的模块，但是也可能属于同一个片选的存储芯片的内部地址

总而言之，多模块是针对已经扩展好了的整个完整的存储器而言的，在考虑分模块的时候不用在意字位扩展，这两者在进行地址划分解释的时候不会互相干扰

### 多体并行存储器类别+存取数据时间分析+低位交叉编址存储体数量分析

多体，即多个存储体，在存取数据的时候应该先选择体，然后去存取数据

所以编址就分为两种，一种是体号在地址的高位，一种是体号在地址的低位：
![image.png](https://typora-1310242472.cos.ap-nanjing.myqcloud.com/typora_img/20250604173321.png)

所以在顺序存取数据（地址连续增大）的时候，高位交叉编址就是在一个体中从上往下读取数据；低位交叉编址就是在每个体之间从左到右读取数据

==存取数据时间分析==

对于一个存储器的存取周期 T，其包括实际的存取时间 r 以及恢复时间，一般恢复时间是大于 r 的，假设 T = 4 r，即存取时间是 r，恢复时间是 3 r，这里的恢复是针对一个体而言的，在恢复时间中，整个存储体都不能进行存取数据

对于高位交叉编址的存储体，连续存取数据只在一个存储体进行，所以所以存取一次数据 r 后只能再等 3 r 时间才能存取下一个数据，其存取过程如下：
![image.png](https://typora-1310242472.cos.ap-nanjing.myqcloud.com/typora_img/20250604173958.png)
连续存取五个存储字，花费的时间就是 5 T

对于低位交叉编址的存储体，连续存储数据在存储体之间进行，所以在从第一个存储体存取完数据之后，可以不用等待第一个存储体恢复，直接在第二个存储体进行存取，对于上图四个存储体，然后连续存取 5 个存储字的情况，其可以连续轮流存取数据，每个数据只用花 r 时间就行了，最后一个数据存取完毕之后等待 3 r 时间恢复，所以时间就是 5 r + 3 r = 2 T：
![image.png](https://typora-1310242472.cos.ap-nanjing.myqcloud.com/typora_img/20250604174414.png)

那么对于低位交叉编址的存储体，只要存储体数量足够多，那么就可以保证轮流存取的时候每个存储字都可以保证 r 时间存取完毕，所以 n 个存储器就需要 nr 时间，然后等待最后一个存储字对应的存储体的恢复时间（不用考虑其他的存储体的恢复了，这个恢复时间一定是最长的，因为它刚刚被存取，所以它恢复完毕，其他的存储体也一定恢复完毕）n - r，所以连续的 n 个存储字的存取时间就是 nr + T - r，如果 n 足够的大，那么读取每个字的时间就近似是 r 了，就是存储器的存取时间

==低位交叉编址存储体数量分析==

低位交叉编址假设有 m 个存储体，在顺序存取的时候，会先将一排的存储体存取完，然后转到第一个存储体，此时必须保证第一个存储体已经恢复完毕，才能不用等待没有间隔继续存取

存取一排的时间是 mr，这个时间要大于等于存取周期 T 才行，r 是存取周期中的实际存取时间即：

$$
mr \geq T
$$

如果 T < mr，那一排的存储字存取完毕之后花了 mr 时间，然后再转到第一个存储体，其还在恢复，那就需要进行等待了，就会有时间浪费

当然 m 如果过多就会有资源浪费，最好的情况就是 mr = T

### 直接映射的 Cache 标志位的优化分析

直接映射方式的原理是，主存块号对 Cache 的块数取模，得到这个主存块应该存放在 Cache 中的位置：

![image.png](https://typora-1310242472.cos.ap-nanjing.myqcloud.com/typora_img/20250609175059.png)

假设此时

![image.png](https://typora-1310242472.cos.ap-nanjing.myqcloud.com/typora_img/20250609175150.png)


Cache 有 $2^3 = 8$ 块，主存有 $2^{28}B$，一块是 64 B，所以主存有 $2^{22}$ 块，所以主存的 28 位地址有 22 位是块地址

这 22 位的块地址对 8 取模之后就得到了这个块应该存放在 Cache 中的位置；那么由于是对 $2^3 = 8$ 取模，所以主存的块号中，只要低 3 位一样的块号，对 8 取模的结果是一样的，这样的块会存放在 Cache 中的同一个位置处：

![image.png](https://typora-1310242472.cos.ap-nanjing.myqcloud.com/typora_img/20250609175546.png)

所以存放在同一个 Cache 处的主存块的块号的低 3 位都是相同的，就是 Cache 的块号

LRU 算法的块的计数器的增加规律是：

### LRU 算法与 FIFO 与 LFU 的对比

LRU 算法的思想在于，最近使用的块可能下次仍然被使用，所以不被替换出去，替换出去的是最久没有使用的块，这样就很好的体现了时间局部性（下次访问的块可能还是当前最近使用的块，所以最近使用的块不慌换出去，换出去的是以前使用的块）

FIFO 算法替换出去的是最先放入 Cache 的块，FIFO 没有体现局部性，因为最先放入 Cache 的块可能被最近经常使用，所以效率比不上 LRU 算法

LFU 算法的思想在于，总的访问次数更多的块保留，而其他使用次数没有那么多的换出去，其缺点在于使用次数是整个时间的所有使用次数，可能 Cache 中的某个块在很久以前使用了非常多次，计数器非常大，但是最近它没有被使用，但是置换的时候它还是保留，换出去的还是总的使用次数每那么多的块，LFU 也没有很好体现局部性原理，效率比不上 LRU 算法

### CPU 从主存读一块数据到 Cache 的过程

当 CPU 在 Cache 中没有命中的时候，就需要从主存中读取一个块到 Cache 中

其基本过程有三个

![image.png](https://typora-1310242472.cos.ap-nanjing.myqcloud.com/typora_img/20250610190331.png)

上述传送一个数据，是指传送一次总线宽度的数据；这个过程是 CPU 从主存调入块到 Cache 的过程，也就是没有命中而浪费的过程

这里假定一个主存块有 4 个字，总线传送一次是 1 个字，下面有三种结构，调入一个主存块到 Cache 花费的时间也是不同的

==（1）窄型结构==

这个结构，CPU 每次是调入 1 个字到 Cache 中，所以是调入 4 次；这种结构相当于一个块 4 个字的数据放在了主存的一个模块中，CPU 每次读一个字到 Cache 中都需要重新给出地址，然后调入；

因为 4 个字在同一个模块，这个模块只能传输以及准备一个字，所以下一个字必须等到上一次总线传输完了然后CPU 给出下一个字的地址，这个模块再准备数据，然后再传送：

![image.png](https://typora-1310242472.cos.ap-nanjing.myqcloud.com/typora_img/20250610191128.png)


所以这个过程花费的时钟周期总数就是 48 个

==（2）宽型结构==

宽型结构和摘星结构其实是一样的，4 个字还是在一个模块中，只不过此时总线的位宽比宅型结构多一些，比如这里总线位宽就是 2 个字宽度；那此时主存一就可以准备 2 个字的数据；传输也可以一次传输 2 个字的数据

虽然还是得等到这个模块将上次传输的数据处理完毕才能进行下一次的准备和传输，但是每次准备和传输的数据位数更多了，所以 CPU 只用给出两次地址，总线传输两次就可以将一个块调入 Cache 了：
![image.png](https://typora-1310242472.cos.ap-nanjing.myqcloud.com/typora_img/20250610191549.png)

所以这个过程花费的时钟周期总数就是 24 个

==（3）交叉结构==

这个结构，假设是一个四体交叉的模块，四个字放在 4 个模块中，那么这 4 个模块在准备数据的时候就可以并行，并且 CPU 只用给出一次地址即可

这种情况，CPU 给出第一个字的地址之后，第一个模块开始准备，然后一个周期后第二个模块开始并行准备，第二个模块开始准备的时候再过一个周期第三个模块开始准备，接着再过一个周期第四个模块开始准备

这样当第一个模块准备完毕，传输完毕的时候第二个模块刚好准备完毕可以立即传输；第二个模块传输完毕之后第三个模块恰好准备完毕可以立即传输；第三个模块传输完毕之后第四个模块准备完毕可以传输

![image.png](https://typora-1310242472.cos.ap-nanjing.myqcloud.com/typora_img/20250610192124.png)

这个过程花费的时钟周期个数就是 15 个时钟周期

不过这个四体交叉存储结构如果块的大小大于 4 个的话继续读取数据是在第一个模块读取，此时其实没有接上流水线，因为第一个模块准备数据只能在第 12 个时钟周期位置开始准备数据准备好数据就是第 22 个时钟周期处了，但是第四个模块传输完数据是第 15 个时钟周期，所以还得再等 7 个时钟周期第一个模块才能传输数据：

![image.png](https://typora-1310242472.cos.ap-nanjing.myqcloud.com/typora_img/20250610193402.png)
并且第一个模块都得等 7 个时钟周期，更别说其他的模块了，按这种轮流启动的方式读取数据，最后一个模块读完之后一定是再读第一个模块等待的时间最少

下面来分析如果要接上流水线模块数和准备时钟周期数应该满足什么条件

假设是 n 体交叉存储结构，CPU 给出地址和传输一次数据仍然是 1 个时钟周期

一个模块准备数据假设是 k 个时钟周期

那么第 n 个模块（最后一个模块）开始准备数据的时候的是 1 + ( n - 1) * 1 个时钟周期处

那么第 n 个模块传输完成的时刻是 1 + （n - 1）* 1 + k + 1 个时钟周期处

在这个时刻第一个模块必须第二次准备完成才行，这样才能接上流水线，它没有准备好，那么一定会出现等待

第一个模块第二次准备完成是 1 + k + 1 + k 个时钟周期

所以必须有：

$$
2k + 2 \leq n + k + 1 \implies k + 1 \leq n
$$

模块数必须大于等于准备的时钟周期数 + 1 才行，此时才能接上流水线

### 24 磁盘传输速率计算的理解

![image.png](https://typora-1310242472.cos.ap-nanjing.myqcloud.com/typora_img/20250607193853.png)

一般磁盘的传输速率计算是转速乘道容量

这个做法的原理在于，转速是每秒转了多少圈磁道，并且假设转了一圈就传输一圈的数据，每秒转了多少圈就传输了多少圈的数据，其乘起来刚好就是容量除以时间

$$
\frac{圈数}{时间} * 一圈容量
$$

所以本质上其实还是容量除以时间，并且转一圈就传输一圈数据，这个才是最大的数据传输操作

这道题目磁道中间还有空隙，要保证数据传输率最大，必须就是转到哪里传到哪里，所以此时不能以一整圈为单位，而应该以一个扇区为单位进行计算，转一个扇区就传一个扇区，此时数据传输率才是最大的，如果以磁道为单位，那一个磁道中还有间隔，转的时候还存在有一些时间没有传数据的情况，那显然就不能保证转到哪里传到哪里，此时数据传输率就不是最大的

一个磁道的容量：

$$
\frac{60 * 1024 * 1024 B}{200} = 0.3 * 1024 * 1024B
$$

上述容量也就是 8 个扇区的容量

磁头划过 8 个扇区的时间是 25 - 1.25 * 8 = 15 ms

所以传输速率就是：

$$
\frac{0.3 * 1024 *1024 B}{15 *10^{-3}s} = 20.9 MB/s
$$

注意上述速率单位中的 M 表示 10^6，所以计算的时候最好全部换成 B 然后计算
