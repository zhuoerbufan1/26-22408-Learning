### 数的真值和机器数是什么？

==数的真值==

所谓数的真值，就是正负号，加上符合人类认知的习惯书面写法

比如 -4, +4，这些是真值，其二进制形式-0100, +0100，这些也是真值，是二进制的真值


==数的机器数==

机器数则是数字在计算机内部的表示，如果有正负号的话则需要进行数字化，0 表示正，1 表示负


真值与机器数不是一一对应的关系，真值可能在机器中有多种表现形式

### 移码的本质是什么？表示规则是什么？

移码的定义其实是：

**真值 A+ 偏置 = 另一个值 B，这个值 B 映射的范围就是就是移码的范围，然后用无符号数将值 B 表示出来就是原来的真值 A 对应的移码**
![image.png](https://typora-1310242472.cos.ap-nanjing.myqcloud.com/typora_img/20250526175802.png)

所以对于移码来说，移码本身的真值 B 一定是大于等于零的数，移码是这个值 B 的无符号二进制表示，也就是原来真值对应的移码表示

对于 8 位原码的真值范围是-127 ~ 127，偏置选择 127 映射的移码范围就是 0 ~ 254，将 0 ~ 254 用无符号二进制表示出来就是真值的移码

对于 8 位补码的真值范围是-128 ~ 127，偏置要选择 128，映射的范围就是 0 ~ 255，将 0 ~ 255 用无符号二进制表示出来就是对应的原真值的移码，此时移码的表示有规律可循，就是将补码的符号位取反，数值位不变就得到了移码

**移码与补码，原码都没有什么联系，移码始终是真值加上偏置后用无符号二进制表示的一串编码，移码是相对真值范围而言的，与真值是一一对应的**，没有要求移码必须与原码或者补码一一对应，移码就是一个无符号的二进制数，并且移码越大，原始真值就越大，并且由于移码是无符号二进制，可以直接通过不加符号的比较来判断真值大小，移码的作用就是将原始真值范围映射到正的范围，通过正数的比较来简化比较运算

### 8 bit 位，移码偏置选择 127 和 128 的区别是什么？

以 8 位二进制为例，移码是与真值一一对应的，根据定义，移码是在真值的基础上加上偏置得到

8 位二进制补码可以表示的真值范围是 $-2^7 \leq x < 2^7$

我们在这个真值范围中分析移码表示

如果偏置选择 128 即，2^7，那么从-128 到 127 对应的移码如下图的第二行所示，此时移码和补码进行对应，就是补码的符号位取反的结果，并且此时移码也是真值加上偏置得到的值按照无符号数表示的形式：
![image.png](https://typora-1310242472.cos.ap-nanjing.myqcloud.com/typora_img/20250531171016.png)

如果偏置选择 127，即 2^7 - 1，此时移码和补码不再满足补码直接符号取反就是移码的关系了，如上图第一行所示

这个时候，移码其实还是按照真值加上偏置然后看作无符号数的表示

只是在-128 表示成移码的时候有点问题，加上偏置之后是-1，但是计算机是一个模 2^8 的系统，所以这个-1 就等价于 255，按照无符号表示就是 1111 1111 了

并且，在 IEEE 754 中，以 8 位计算机为例，阶码就采用移码表示，并且此时采用的偏置就是 127，即 2^7 - 1，同时真值范围-128 到 127 中的最小两位-128 和 -127 两个全 1 和全 0 的移码不对应真值，所以 IEEE 中移码对应的真值范围其实就是 126 ~ 127

### ZF, CF, OF, SF 的含义，以及实现方式

#### ==标志位的含义==

ZF: 零标志位
SF: 有符号数运算结果正负标志位
OF: 有符号数运算结果溢出标志位
CF: 无符号数运算结果溢出标志位

#### ==进行运算的时候标志位的取值情况==

ZF: 有符号数或者无符号数相减为 0 的时候 ZF = 1，其他情况 ZF = 0（注意此处对有符号数也成立，因为有符号数运算结果是+0，即同样是每一位都是 0，此时 ZF = 1，无符号和有符号（补码）运算结果为 0 都只有一种情况，那就是全 0）

SF：有符号数运算结果为负的时候 SF = 1, 为正的情况 SF = 0，结果为 0 的时候 SF = 0（补码是+0，此时符号位为 0 = SF）

OF：有符号数负数加负数溢出或者正数加正数溢出的时候 OF = 1，其他为 0；表现在编码中就是双符号位异或为 1 的时候就溢出，此时 OF = 1

CF：无符号数减法结果小于 0 溢出，CF = 1；或者无符号数加法的结果大于最大值的时候溢出，CF = 1；其他情况 CF = 0

#### ==四种标志位的硬件实现方式==

ZF: 运算的结果每一位都是 0 的时候 ZF = 1

SF: 取运算结果的最高位 = SF

OF: 最高位的进位与次高位的进位进行异或

CF: 最高位的进位与加法器输入的进位 C 0（借位） 进行异或


![image.png](https://typora-1310242472.cos.ap-nanjing.myqcloud.com/typora_img/20250616172732.png)

这里的 C 0 或者右边的 Cin，会在执行减法的时候变成 1，因为执行减法的时候是减数按位取反，然后 Cin = 1 表示加 1；其他情况 Cin = 0

注意，符号扩展的一个原则就是要确保数的真值不发生改变

对于一个 1001 的补码，其真值是-7，扩展到 8 位，就是 1111 1001，根据快速补码转真值的算法，它的真值其实还是-7，所以补码就是向左扩展符号位

而原码来说只能在符号位和数值之间增加 0，这样才能保证真值不发生改变

### 根据扩展的思想快速计算补码的真值的方法

按照补码计算的原则，符号位参与运算，比如 1000 0001，就是-128 + 1 = -127，这个就是真值

但是如果遇到 1111 1111 1111 1101 这类的补码，这种符号参与运算的方法就有点难搞

这时可以转成原码计算，但是没必要

1111 1111 1111 1101 其实可以看成 1101 的符号扩展的结果，所以这两者的真值就是相等的

即 (1111 1111 1111 1101) 真 = （1101）真 = （101）真 = -4 + 1 = -3

计算非常快啊！

### 定点数包含哪些东西？

定点数主要分为无符号数和有符号数，定点数与浮点数相对，**定点数只能表示整数和小数**

有符号数用于表示整数和小数，只是约定的小数点的位置不一样，原码反码补码移码一般是有符号数的概念

有符号数又分为定点整数和定点小数，两种数的表示结构规定如下：

### 定点数的逻辑移位是指什么？


==逻辑移位==

只针对无符号数，无论左移还是右移一律补 0

左移，高位的 1 移出出错（溢出）

右移，低位的 1 移出精度丢失

### 定点数的算数移位是指什么？左移和右移的溢出情况呢？


==算数移位==

一般针对的是有符号数，在计算机中有符号数是用补码存放的，**所以一般针对的就是补码**

左移低位补零，右移补符号位，符号位也参与运算（注意与取补运算的区别，取补运算只是数值位参与运算）

左移，只要符号位发生改变就出错（溢出）
右移，低位的 1 移出的时候精度丢失

### 算数移位对数的真值改变原理是什么？

==数的大小改变==

算数移位的扩大和缩小都体现在真值的扩大和缩小

即将 $[x]_{补}$ 左移一位得到的是 $[2x]_{补}$，右移一位得到的是 $\left[ \frac{x}{2} \right]_{补}$
比如：$[x]_{补} = 11000100$，x 真值是-60，对补码左移一位得到 $10001000$，这个数刚好是真值 -120 的补码，即对 $[x]_{补}$ 左移一位得到的是 $[2x]_{补}$

当然由于精度和位数的关系，有些算数移位也不是严格的等同于乘 2 和除 2

**对于双符号补码**

与单符号位一样，右移补最高符号位，左移补零

### IEEE 规格化数是什么？

IEEE 有一个单独的符号位，所以尾数部分就没有符号位，所以尾数部分就是一个真值

IEEE 的规格化形式是：$(-1)^s *1.M *2^{E - 127}$

这里 S 是符号

1.M 中的 1 是隐藏的默认的不存放在机器中，M 是尾数部分存放在机器中，1. M 的意思是你必须将二进制变成 1. M 的形式，然后将 M 存放在机器的尾数部分中

E 是阶码，阶码按照无符号数转换成真值 - 127 是这里的 2 的指数，并且阶码 E 的范围是 1 ~ 254（8 位阶码）


==按照以上形式表示并存储在机器中的数就是规格化数，其他的是非规格化数==

注意 IEEE 是包含非规格化数的，此时 IEEE 根据其结构转换成真值的方式与上文规格化数的转换方式不同

# 理解与总结




### 补码和原码转换的符号位进位问题

补码也原码的互相转换规则是：正数相同，负数取反加一

正数不变，所以转换过程中进位只会发生在负数中

 并且只有一种情况才会涉及符号位的进位问题

即原码 $1, 0000000(-0)$ 的补码，它的补码是 $1,0000000$，这里的进位丢掉，-0 的补码作为最小的一个数-128

其他的数值位取反加一都不会将进位溢出到数值位，因为 0000000 取反后是最大的，其他的取反都不会超过 1111111，因此都不会将进位溢出到符号位

### 对计算机摸系统的理解 + 补码的作用

假设对于一个 8 位的计算机，那么对于这个计算机任何操作得到的结果都只能映射到 `00000000 ~ 11111111`，即 $0 \sim 2^8 -1$ 中，进位如果超过 8 位，那就丢弃

所以这个计算机就是一个天然的摸 $2^8$ 系统

对于一个摸 m 的系统，假如两个数 k 1, k 2 摸 m 的结果一样，那么 k 1 和 k 2 就是在这个系统中完全等价的两个数（根据数论知识）

所以对于一个数 k，k 1 是负数，那么 (k + k 1) mod m，实际上是一个减法，但是可以用一个与 k 1 等价的正数 k 2 代替 k 1，即：

$$
(k + k_{1}) || m == (k + k_{2}) || m
$$
这两个运算的结果相等，所以就可以将减法变成加法了，我们规定，将负数替换成正数的时候统一用这个负数在摸 m 下的补码来替换这个负数

这就是计算机中补码运算的基本原理


### 移码作用的理解

在物理电路中比较大小是很难区分二进制的符号位的，即不会像人类一样可以认为 1111，1111 是个负数，而 0111，1111 是个正数，所以后者比前者大，如果要加入符号位的判断话，物理电路就会很复杂

为了简化比大小的物理电路，我们试图让物理电路还是按照不考虑符号，按照一串原本的二进制来比较大小，这就引出了移码的概念

移码是一个数补码的符号位取反，其他位不变的一串二进制

数的增大，对应的移码也会相应增大：

![image.png](https://typora-1310242472.cos.ap-nanjing.myqcloud.com/typora_img/20250526151247.png)

这样物理电路在比较大小的时候可以按照移码来比较，就单纯比较原始的二进制，不用考虑符号位了

### 计算机硬件对于补码减法和无符号数减法操作的原理分析

==补码减法==

对于两个带符号数 A - B

计算机硬件中的两个操作数寄存器分别 存放的都是 $A_{补}，B_{补}$，计算出的结果也是 $[A - B]_{补}$

根据公式 $[A - B]_{补} = [A]_{补} + [-B]_{补}$

那么计算机的第一个寄存器不需要更改，直接就是 $A_{补}$，第二个寄存器，需要将里面的数值 $B_{补}$ 变换成 $[-B]_{补}$

假如 B 是一个正数，B 其实以补码存放，我们通过转换成真值再转成 $[-B]_{补}$ 来观察过程， 那么从 $B_{补}$ 到 B，不改变，从 B 到-B，符号位取反，从-B 到 $[-B]_{补}$, 数值位取反加一，所以总的变换过程就是每一位取反，然后末尾加一

假如 B 是一个负数，那么从 $B_{补}$ 到 B，数值位取反加一，从 B 到-B，符号位取反，此时-B 是正数，所以从-B 到 $[-B]_{补}$, 不进行改变，所以总的变换过程就是每一位取反，然后末尾加一

所以计算机硬件计算补码减法的时候，对减数的操作一律是全部位取反加一，然后再与被减数相加，这样就得到了 A - B 的补了

==无符号减法==

对于两个无符号数 A - B

计算机寄存器中存放的都是无符号数 A，B

根据公式，$A - B = A + (-B) = A + (-B)_{补}$

所以计算机需要对减数的寄存器中存放的 B 进行变换，变成 $(-B)_补$

对于一个 8 位的计算机系统，寄存器的位数就是 8 位，是一个模 256 的系统，结果会映射到 0 ~ 255

那么假设减数是 56，那么-56 在 256 下的补码就是 200，所以 $B + (-B)_补 = 256$，B 始终是无符号数

所以直接对 B 所有位取反加一，就得到 $(-B)_补$ 了，然后与 A 相加，就得到了 A - B 的结果

**所以无符号数的减法在计算机硬件层面的操作与有符号数补码的减法是完全一样的**

最后结果就是 `0.1001111` 了，这里是无符号小数的乘法运算过程，这个过程只针对数值位进行了操作，所以无符号整数的操作也是这样的

==溢出判断==

**手算判断**

对于 n 位的无符号数乘 n 位的无符号数，如果最后结果用 2 n 位保存，一定不会溢出（1111 乘 1111 结果是 225，但是 8 位保存结果的话最大可以保存 255）

如果最后结果用 n 位保存，则直接进行十进制验算即可，比如 1111 乘 1111 结果是 225，显然范围超出了 4 位二进制无符号数的范围（0 ~ 15）

**机器判断**

像这样 n 位乘 n 位，最后结果用 2 n 位保存，那肯定不会溢出

但是如果这里用 2 n 位保存中间结果，最后截取后面 n 位作为结果的话，如果前面前 n 位不全为 0，那就是有溢出（很显然，因为是无符号数，不存在符号位，n 位结果超了那数值就是超了）

最后的结果再加上符号位异或的结果即可

### IEEE 754 的阶码表示理解

IEEE 754 的格式如下所示：
![image.png](https://typora-1310242472.cos.ap-nanjing.myqcloud.com/typora_img/20250531173256.png)


IEEE 754 的阶码采用的一律是移码表示，对于 float 类型的数来说，阶码是 8 位

对于 8 位的阶码，即 8 位的移码，标准情况是与补码的真值一一对应的，即真值范围是 $-2^7 \leq x < 2^7$

但是 IEEE 规定偏置是 $2^{n-1} - 1$，在这里就是 127

对于这个真值范围加上这个偏置之后就是 $-1 \leq x \leq 254$

对于这个范围的数，其移码表示仍然是看作无符号数来进行表示，-1 在模 256 的系统中与 255 等价：
![image.png](https://typora-1310242472.cos.ap-nanjing.myqcloud.com/typora_img/20250531173857.png)

这时，IEEE 仍然规定最小的两个-128 和-127 对应的移码不表示真值，而作其他的特殊用途

所以在 IEEE 754 中 8 位移码对应的真值范围就是 $-126 \leq x \leq 127$

总结：
（1）IEEE 754 中阶码的偏置是 127，但是转化成移码是跟偏置为 128 转化成移码的思想类似，仍然是算出原来真值加上偏置之后对应的范围，然后对这个范围的数按照无符号数进行表示就得到了移码，只不过负数在模 256 的系统中进行等价

（2）IEEE 754 规定移码为全 1 和全 0 的两个不对应真值，所以 IEEE 754 的偏置为 127 对应的移码真值范围会比标准的少最小的两个数

（3）IEEE 中阶码转化成真值是倒过来的过程，将阶码按照无符号数解释成一个数值，然后这个数值减去 127 就是真值了（8 位阶码）

### 32 位机器，int 和 float 互相转化的理解

32 位机器中 int 是 32 位，能表示的范围就是 $-2^{31} \sim 2^{31} -1$，其中数值位是 31 位

32 位机器中 float 是 32 位，数符 1 位，阶码 8 位，尾数 23 位（实际表示 24 位）

从 int 转化成 float，float 的 24 位尾数不能全部表示 int 的 31 位的数值，所以会有精度的损失，但是由于 float 的阶码真值范围是-126 ~ 127，所以虽然尾数不能完全表示 int 损失精度，但是可以通过阶码达到与 int 一样的数量级，float 表示的数的范围是可以包围 int 的，所以不会溢出

反过来，从 float 转化成 int，由于 float 的范围在 int 之外，所以会有溢出可能；同时由于 float 是可以表示一个纯小数的，比如 0.11011....，而这个纯小数转化成 int 是直接下取整的，截断小数点后面的所有的数变成 0，所以就会有精度丢失

另外，无论是 float 还是 double，他们转 int 都是真值直接截断小数部分然后变成 int 的

### 2 移码的偏置的概念

![image.png](https://typora-1310242472.cos.ap-nanjing.myqcloud.com/typora_img/20250526170501.png)

移码的定义其实是：

**真值 A+ 偏置 = 另一个值 B，这个值 B映射的范围就是就是移码的范围，然后用无符号数将值 B表示出来就是原来的真值 A 对应的移码**
![image.png](https://typora-1310242472.cos.ap-nanjing.myqcloud.com/typora_img/20250526175802.png)

所以对于移码来说，移码本身的真值 B一定是大于等于零的数，移码是这个值 B 的无符号二进制表示，也就是原来真值对应的移码表示

对于 8 位原码的真值范围是-127 ~ 127，偏置选择 127 映射的移码范围就是 0 ~ 254，将 0 ~ 254 用无符号二进制表示出来就是真值的移码

对于 8 位补码的真值范围是-128 ~ 127，偏置要选择 128，映射的范围就是 0 ~ 255，将 0 ~ 255 用无符号二进制表示出来就是对应的原真值的移码，此时移码的表示有规律可循，就是将补码的符号位取反，数值位不变就得到了移码

**移码与补码，原码都没有什么联系，移码始终是真值加上偏置后用无符号二进制表示的一串编码，移码是相对真值范围而言的，与真值是一一对应的**，没有要求移码必须与原码或者补码一一对应，移码就是一个无符号的二进制数，并且移码越大，原始真值就越大，并且由于移码是无符号二进制，可以直接通过不加符号的比较来判断真值大小，移码的作用就是将原始真值范围映射到正的范围，通过正数的比较来简化比较运算

### 14 规格化表示的原因分析

![image.png](https://typora-1310242472.cos.ap-nanjing.myqcloud.com/typora_img/20250602172206.png)

规格化，其实就是要求原码的最高数值位是 1

所以对于一般浮点数来说原码必须是 0.1 XXXXXX（正数），1.1 XXXXXX（负数） 这种形式（最高位是符号位，所以是 0 或 1 无所谓）；

对于 IEEE 来说，尾数就是原码，最高位不是符号位是数值位，而又要求规格化，所以始终是 1，所以是 1. XXXXX 这种形式，所以 1可以省略，将后面的 XXXXX 表示在机器中

对于一般浮点数的补码来说，为了保证原码的最高数值为是 1，所以负数一定是 1.0 XXXXXX 这种形式，变成原码之后最高数值位才能是 1，所以正数一定是 0.1 XXXXXX 这种形式，与原码一样，最高数值位是 1

这里为什么最高数值位一定要是 1 呢，以一般尾数的原码为例，对于一个 0.0001 XXXXXX * 2^4 与 0.1 XXXXXX * 2^1，这两个数的真值量级是一样的，都是 1. XXXXXX 的量级，但是很显然，在同样的量级下，前者的 1 之前的 0 占了位置，不能用于表示别的数，而后者将 1 提前了，那么尾数可以用于表示的数就更多，所以相同量级下精度就更高

float 可以转成 1.1111111111... 1（一共 24 个 1），第一个 1 省略，后 23 个 1 放在自己的尾数中，所以可以表示

但是 int 是 00000010（高的第 31 ~ 24 位） 111111111111... 11111 

float 转成的就是 1.01111111111... 111（0 后面 22 个 1），然后将 01111.... 111 (22 个 1) 存在自己的尾数部分，显然将原来 int 的低位一些 1 移出去了，精度发生了丢失

所以对于正的 int 来说，大小不能超过 $2^{24} - 1$ 才能被 float 无精度丢失进行表示

写成二进制形式，10 大概是 2^3，所以进行的浮点数加法大致是：

1.5678 * 2^9 + 1.5 * 2^300

那么第一步就是要进行对阶，要让 1.5678 的二进制表示右移 200 多位，但是你 double 的尾数部分才 52 位，1.5678 的二进制的有效位在这时会全部移出，然后其尾数是全零（大概 200 多个 0）与 1.5 位二进制尾数相加（1.1）（粗略理解）

加完之后进行舍入，那 1.5678 后面被移出的有效位将会被全部舍去（因为 0 太多了），所以 (d + f) 结果还是 d，(d + f) - d 结果就是 0 了
