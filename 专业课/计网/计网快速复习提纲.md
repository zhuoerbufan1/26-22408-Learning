### 调制速率会影响传输速率吗？为什么？传播速度呢？

会，因为调制就是将信号源发出的基带信号变成模拟信号或者数字信号（基带信号变成数字信号就是各种编码方式）然后放到信号上传输

那么如果你老半天才调制一点点，然后再放到信道上，那当然数据传输就慢了，而且信道也没有充分被利用

如果你调制转换基带信号很快，那当然传输速率就会相应快一些

传播速度不会影响传输速率，传播是数据在信道上的传播，传输是将数据放到信号上，传播当然不影响传输速率

### 流量控制是什么？数据链路层是怎么实现流量控制的？

流量控制是指：发送方不会以一个超过接收方接收能力的速度发送数据，一般会与可靠传输机制结合在一起，比如滑动窗口中的窗口大小就是一种限制发送方发送速度的方式，你发送方发送速度过快的话，多余的帧就会被接收方直接丢弃让发送方重发，这个就实现了对发送方发送速度的限制

### 透明传输是什么？

在计算机网络的数据链路层中，​**​透明传输​**​是指​**​确保数据链路层能够正确识别帧的边界，并对上层（网络层）交付的数据内容不加限制地进行传输的能力​**​。简单来说，就是无论上层传递下来的数据是什么比特组合（哪怕与帧的控制字符完全相同），数据链路层都能将其原封不动地传输出去，接收方也能准确恢复原始数据，就像数据链路层“看不见”数据内容一样。

就是网络层交给数据链路层的数据像是对数据链路透明的一样，数据链路层不会对其有任何的修改，数据链路只完成自己的工作，比如封装成帧，加上首部和尾部，那接下来就可以毫无差错的传递给对方

如果是简单的字符填充法进行帧定界，那数据链路层就无法做到透明传输，因为网络层交给数据链路层的数据会对数据链路层工作产生干扰和影响，数据链路层必须对这些数据进行一些修改措施，比如加上转义字符等，这就不是透明传输了

透明传输是一个强调上下层功能分离的概念

### 数据链路层提供对差错的纠正吗？为什么？

提供纠错功能，但是数据链路层没有用到这个功能，数据链路层只用到了检测错误，有了错误就直接丢弃数据帧让发送方重发，而不进行纠正错误，虽然数据链路层采用的一些检错方法的确可以检测出来错误

注意，数据链路层是有纠错的能力的

这里不用管 GBN 是否采用的是累计确认机制

这里信道利用率达到最大的含义就是要在发送一个帧之后，确认帧返回，保证在这个时间段内发送方一直不停的发送数据帧即可，既然是一直不停发送数据帧，那这些数据帧一定是在发送方的一个窗口中的，因此可以得到窗口大小满足的最小限制

此外，还得直到 GBN 协议中窗口大小与序号编号的不等式关系：

1 \leq Wt \leq 2^{n - 1}
$$

上述的 n 是给帧编序号的比特数个数，从而得到比特数的结果

### 4 GBN 协议信道利用率达到最大的情况（范围取值问题）

![image.png](https://typora-1310242472.cos.ap-nanjing.myqcloud.com/typora_img/20250816114650.png)

这道题分别取 512 B 和 128 B 按照上一题的计算方式分别计算编号的 bit 数，这两种情况计算得到的是极限情况

但是最后取值是按照 128 B 的比特数进行取值的，而不是 512 B 的长度

这是因为你发送的数据帧长度是不确定的，是 128 B 和 512 B 之间混着发送的，如果你采用了 512 B 的长度计算得到的窗口大小，即 3 bit 决定的 5 帧以上，那假如有一段时间帧的长度全是 128 B，此时要想要信道利用率达到最大，那你就必须让窗口达到 11 帧以上了，显然此时 512 B 计算得到的窗口长度和编号 bit 数就无法满足

但是如果让窗口大小是 11 帧以上，bit 数是 4，那么哪怕有一段时间的帧长大于 128 B，比如一段时间的帧长是 512 B，此时只要窗口大于 5，那就可以满足在发送一帧到接收确认帧的时间内连续发送了，而 128 是超过 11 帧的窗口，此时还有冗余，当然更满足了

所以应该采用 128 长度帧决定的最大的窗口长度

### 为什么经过了一个争用期如果发送方没有检测到碰撞，那这次发送就一定不会产生碰撞呢？

考虑以太网端到端的带个主机 A 和 B，这两个主机的距离最长，信号传播一趟的时延是 $\tau$

那么 A 向 B 发送数据，这个数据与 B 发送的数据产生碰撞的最晚时候是 A 的数据发送到 B 的家门口的时候，此时 A 从发送检测到碰撞的时间就是 $2\tau$，即一个争用期的时间

那么与 B 发送的数据产生碰撞不可能更晚了，更晚 B 就开始接收数据了，当然 B 就不可能发送数据了，所以不会产生碰撞

那么与别的主机发送的数据产生碰撞并检测到的时间也不会更晚，因为别的主机都离 A 更近，**A 的数据与别的主机产生碰撞的最晚时机都是 A 的数据发送到别的主机家门口的时候**，这样 A 与别的主机一来一回的时间一定会小于与 B 一来一回的时间，这样 A 与别的主机发送的数据产生碰撞并检测到的时间也一定会小于 $2\tau$ 不会更晚

所以 $2\tau$ 是以太网中相距最远的两个主机，其中一个主机发送数据并检测到碰撞的最晚时间，不可能有别的碰撞更晚了

那么对于以太网中的任意一台主机 A（除了端到端的主机），假如他与任意某台主机 B发送的数据产生了碰撞，那么 A 发送数据并检测到碰撞的最晚时延是数据到 B 的家门口的时候产生了碰撞，而 B 与 A 的距离一定小于以太网端到端的距离，所以这个时延一定小于 $2\tau$，即如果产生了碰撞，A 从发送到检测到碰撞信号，这个时延一定会小于 $2\tau$

那么也可以说，如果经过了 $2\tau$ 还没有检测到碰撞，那么此次发送就一定不会产生碰撞了（并且根据载波监听，A 的数据传遍了整个信道，不会再有主机发送数据了，后续也不会再有碰撞了）

我们将 $2\tau$ 作为争用期，他的含义就是，**任意一台主机他发送数据并检测到数据碰撞的时延都会小于 $2\tau$，那么一旦这台主机发送数据的时候经过了 $2\tau$ 还没有检测到碰撞，那就可以确定此次发送数据碰撞一定不会出现了**
### CSMA/CD 协议的最短帧长定义是什么？为什么规定这个最短帧长？

因为要保证 A 在发送的时候可以检测到所有的碰撞，而最晚发生碰撞并检测的时延就是 $2\tau$，所以必须要保证发送这个帧的时延大于 $2\tau$


### 以太网的最短帧长具体数据是多少？争用期的具体数据是多少？

由于共享式以太网采用了 CSMA/CD 协议，因此在发送数据帧的时候也在监听发送出去的帧是否发生了碰撞，如果发送的这个帧太短，其都全发送完了还没有接收到已经发送的帧的碰撞信号，目的主机会丢弃发送碰撞的帧，但是源主机不会重发帧，所以源主机就得确保在发送这个帧的时候能够检测到它是否与其他设备发送的帧发生了碰撞

其实发送设备只要检测最开始发送的数据有没有发生碰撞即可，因为最开始发送的数据如果没有发生碰撞，说明这个数据在总线上顺利传播给了目的设备，而由于其他设备都会监听总线，所以此时整个总线都会被发送设备独享，因此后续发送的数据也不会发生碰撞

发送设备在发送最开始数据的后边检测边发送后面的数据，只有发送的数据帧足够大，才能充分检测最开始发送的数据帧是否发生了碰撞，为了能够检测是否与以太网这任意一台其他设备发送的数据发生了碰撞，检测的时间必须大于等于 $2\tau$，因此发送的数据帧长度也有一个最小值，即最小帧长：

#### 网桥是什么东西？结构是什么？工作原理是什么？

==网桥是什么？==

网桥也是用来连接扩展两个以太网的，但是网桥比集线器的功能更多，其工作在数据链路层（当然包含物理层的功能）

网桥包含数据链路层的一些功能，比如网桥可以识别帧的结构，可以根据帧首部的 MAC 地址和网桥自身的帧转发表来转发和丢弃所受到的帧

用网桥来扩展以太网，不仅仅增加了站点数量，而且原来的两个独立的碰撞域仍然是独立的，由于网桥隔离了碰撞域，此时的整个以太网就不再是共享式以太网了，但是两个独立的网段仍然是共享式以太网

==网桥的结构==

网桥的核心是一个转发表，其记录了各个站点主机的地址和自己对应的接口，此外需要注意的是网桥在转发帧到别的局域网的时候其接口也会执行相应的控制协议，比如共享式以太网就是 CSMA/CD 协议：

==网桥的工作原理：==


比如主机 A 发送一个目的 MAC 地址是 D 的单播帧，B 和 C 的网卡识别目的 MAC 地址不是自己，因此丢弃这个帧，网桥通过查找自己的转发表，发现 D 的地址对应接口 2，因此从接口 2 将这个帧转发给另一个以太网，这个以太网中的 E 和 F 接收到这个帧，发现目的 MAC 地址不是自己因此丢弃，D 发现目的地址是自己，因此接受这个帧：

#### 透明网桥是什么？透明网桥的自学习是什么？

透明网桥指的是以太网中的各个站点是不知道自己的帧被哪个网桥转发的，即以太网中的各个网桥对于各个站点是透明的

透明网桥的自学习其实就是建立网桥的转发表的过程, 透明网桥通过自学习算法，根据以太网中各个站点的通信建立自己的转发表

==网桥自学习的过程：==

假设一个具有空白转发表的网桥，并且简化期间各个站点的 MAC 地址直接用各个站点的名字代替

首先站点 A 发送一个目的地址是 B 的数据帧，这时网桥从接口 1 接收到这个帧，因为是从站点 A 发来的，所以网桥就知道了站点 A 对应接口 1，在表中添加这个数据，但是由于目的地址 B 转发表中没有记录，所以此时网桥就盲目转发到其他的接口：

#### 网桥的生成树协议 STP 是什么？

如果两个以太网有两个网桥连接起来（为了提高可靠性），那么当一个主机发送广播帧的时候就会形成一个圈，整个网络不停转发这个广播帧（当然如果两个网桥都没有某个单播帧的目的 MAC 地址记录也会出现这种情况），网络资源被浪费：

交换机的每个端口都是独立的带宽，如果两个端口连接两个独立的设备的话，这两个设备同时通信的时候两个端口之间并不冲突，并且交换机一个端口的转发和接受通道也是独立的

最主要的是交换机的存储转发机制，交换机在内部先将数据帧存储，然后转发到对应的端口，交换机在内部解决了信道使用冲突问题

#### 共享式以太网和交换式以太网的对比？

其实就是集线器与交换机的对比：

（1）集线器接收一个单播帧的时候会转发给所有的接口，而交换机则是根据自己的转发表转发到对应的接口
（2）集线器接收一个广播帧的时候会转发给所有的接口，而交换机同样是转发给所有的接口，但是原理是不一样的，集线器只是盲目转发给所有的接口，而交换机则是识别了目的 MAC 地址之后才进行转发
（3）对于多个主机同时通信的情况，集线器则会发生碰撞，而交换机采用存储转发的方式，避免的碰撞发生：
![image.png](https://typora-1310242472.cos.ap-nanjing.myqcloud.com/typora_img/20250220112726.png)
（4）使用集线器扩展共享式以太网，即扩大了广播域，也扩大了碰撞域，但是使用交换机扩展以太网的话，则广播域扩大但是碰撞域仍然隔离

### 点对点 PPP 协议是什么，包括哪些东西

PPP 协议就是点对点数据链路层协议，PPP 协议其实是和以太网是两种对应的数据链路实现技术，PPP 负责点对点的数据链路通信，用于拨号上网，用于用户连接到 ISP，以及路由器之间的串行连接等等；而以太网则是用于多点通信的局域网实现技术，以太网包括物理层和数据链路层；当然以太网和 PPP 协议是可以杂糅在一起的，毕竟在多点通信的以太网中总还是有点对点通信的时候

点对点是目前使用最广泛的点对点数据链路层协议，其将上层交付下来的协议数据单元封装成帧，其包括网络控制协议 NCPs（Network Control Protocols，网络控制协议）用于支持不同的网络控制协议，以及一个链路控制协议 LCP 用于建立，配置以及测试数据链路的连接，PPP 向上提供的是不可靠传输服务：

![image.png](https://typora-1310242472.cos.ap-nanjing.myqcloud.com/typora_img/20250214101055.png)

NCPs 即网络控制协议族，其不是单单的一种协议，PPP 协议本身只负责建立点对点链路，但它并不关心上层使用什么网络协议（比如 IP、IPX 等）。为了让这些网络协议能够在 PPP 链路上运行，
PPP 引入了 **NCPs**。每种网络协议都有自己的 NCP，比如：IPCP（Internet Protocol Control Protocol）：用于配置 IP 协议，让自己的主机获取一个 ip 地址等等

而 LCP 协议主要负责在开始通信之前保证链路是可靠的，配置是正确的，其主要在通信开始之前配置链路，比如确定最大帧的大小，是否启用压缩，是否错误检测等等，注意这个功能是属于数据链路层的

### PPP 协议的工作流程是什么？

PPP 协议的初始都是静止状态，当用户的 PC 和服务器的 ISP 之间检测到调制信号，并建立物理层的连接之后，链路就进入到建立状态，在链路建立的情况下，LCP 协议开始协商一些链路的配置，比如最大帧长和使用的鉴别协议等等，如果协商成功，则进入链路的鉴别状态，协商失败回退到静止状态

鉴别状态主要就是进行鉴别身份的，如果鉴别成功，则进入网络状态，如果鉴别失败则进入终止状态

进入网络状态之后 PPP 链路的两端开始利用特定的 NCP 协议进行 NCP 配置，比如如果链路上层使用的是 IP 协议，那么这里的 NCP 协议就是 IPCP 协议，来对链路的每一端配置 IP 地址

NCP 协议配置成功之后就进入到链路的打开状态，双方就可以进行数据通信，当链路的一端发出终止请求或出现故障的时候就进入链路的终止状态，当载波停止的时候又进入了静止状态：

![image.png](https://typora-1310242472.cos.ap-nanjing.myqcloud.com/typora_img/20250214103932.png)


这个过程，很显然就是控制数据在物理链路上的传播的过程，尤其是 LCP 协议的工作，因此从这个工作流程也可以进一步体会到数据链路的功能

## 虚拟局域网 VALN
### 虚拟局域网 VLAN 是什么

当交换机将更多的以太网连接到一起的时候会组成一个更大的广播域，当广播域足够大而并且某个主机发送一个广播请求的时候就会出现广播风暴即这个足够大的广播域中的所有主机都会受到这个广播请求，这样就会造成 CPU 等资源的浪费，因此我们必须对广播域进行划分

一种划分方式是用路由器将广播域划分，路由器工作在网络层，可以隔离广播域，但是路由器的造价比较高，因此在这个时候 VLAN 就出现了

VLAN，即虚拟局域网，这一种将局域网中的站点划分成一个个组的技术，一个逻辑组就是一个 VLAN，一个 VALN 中的站点具有相同的的应用需求，属于同一个 VLAN 中的站点可以直接进行通信，而不同 VLAN 之间的站点不能直接通信，比如下图中的一个大的广播域划分了两个 VALN，这两个 VALN 自己内部的主机可以受到自己内部主机发送的广播帧，但是两个 VALN 之间不能受到广播帧：
![image.png](https://typora-1310242472.cos.ap-nanjing.myqcloud.com/typora_img/20250220214951.png)


网络管理员通过对交换机进行配置来建立多个逻辑上独立的 VALN，属于同一个交换机上的站点可以属于不同的 VLAN，而属于同一个 VALN 的多个站点可以连接到不同的交换机上

### 网络层是什么？网络层的功能有哪些？

网络层主要负责将分组从源主机经过多个网络到目的主机，其主要负责分组转发和路由选择两种功能，对于一个单独的局域网，则只需要实现物理层和数据链路层就可以通信了，但是对于不同异构的网络之间的通信，则必须用到路由器，即网络层的功能

网络层向上层提供了两个服务，一个是面向连接的虚电路服务，一个是无连接的数据报服务

### 网络层向上提供的是哪两种服务？


### 面向连接的虚电路服务是什么？

面向连接的虚电路是网络层提供给上层的一种服务，虚==电路其实是一种逻辑上的连接，分组沿着这条连接按照存储转发的方式通信，而不是真正实际建立了一条物理连接==，具体来说，分组只在连接建立的阶段使用目的主机的地址，之后分组的首部使用的就是这条虚拟连接的电路编号了，通信结束之后双方释放建立的虚电路，这种方式如果使用可靠传输的协议，那么网络自身就可以保证传递的数据准确无误

![image.png](https://typora-1310242472.cos.ap-nanjing.myqcloud.com/typora_img/20250222212827.png)


> 而采用电路交换的电话通信则是一条真正的物理连接，分组交换的虚电路只是与电路交换的连接类似，但是并不完全一样


### 无连接的数据报服务是什么？

无连接的数据报服务也是网络层向上提供的服务之一，这种方式的可靠数据通信与虚电路服务不同，其可靠性并不是由网络保证的，而是由用户主机保证

这种方式不需要建立网络连接，每个分组可以走不同的路径，并且每个分组必须携带目的主机完整的地址
![image.png](https://typora-1310242472.cos.ap-nanjing.myqcloud.com/typora_img/20250222213120.png)

**这种网络服务不提供可靠的传输**，保证数据的可靠依赖的是网络边缘的站点自身，那么网络内部的路由器功能就可以做得很简单，只需要负责相对简单的交付功能而不用考虑数据处理功能，这样就大大降低了路由器造价，**这种方式也是现在使用最多的服务方式**

变长划分子网号是根据可分配的主机个数来决定的，先决定主机号位数，再决定子网号位数

### 变长子网划分的一个例题

![image.png](https://typora-1310242472.cos.ap-nanjing.myqcloud.com/typora_img/20250821141703.png)

这里的子网划分保证

（1）子网从小到大进行划分，即每个子网所占的子网号位数从小到大

（2）一定保证任意子网号不是别的子网的子网号的前缀

所以对于第一个子网，让其所占 1 bit 的子网号即可

101.200.0001 (0) 000.0000 0000，第一个子网所占 1 bit 子网号，并且是 0

那么第二个子网就比如占 2 bit 子网号了，不能占 1 bit 子网号并且是 1，因为如果第二个子网占 1 bit 子网号，并且是 1，那么前两个子网的子网号就一定是剩下子网所占子网号的前缀了，所以第二个子网不能只占 1 bit 子网号并且是 1

第二个子网占 2 bit，可选择的子网号是 00 01 10 11，这里 00 和 01 不选，因为要保证第一个子网的子网号 0 不是前缀，所以按顺序的话就选 10：

101.200.0001 (10) 00.0000 0000

同理，第三个子网号就不能选 11 了，而必须占 3 bit 子网号，同上，为了保证第一和第二个子网的子网号不是第三个子网的前缀，第三个子网号选择就是 110 了


101.200.0001 (110) 0.0000 0000

同理第四个子网的子网号就应该选择 4 bit 并且是 1110 了：

101.200.0001 (1110). 0000 0000

第五个子网是最后一个子网，不用再考虑后续的前缀问题了，所以第五个子网可以选择 4 bit，并且是 1111 作为子网号：

101.200.0001 (1111). 0000 0000

因此可分配的最少主机个数就是 2^8 - 2 = 254 个了

### 子网划分树是什么？

子网划分树，根结点是最原始的没有划分子网的结点

这个树，每往左走一位，就表示用一位 0 作为子网号，每往右走一个结点，就表示用一位 1 作为子网号

比如下面的例子，原始的网络号是 24 位网络，往左走一个结点是占用 1 bit 的 0主机号作为子网号，往右走一位是占用 1 bit 的 1 作为主机号

![image.png](https://typora-1310242472.cos.ap-nanjing.myqcloud.com/typora_img/20250821150337.png)

这棵树的特点是，你两个子结点的主机号从全 0 取到全 1 可以覆盖父结点的主机号从全 0 到全 1 的所有可能 IP 取值，并且这两个子结点从全 0 取到全 1 的时候的 IP 地址是连续的，即左边结点主机号取全 1，这是左边最后一个 IP，然后加 1，就变成了右边结点主机全 0 的 IP 了；并且这两个子结点的主机号从全 0 取到全 1 的时候不会重复

相当于两个子结点的主机号从全 0 取到全 1，不重不漏的取满了原地址块的所有 IP

### 为什么要使用 IP 地址和 MAC 地址两种地址来通信呢？

这是因为 MAC 地址没有网络的划分，那么如果只用 MAC 地址，于是路由器来转发的时候就需要将海量的 MAC 地址存放到自己的路由表中，此时手工配置路由表就是不可能的，并且哪怕是自动构建路由表也需要占用海量的存储空间和资源，并且查表也是带来很大的时延

而 IP 地址由于有网络的划分，这样路由表只用存储网络号就可以了，这样路由记录就会大大减少，路由表只用记住部分网络地址，而不用记住网络中各个通信端口的 MAC 地址

简单来说 IP 地址就适用于在多个异构网络互联的时候进行大方向导航用的，而在单个局域网中将数据传给精确的主机，那就需要使用 MAC 地址了，并且在数据包传输的过程中 MAC 地址会发生变换的，这取决于每一条之间的两个结点的 MAC 地址，但是 IP 地址始终不会发生变化

一般路由器查表转发的时候是可以明确知道下一条的路由器端口的 IP 地址的，但是在数据链路层封装的时候下一条路由端口的目的 MAC 地址是无法知道的，这就需要 IP 地址解析协议 ARP 来解决这个问题

### 地址解析协议 ARP 是什么？其工作过程是什么？

地址解析协议 ARP 是根据已知 IP 地址找到同一个局域网中相应的 MAC 地址的协议，注意 ARP 协议不能跨网络使用

举一个例子来说明 ARP 协议的工作过程，如下图所示，主机 A 需要向主机 B 发送一个数据，但是主机 A 只知道主机 B 的 IP 地址，但是不知道 MAC 地址

此时主机 A 中会有一个 ARP 的缓存表，这个表中记录着这个局域网中的 IP 地址和 MAC 地址的对应关系，这里的动态指的是过了一个周期之后这条记录应该删除，静态一般是用户自己配置的，一般只有计算机重启的时候才会删除

![image.png](https://typora-1310242472.cos.ap-nanjing.myqcloud.com/typora_img/20250226095329.png)

主机会先从自己的 ARP 缓存表中查找主机 B 对应的目录，但是没有找到，这时主机 A 就会发送一个广播 ARP 报文，目的 MAC 地址是广播地址，用来询问主机 B 的 IP 地址所对应的 MAC 地址，这时主机 B 受到这个广播报文之后首先将主机 A 的 IP 地址和 MAC 地址的对应关系写到自己的 ARP 缓存表中，然后发送响应报文给主机 A：

### IPV 4 数据报首部格式是什么？各个字段的意义是什么？

数据报首部中的每一行都由 32 个比特，即四个字节组成，每一行称为一个字段或者域

数据包首部分为固定部分和可变部分两个部分组成：

![image.png](https://typora-1310242472.cos.ap-nanjing.myqcloud.com/typora_img/20250226104754.png)

IP 数据报中的某个字段或者某些字段的组合，用来表示 IPV 4 协议的相关功能

下面来解释这些字段

#### ==版本字段：==

用来表示 IP 协议的版本，通信双方使用的通信协议版本必须一致，目前广泛使用的 IP 协议版本号为 IPV 4

#### ==首部长度==：

以 4 字节为单位，用来表示 IPV 4 首部的长度，其最小取值是 0101，表示十进制的 5，然后再乘以单位 4 字节，表示 20 个字节的 IPV 4 的固定长度，最大取值是 1111，表示十进制的 15，然后乘以单位 4 字节，表示 20 个字节的固定长度和 40 个字节的可变长度

#### ==可选字段：==

一般用于排错，测量以及安全措施等等，不过很少使用

#### ==填充字段：==

用来确保 IPV 4 数据报首部的长度是 4 字节的整数倍（这是因为首部长度字段的单位是 4 字节），使用全 0 进行填充

#### ==区分服务：==

这个字段的不同取值课提供不同等级的服务，一般情况下不使用这个字段

#### ==总长度：==

这个字段的取值以字节为单位，用来表示 IPV 4 数据报的总长度（首部长度 + 数据长度）

#### ==标识，标志，片偏移：==

共同作用于 IP 数据报分片

==标识：==

长度为 16 个比特，IPv 4 数据报的各个分片分组应该具有相同的标识，IP 软件通过计数器来给数据报赋予标识，每产生一个数据报，就将计数器赋给标识，并且计数器加一

==标志：==

最低位为 MF，MF = 1 表示本分片后面还有分片，MF = 0 表示本分片后面没有分片

中间位为 DF，DF = 1 表示不允许分片，DF = 0 表示允许分片

最高位为保留位设置为 0

==片偏移：==

长度为 13 个比特，这个字段的取值单位是 8 字节，用来表示这个分片中的数据载荷位置偏移其在原 IP 数据报中数据载荷的位置处多远

### 链路层 MTU 是指什么？

### 子网划分的时候为什么不能让某个子网是另一个子网的前缀？

比如下面的一个情况，专业 1 对应的子网是专业 2 对应子网的前缀

![image.png](https://typora-1310242472.cos.ap-nanjing.myqcloud.com/typora_img/20250822152908.png)

根据最长匹配规则这个 IP 数据报会发往专业 2 对应的子网中，但是这个目的地址仍然有可能对应专业 1 子网中的某一台主机，那这样就发送错误了

这个错误出现的原因就是专业 1 和专业 2 这两个子网用了重复的 IP 地址，即专业 1 的子网号是专业 2 的子网号的前缀

而路由器中之所以会出现某个网络号是另一个网络号的前缀的情况，是因为实际上更长的网络号其实是更短的网络号中包含的子网，等于说这个路由器的两个端口其实是连到了一个网络中，其中对应网络号更长的端口连的网络是另一个端口连的网络的子网，所以你最长匹配发往的是子网显然是更精确的，并没有出现两个网络 IP 地址重复的情况，更长网络前缀中对应的主机同样在更短前缀的网络中

而我们自己进行子网划分的时候是将网络全部分割开的，所以不能有某个子网是另一个子网的前缀的情况出现，否则就会出现 IP 重复，那么根据最长匹配规则，就可能出现转发错误

### ICMP 的差错报告报文分为哪五类？

（1）==终点不可达报文==，即当路由器不能交付 IP 数据报的时候，就向源点发送终点不可达报文，比如，主机 H 1 向路由器 R 1 发送一个报文，但是路由器 R 1 无法根据目的 IP 地址匹配路由转发条目，只能将其丢弃，并向源点发送一个重点不可达的报文：

（2）==源点抑制报文==，当路由器或者主机太过拥挤的时候，就向这个 IP 数据报的源点发送一个源点抑制报文，表示让其发送数据慢一点

（3）==时间超时报文==，也就是路由器对收到的 IP 分组的 TTL 减一后发现为 0，则丢弃这个报文，并向该 IP 数据报的源点发送一个时间超时报文：

（4）==参数问题报文==，即当主机或者路由器收到了一个 IP 数据报首部出现问题的分组的时候就丢弃这个 IP 分组，并发送参数问题报文给数据分组源点

（5）==改变路由报文==，即路由器收到分组之后发送给主机一个改变路由的报文，以通知主机下次可以将数据报发送给别的路由器，通过更好的路由到达目的

## 路由选择协议

### 路由器是什么？其基本工作原理是什么？

路由器其实是一种具有多个输入输出端口的计算机，其任务就是分组转发，路由器的基本结构由路由选择部分和分组转发部分组成

路由选择部分的核心是路由选择处理机，其任务就是根据路由选择协议与其他路由器进行周期性的路由信息交换，以便构建和更新自己的路由表

分组转发部分由交换结构，一组输入端口和一组输出端口组成

信息从某个输入端口进入路由器，物理层将电信号转换成比特流之后向上交付给数据链路层，数据链路层从比特流中识别出帧，去掉帧头和帧尾向上交付给网络层处理；网络层处理数据分组，根据数据分组中的 IP 地址进行查表转发，如果没有匹配的条目，则丢弃分组；如果能够匹配，则按照匹配条目中的端口进行转发，并且网络层会修改数据分组中的一些值，比如将 TTL 减一，首部检验和等字段，然后交给数据链路层进行封装，数据链路层将数据分组封装成帧之后交给物理层，物理层将帧看作比特流，变换成电信号发送出去

如果数据链路层交付给网络层处理的是携带路由报文的路由分组，则将路由报文交付给路由选择处理机，路由选择处理机根据报文的内容更新自己的路由表，路由表一般是对网络拓扑结构变化进行计算最优化，而转发表是从路由表得到的，应该对查找过程最优化

输入缓存区用来处理新进入路由器但是还没有来得及处理的分组，输出缓冲区用来暂存已经处理完毕但是还来不及发送的分组，一般路由器的端口同时具有输入和输出的功能

### 因特网采用的路由协议的特点有哪些

（1）自适应，即因特网采用的是动态路由选择，可以很好适应网络的变化

（2）分布式，因特网中的各个路由器通过互相信息交互，共同完成路由信息获取和更新

###  RIP 的工作特点是什么？

（1）只和相邻的路由器交换信息
（2）交换的信息是自己的路由表，即本路由器到 AS 系统中各网络的最短 RIP 距离，以及到达各网络应该经过的下一条路由器
（3）大概经过 30 s 的时间就周期性交换信息，当然，如果网络拓扑发生了变化也需要交换信息，即触发更新

###  RIP 的缺点是什么？

> [!NOTE] 关于封装和层级之间逻辑通信的理解

###  OSPF 协议的具体工作过程是什么？

如果此时 R 1 发现自己的数据库缺少了某些详细信息，则它会向 R 2 发送链路状态请求分组，此时 R 2 会将 R 1 缺少的链路状态详细信息封装在链路状态更新分组中发送给 R 1，然后 R 1 添加这些详细信息到自己的数据库之后会给 R 2 发送链路状态确认分组，当然 R 2 也可以向 R 1 发送链路状态请求分组

### OSPF 协议的区域划分是什么？

### 网际层的多播过滤是什么？

由于 IP 多播地址与多播 MAC 地址的映射关系不是一一对应的，即多个 IP 多播地址可能映射到同一个 MAC 帧，因此收到多播数据报的主机需要将不是主机接收的 IP 多播数据报丢弃

比如下面有三个 IP 多播组，但是有两个多播组的多播 IP 地址映射的 MAC 多播地址是相同的，从 IP 多播角度看就是三个不同的 IP 多播组，但是从硬件 MAC 层来看的话就只有两个多播组，所以如果 IP 多播只想传递中间一组的多播主机组的话，由于 MAC 地址相同，左边也会收到 IP 数据报，所以最左边的多播组就应该在网络层进行屏蔽：

![image.png](https://typora-1310242472.cos.ap-nanjing.myqcloud.com/typora_img/20250228113250.png)

具体屏蔽来说，这些多播组的主机接收到 MAC 帧之后需要根据帧的目的 MAC 地址看是否在数据链路层接受这个多播 MAC 帧，这一步左边的两个多播主机都会在数据链路层接受这个 MAC 帧，因为这多播 MAC 帧的目的 MAC 地址与其可以接受的 MAC 帧一样

接着左边两个多播主机 MAC 层接受之后会向上交付给网络层处理，网络层再根据这个多播 IP 数据报的目的 IP 地址来决定是否接受，显然，最左侧的多播主机组会在网际层丢弃这个多播 IP 数据报：

![image.png](https://typora-1310242472.cos.ap-nanjing.myqcloud.com/typora_img/20250228113605.png)


### 网际组管理协议 IGMP 是什么？

这个协议是用来当路由器收到某个多播数据报的时候分辨自己接口上是否有这个多播组成员的协议

![image.png](https://typora-1310242472.cos.ap-nanjing.myqcloud.com/typora_img/20250301100636.png)

使用这个协议的路由器其实仅仅能分辨自己网络上的主机加入或者退出了某个多播组，但是并不知道多播组所包含的成员数量，也不知道多播组的成员都分部在哪些网络中

为了将 IP 多播数据报以最小的代价传递给互联网上的多播组，网络上的多播路由器必须协同工作，这就需要多播选择路由器

### 网际组管理协议 IGMP 的工作原理是什么？

#### ==加入多播组：==

也就是让多播路由器知道自己连接的网络中有这个多播组的存在，比如在下面一个局域网中，主机 A，B 都想要加入 226.0.9.26 这个多播组中，此时多播路由器有另外一个多播地址的记录，但是没有主机 A 和 B 的记录，此时假设主机 B 首先发送了 IGMP 成员报告报文：
![image.png](https://typora-1310242472.cos.ap-nanjing.myqcloud.com/typora_img/20250301103647.png)

这个 IGMP 报文封装在 IP 多播数据报中，同时 IP 多播数据报被封装在以太网的多播帧中，这个 IGMP 数据报的内容和 IP 目的地址和 MAC 目的地址如下所示：

![image.png](https://typora-1310242472.cos.ap-nanjing.myqcloud.com/typora_img/20250301103858.png)

这个以太网帧发送之后会天然的在链路上进行广播，（==注意每个主机自己单独的 IP 地址和 MAC 地址与多播 IP 地址和多播 MAC 地址是独立存在的，其会分辨收到的数据报是独立的还是多播的，一般是通过 IP 数据报和 MAC 帧的目的地址进行判断，并分别与自己所属的这些多播地址进行对比==）此时主机 D 收到了这个 MAC 帧，但是 MAC 地址与自己不同，在数据链路层就直接丢弃了，主机 C 也会收到这个多播 MAC 帧，由于这个 MAC 帧的目的 MAC 地址与自己的多播 MAC 地址相同，所以在数据链路层就会接受这个 MAC 帧，并将其网上交付给网际层，结果网际层发现收到的数据报的 IP 多播地址与自己所在的多播组不同，因此就会丢弃

而主机 A 则可以在网际层和数据链路层接受这个多播数据报，并交付给 IGMP 协议分析，知道这是来自同一组的主机发送的数据报之后就取消了自己所准备的 IGMP 成员报告报文，因为只要路由器知道了自己连接的局域网中有多播组成员即可，不需要知道有谁是成员

![image.png](https://typora-1310242472.cos.ap-nanjing.myqcloud.com/typora_img/20250301110141.png)

当路由器 R 1 收到这个成员报告报文之后，通过解析这个报文，知道了自己的网络中有 226.0.9.26 这个组的成员，所以直接添加到自己的多播组列表即可：

![image.png](https://typora-1310242472.cos.ap-nanjing.myqcloud.com/typora_img/20250301110254.png)


#### ==监视成员变化：==

监视成员变化主要是多播路由器主动进行的，多播路由器每隔 125 s 就向自己所连接的网络中发送一个 IGMP 成员查询报文，这个报文封装在 IP 数据报中，其内容就是 0.0.0.0 表示要查询网络中的所有的多播组，其目的 IP 地址为 224.0.0.1 这个特殊的 IP 地址在本网络中所有参与多播的路由器和主机都会接受这个 IP 数据报，其目的 MAC 地址为这个特殊的多播 IP 地址所映射的 MAC 地址，此时这个网络中的所有主机都会收到这个多播帧：

![image.png](https://typora-1310242472.cos.ap-nanjing.myqcloud.com/typora_img/20250301111021.png)

此时只有主机 D 会丢弃这个多播帧，而主机 A, B, C 都会在数据链路层和网络层接受这个多播帧，并且这三个主机的 IGMP 协议都会解析这个报文发现是查询多播成员的报文，此时三个主机都会进行响应，但是每个响应的延迟时间不一样
![image.png](https://typora-1310242472.cos.ap-nanjing.myqcloud.com/typora_img/20250301111442.png)


这样做其实是因为多播路由器不关心自己网络中某个多播组的成员具体是谁，因此只要有一个主机说自己属于某个多播组，那就对多播路由器而言足够了，不需要太多的多播组重复响应，因此主机 B 发送了成员报告报文之后主机 A 收到这个成员报告报文就会取消自己的响应，跟上文的原理类似，当路由器收到主机 B 的成员报告报文之后就会在多播组列表中更新这个多播组的计时：


![image.png](https://typora-1310242472.cos.ap-nanjing.myqcloud.com/typora_img/20250301111615.png)


假如此时主机 C 不再是多播组的成员，那主机 C 就不会响应 R 1 的查询报文，此时路由器 R 1 经过一段时间之后就会将这个多播组从自己的列表中删除：

![image.png](https://typora-1310242472.cos.ap-nanjing.myqcloud.com/typora_img/20250301111807.png)


当然，上述例子是多播路由器针对网络中的所有多播组的查询，其实多播路由器还可以针对某个特定的多播组进行查询，这个查询一般用于路由器收到了这个多播组有成员退出的时候进行查询：

![image.png](https://typora-1310242472.cos.ap-nanjing.myqcloud.com/typora_img/20250301111935.png)
