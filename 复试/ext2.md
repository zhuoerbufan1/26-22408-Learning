
# 基本介绍

这里是用一个二进制的文件来模拟一个磁盘，通过向这个二进制文件中写入数据来模拟向磁盘中写入数据，在这个文件系统中我们实现了进入文件夹`cd`，创建文件夹`mkdir`，创建文件`mkf`，删除文件夹`rmdir`，删除文件`rmf`， 读取文件内容`read`，打开文件`open`，向文件中写入内容`write`，列出当前文件夹的所有文件`ls`，更改文件权限`attrib`等命令

用来存储文件系统的详细信息，比如块个数、块大小、空闲块

```cpp

     unsigned short bg_used_dirs_count;   /*本组目录的个数*/
```

### 数据块位图

我们通过位图来查找空闲块，数据块位图`512`字节，一共`4096`位，所以数据块的总个数也是`4096`个

### `inode`位图

inode 位图大小也是 512 字节

同数据块位图一样，根据索引位图可知索引结点块的是`512*8`个，最多对应`512*8`个文件，每一个索引块，也就是索引结点，对应一个文件，一个索引结点块的大小是`64`字节

### `inode`索引结点表

**因为用户输入文件名进行比较找到对应的文件目录项的时候是将文件目录项所在的盘块一起调入内存的**，但是我们寻找对应的目录项的时候用来对比的是文件名，所以前面调入内存的盘块中的目录项中的其他描述信息是无效的，这时`unix`采用了将文件名与文件描述信息分开的方法，**使文件描述信息与文件名分开单独形成一个称为索引结点的数据结构**，这样可以减小文件目录项的大小，于是一个磁盘块所包含的目录项更多，从而减小平均调入内存的磁盘块数量。

`inode`索引结点表共有`512`个索引结点块，每个索引结点块的大小是`64`字节，一共可以对应`512*8`个文件

索引结点的结构如下：

``` // 索引结点的数据结构  
 struct inode  
 {  
     unsigned short i_mode;     /*文件类型及访问权限*/  
     unsigned short i_blocks;   /*文件的数据块个数*/  
     unsigned long i_size;      /*大小( 字节)*/  
     unsigned long i_atime;     /*访问时间*/  
     unsigned long i_ctime;     /*创建时间*/  
     unsigned long i_mtime;     /*修改时间*/  
     unsigned long i_dtime;     /*删除时间*/  
     unsigned short i_block[8]; /*指向数据块的指针*/  
     char i_pad[24];            /*填充(0xff)*/  
 };
```
### 目录项结构

文件的目录项其实就是目录文件的内容，每一个目录项对应当前目录下的一个文件，当前目录文件下的所有的文件的目录项组成一个目录文件，作为目录文件的内容写入在数据块中，所以目录文件其实也是一种文

在数据块中一个数据块大小是`512`字节，最多包含`32`个目录项，一个目录项的大小是`16`字节，目录项的结构如下所示

## 基本对应关系

当我们创建一个文件并向文件中写入东西的时候我们需要考虑以下几个地方：

1. 我们需要知道当前的目录，在当前的目录下创建一个文件
2. 创建一个文件之后需要修改当前目录以及新创建的文件的信息
3. 写入内容的时候是先写到一个缓冲区，然后再更新到磁盘中的，同理，更新信息的时候也是先写入到一个缓冲区然后再写入到磁盘存储的


定义的各种缓冲区如下：

```
//缓冲区的意思时临时写入内容的地方，当内容写入进缓冲区后再写入到文件中  
 char Buffer[512];          // 针对数据块的 缓冲区  
 char tempbuf[4097];        // 输入缓冲区  
 unsigned char bitbuf[512]; // 位图缓冲区，这个位图缓冲是通用的  
 struct group_desc super_block[1]; //   组描述符缓冲区  
 struct inode inode_area[1];       //   节点缓冲区  
 struct dir_entry dir[32];         //  目录项缓冲区
```


当数据写入到缓冲区需要写入磁盘，或者我们需要从磁盘取出数据放入缓冲区的时候，我们将对磁盘的读写模拟为对一个二进制文件的读写，以读写文件的索引结点为例：

```c
 void update_inode_entry(unsigned short i) // 写入更新第i个inode入口  
 {  
     fseek(fp, INODE_TABLE + (i - 1) * INODE_SIZE, SEEK_SET); // 重定位到inode索引表  
     fwrite(inode_area, INODE_SIZE, 1, fp);                   // 将节点缓冲区内容存储在文件中，存储在节点索引表中  
 }  
 void reload_inode_entry(unsigned short i) // 读取第i个inode入口  
 {  
     fseek(fp, INODE_TABLE + (i - 1) * INODE_SIZE, SEEK_SET); // 重定位指针到inode索引表1536处加第i个inode  
     fread(inode_area, INODE_SIZE, 1, fp);                    // 载入第i个inode入口到inode_area缓冲区中  
 }
```


### .和.. 两个特殊文件

（1）`.` 和 `..` 两个文件占据当前目录文件的第 0 个数据块的第 0 和第 1 个目录项
（2）`.` 文件的目录项中的索引结点就是当前目录文件
（3）`..` 文件的目录项中的索引结点是当前目录文件的上一级目录的索引结点（如果是根目录的话仍然是跟目录的索引结点）
（4）每个目录文件被创建的时候会进行初始化，包括初始化它的 inode 结点，并给其预分配一个数据块，这个数据块中的 32 个目录项也会被初始化，其中 `dir[0]` 会被初始化为 `.` 文件，它的索引结点号是新创建的目录文件索引结点号，其中 `dir[1]` 会被初始化为 `..` 文件的目录项，它的索引结点号会被初始化为当前目录的索引结点号，即 current_dir

这样在当前目录项通过 cd 命令进入 `.` 文件或者 `..` 文件的时候找到当前目录的目录项就可以顺利找到这两个文件的索引结点号了


### 关于根目录

（1）根目录的索引结点号是 1
（2）根目录最开始会分配第 0 号数据块，当然第 0 号数据块应该是目录项数据，会被读取到 `dir[32]` 中

## 基本函数功能
### `initialize_memory` 初始化内存

完成的功能：
（1）初始化文件打开表
（2）读入磁盘的组描述符到内存中，如果磁盘不存在（文件不存在），则初始化磁盘后再将磁盘的组描述符读入到内存

### `initialize_disk` 初始化磁盘

#### 初始化整个磁盘


（1）首先将缓冲区 buffer 全部填充为 0，buffer 是一个 char 数组，一共 512 字节
（2）然后用 buffer 反复写入整个磁盘的 4612 个数据块，这里每个数据块也是 512 字节


#### 初始化组描述符

（1）组描述符在磁盘的最开始的 512 字节中
（2）首先将其读入到 super_block【0】结构中，它用来存放读入内存的组描述符
（3）然后先初始化 super_block【0】中的所有信息
（4）再将 super_block【0】写回磁盘的最开始的 512 字节，完成了整个磁盘的组描述符的初始化


#### 初始化根目录的索引结点

（1）根目录的索引结点号是 1 号
（2）将根目录的索引结点放入索引结点缓冲 `inode_area` 中
（3）修改根目录的索引结点信息，给根目录分配第 0 个数据块
（4）将根目录的索引结点更新的磁盘

#### 初始化根目录的目录文件内容

（1）根目录初始情况用第 0 个数据块存放自己的目录文件内容
（2）第 0 个数据块可以存放 32 个目录项，根目录初始的时候会将第 0 个数据块读入到目录项缓冲 `dir[32]` 中
（3）初始化 `dir[0]` 和 `dir[1]` 两个目录项，这两个目录项对应两个特殊的文件，. 文件和.. 文件
（4）由于是通过目录项找到文件索引结点，再通过文件索引结点找到文件的数据块，所以在根目录中，. 文件和.. 文件的目录项结构体中的索引号都设置成 1，那么根据. 和.. 这两个文件名找到他们的目录项之后，找到的还是根目录本身，显然. 文件和.. 文件在根目录中确实是表示文件本身的
（5）初始化根目录的第 0 个数据块之后需要将其写回到磁盘中的第 0 个数据块


### `allocate_block()` 分配数据块功能

（1）需要载入数据块位图到缓存中，修改数据块位图，并更新到 `FS_zqw_zzw.txt` 文件（磁盘中），这里数据块位图需要先从磁盘载入到 bitbuf 这个 512 字节专门存放位图的缓冲区，然后才能修改，再写回磁盘，因为这里 bitbuf 是所有位图公用的缓冲区

（2）需要更新内存缓冲中的组描述符中的空闲块个数，并更新到磁盘中，这里组描述符不需要重新从磁盘载入内存，再修改再更新回磁盘

（3）需要找到位图中哪个块是空闲的，并将空闲块号返回

#### 在 512 字节的位图中寻找空闲块号的功能实现

前提是 512 字节的位图已经放入了 bitbuf 缓冲区中，一个字节 8 bit，可以表示 8 个数据块的分配信息

其实就是从上一个已经被分配的数据块所在的位图字节开始，往后遍历，看哪个位图字节有空闲的数据块，如果遍历到最后一个位图字节都没有空闲的，则回到最开始的位图字节继续寻找

找到空闲的位图字节之后，通过下面的代码找到它具体是这个字节的哪一个 bit：

```cpp
    // 找到一个空闲的位图字节后与100000000按位与，并用flag来记录位图块的哪一位是0，也就是空闲的数据块
    // con = 1 0000 0000
    while (bitbuf[cur] & con)
    {
        con = con / 2; // 将100000000的1不断往后移动继续按位与操作
        flag++;
    }
```


### `get_inode()` 分配索引结点功能

基本思路和分配数据块是一样的

（1）载入 inode 位图到 bitbuff 中，并找到一个空闲的 inode，返回 inode 号，修改 inode 位图，并更新到磁盘
（2）修改组描述符，并更新到磁盘
（3）inode 的号是从 1 开始的，所以在 inode 位图中寻找空闲 inode 号的时候逻辑稍微有点不一样

### `reserch_file()` 查找文件函数的实现

根据文件名和文件类型遍历当前目录文件的所有目录项来查找文件

（1）利用 current_dir 变量获得当前目录文件的索引结点号
（2）将当前目录文件的索引结点号加载到内存
（3）通过目录文件的索引结点号获得它所占据的所有数据块
（4）将每个数据块读入到 `dir[32]` 中，遍历这个目录文件的所有目录项

从而得到：
（1）待查找文件的索引结点号
（2）待查找文件的目录项在当前目录文件中的数据块号
（3）待查找文件的目录项在当前目录文件中的某个数据块中的目录项号（一个数据块可以存放 32 个目录项）



### `cd()` 命令的实现

（1）需要根据目录文件名调用 `search_file` 函数获得目录文件的索引结点号
（2）将 `current_dir` 变量切换到目录文件的索引结点号，这样就完成了基本的文件切换
（3）如果文件名是 `.`，则什么都不会改变
（4）如果文件名是 `..`，由于 `.` 和 `..` 也当作了普通文件，这两个文件的占据的是一个目录文件的第 0 个数据块的第 0 个目录项和第 1 个目录项，因此调用 `search_file` 的时候同样会查找到 `..` 文件的索引结点号（当前目录的上一级目录的索引结点号），这个时候同样可以完成切换
（5）如果是 `..`，则还需要在当前路径中阶段当前目录名的位置，这样下次循环的时候输出目录就是上级目录的路径了

### `mkdir()` 命令的实现

（1）需要加载当前目录的索引结点到缓冲区中
（2）判断当前目录是否有空闲的目录项，判断原则是看当前目录文件的大小是否与它所占的数据块总大小相等（文件大小与文件的数据块大小是不一样的）
（3）如果有空闲目录项，需要不停的加载当前目录的每个数据块的 32 个目录项到目录项缓冲区 dir【32】中，找到这个空闲目录项，将空闲目录项中设置新创建的文件的文件名，索引结点号，文件类型，更新 dir 到原来的数据块中
（4）如果没有空闲目录项，需要给当前目录分配一个新的数据块，修改当前目录的 inode 结点，然后将新的数据块内容读入到 dir【32】中，将 `dir[0]` 设置新创建的文件的文件名，索引结点号，文件类型，更新 dir 到数据块中

### `prepare()` 函数，初始化新创建的文件的索引结点，或者目录的索引节点以及目录的初始内容

创建完了文件或者目录，初始化了这个文件或者目录在上一级目录文件中目录项之后，并且分配了一个索引结点，然后调用 `prepare` 方法，来初始化索引结点（目录文件需要初始化它的第一个数据块）

（1）如果是普通文件，则只需要初始化下文件大小和所占数据块即可，以及权限
（2）如果是目录文件，
