### 反向传播的核心逻辑

（1）从输出变量开始，调用它的 backward 方法
（2）取出它的生成函数放到一个 list 中
（3）只要 list 不为空则继续循环，这个循环的逻辑是
（4）从 list 中取出一个函数，获得它的输入输出，调用这个函数的 backward 方法，计算输入变量的导数，然后再将输入变量的生成函数挨个追加到 list 列表中，进入下一轮的循环

### 你是怎么实现 softmax 交叉熵函数的正向传播的？

给定的 x 是多个样本，

（1）首先计算每个样本的指数和然后再求对数之后的结果，为了防止溢出，可以先让每个样本的元素减去自己分量中的最大值，然后再取指数，最后的效果是：

$$
\ln((e^{x_{1}-M} + e^{x_{2}-M}\dots) *(e^{M})) = \ln(e^{x_{1}-M} + e^{x_{2}-M}\dots) + M
$$

最后得到的结果就是 log_z

log_z 是一个列向量，这个向量的每个维度都是每个样本的取指数之和再取对数的结果
（2）然后是计算每个样本 softmax 取对数的结果

$$
\ln \frac{e^{x_{1}}}{e^{x_{1}}+e^{x_{2}}\dots} = \frac{{\ln e^{x_{1}}}}{\ln(e^{x_{1}}+e^{x_{2}}\dots)} = x_{1} - \ln(e^{x_{1}}+e^{x_{2}}\dots)
$$

所以每个样本 softmax 再取对数的结果就是每个样本的分量元素直接减去这个样本的所有元素取指数然后再取对数的结果了

也就是 x - log_z

（3）根据标签 t，按照交叉熵计算公式，取出 softmax 并取对数之后每一个样本输出中概率最大的那个加起来，然后再除以样本个数 N，这样就得到了所有样本的平均交叉熵损失

### 你是怎么实现数据批量加载，打乱，预处理的？

**打乱**

（1）打乱，实际上不是真实的打乱数据，而是生成一个样本数长度的一个列表，这个列表是样本编号的随机排列，然后读取数据的时候从这个随机列表中取出行号，这样就达到了打乱数据的效果

（2）并且 Datalodaer 中还有一个属性 matinteration，最大迭代次数，当在模型训练中达到最大迭代次数的时候，就会自动调用 reset () 方法，再生成一个随机样本行号列表，供下一次 epoch 训练使用

**批数据加载**

Dataloader 实现了__inter__和__next__这两个方法，将自己变成迭代器

这样在主文件进行模型训练的时候可以直接通过 for x in train_loader 来取出 batch_size 个数据放入模型进行训练

在__next__方法中，根据迭代次数，按顺序从随机行号列表中取出 batch_size 个数据，直接返回就好了

**预处理**

这个预处理实际上封装在 Dataset 类的 transform 属性中，在 Dataloader 的__next__方法中，实际上是调用了它保存的 Dataset 类中的 getitem 方法，在 getitem 方法中利用 transform 属性（它是对某个函数的引用）然后将数据处理之后返回给 Dataloader，然后再返回给用户

### 你遇到的 bug？

遇到一个印象深刻的 bug 是 numpy 对矩阵乘法的一个兼容的隐蔽 bug

我在测试 Linear 处理多样本线性回归的时候，在生成训练数据的的时候使用的 x 是一个 100 * 4 的矩阵，而 W 我直接指定成了一行 4 个样本的数据（我实际上是想要 W 是 4 * 1 的参数，但是误操作生成了单行的 4 元素数据）

但是 numpy 仍然会执行 100 * 4 与 (4, ) 形状的数组进行矩阵乘法，生成的数据是消去了维度 4 的结果，即 (100, ) 这样形状的数据

这个数据在加上参数 b，以及一个形状为 (100, 1) 的随机噪声之后，会被 numpy 自动广播成 (100, 100) 的数据，但是这显然是不对的，正确的训练数据 y 应该是 (100, 1) 的形状，但是诡异的是 numpy 会让其一直执行下去，一直到计算误差的时候发现维度不正确

bug 原因就是我一直以为 numpy 是严格按照形状来检查矩阵乘法是否合法的，不知道它对一维数组的兼容

后续每次不管是测试数据还是做什么，我都是没偷懒严格生成固定形状的矩阵，这样就没有出现 bug 了
