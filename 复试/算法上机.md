### sort 函数

#### 对单个数组元素进行排序

sort 函数是 C++中的函数

对 vector 进行升序的操作是 :

```cpp
vector<int> a;
sort(a.begin(), a.end());
```

上面的 a.begin () 表示指向 a 的第一个元素的指针；a.end () 是指向最后一个元素的后一个位置的指针, sort 函数的括号中对元素是左闭右开的

对普通数组 a[]进行升序排序是：

```cpp
int a[n];
sort(a, a + n);
```

如果想要降序操作还得加上一个 cmp 函数：

```cpp
bool cmp(int &x, int &y) {
   return x > y;
}

int main(){
	int a[n];
	
	sort(a, a + n, cmp);//此时降序排列
}
```

这里 cmp 函数的含义就是保证前后两个元素 x, y 满足 cmp 函数中为 ture 的规则
#### 对数组之间进行排序

比如，如果想要按照数组元素个数对数组排序，并且两个数组的元素个数相等的时候数组元素按照字典序排序（字典序就是当两个数组元素个数相同的时候，前 k - 1 个元素相等，如果第 k 个元素 a[k]  < b[k]，则数组 a 排序在 b 前面）

```cpp
vector<vector<int>> result; //一堆待排序的数组

//自定义排序规则
bool cmp(const vector<int> &a, const vector<int> &b){
	//先保证个数小的在前
	if(a.size() ！= b.size()) return a.size() < b.size();
	else return a < b;//个数相等的时候保证字典序
}

sort(result.begin(), result.end(), cmp);


```

### CPP 中的循环变量回收问题

| 变量类型        | 生命周期         | 回收机制       | 风险提示           |
| ----------- | ------------ | ---------- | -------------- |
| 基本类型 (int等) | 每次迭代结束       | 栈内存立即回收    | 无风险            |
| 对象类型        | 每次迭代结束       | 析构函数调用+栈回收 | 注意析构函数副作用      |
| 原始指针        | 每次迭代结束（指针本身） | 栈回收（指针变量）  | **堆内存泄漏**（高风险） |
| 智能指针        | 每次迭代结束       | 自动释放管理的内存  | 无风险            |
基本变量和对象类型是指在循环中定义的 int，double, string 之类的，一次循环结束的时候其会自动回收，下一次循环或者跳出循环这个变量就不能再使用了，比如：

```cpp
for (int i = 0; i < 5; ++i) {
    int temp = i * 10;      // 基本类型
    std::string s = "test"; // 对象类型
    
    // 每次迭代结束时：
    // 1. s的析构函数会被调用（释放字符串内存）
    // 2. temp和s的栈内存会被回收
}
```

指针类型的话，如果是普通的指针，其与基本变量是一致的，指针变量本身会被销毁，但是指针变量指向的 new 语句的内存不会被销毁：

```cpp
while(p && p->next){

        ListNode* temp = new ListNode(p->val);//temp指针变量每次循环都会重新创建
        //但是new的内存空间不会被回收，temp是这块内存空间地址
        //后面的语句是让这个内存空间的next指针指向上一个内存空间
        //这些内存空间以及各自的关系不会在循环结束后发生改变，改变以及销毁的只是存放这个内存空间地址的容器temp指针

        temp->next = pre;

        pre = temp;

        p = p->next;

    }
```

### C ++中的数组传参和二维数组传参

==二维数组传参==

**数组形式传参**

这里的列必须是常量，是一个具体常数 3，或者 4；或者是一个 const int n；不能是 int n

```cpp
void func(int a[][3], int rows) { // 必须指定列数（此处为3）
    for (int i = 0; i < rows; ++i) {
        for (int j = 0; j < 3; ++j) {
            cout << a[i][j] << " ";
        }
    }
}

int main() {
    int arr[2][3] = {{1,2,3}, {4,5,6}};
    func(arr, 2); // 传递数组名和行数
}
```

**`vector<vector<int>>` 形式传参**

下面是一个使用 `std::vector<std::vector<int>>` 容器进行二维数组传参的完整示例：
```cpp
#include <iostream>
#include <vector>

// 1. 按值传递（会创建副本，适用于需要修改副本的场景）
void printByValue(std::vector<std::vector<int>> matrix) {
    std::cout << "按值传递:\n";
    for (const auto& row : matrix) {
        for (int num : row) {
            std::cout << num << " ";
        }
        std::cout << "\n";
    }
    matrix[0][0] = 100; // 修改不影响原始数据
}

// 2. 按常量引用传递（推荐，避免拷贝，只读访问）
void printByConstRef(const std::vector<std::vector<int>>& matrix) {
    std::cout << "\n按常量引用传递:\n";
    for (const auto& row : matrix) {
        for (int num : row) {
            std::cout << num << " ";
        }
        std::cout << "\n";
    }
}

// 3. 按引用传递（可修改原始数据）
void modifyMatrix(std::vector<std::vector<int>>& matrix) {
    std::cout << "\n按引用传递（修改前）:\n";
    for (const auto& row : matrix) {
        for (int num : row) {
            std::cout << num << " ";
        }
        std::cout << "\n";
    }
    
    // 修改原始数据
    for (auto& row : matrix) {
        for (int& num : row) {
            num *= 2; // 每个元素乘以2
        }
    }
}

int main() {
    // 创建二维vector
    std::vector<std::vector<int>> matrix = {
        {1, 2, 3},
        {4, 5, 6},
        {7, 8, 9}
    };

    // 1. 按值传递调用
    printByValue(matrix);
    
    // 2. 按常量引用传递调用
    printByConstRef(matrix);
    
    // 3. 按引用传递调用（会修改原始数据）
    modifyMatrix(matrix);
    
    // 显示修改后的结果
    std::cout << "\n修改后的原始矩阵:\n";
    printByConstRef(matrix);

    return 0;
}

修改后的原始矩阵:

```

| **传递方式**         | **语法**                              | **特点**                              | **适用场景**    |
| ---------------- | ----------------------------------- | ----------------------------------- | ----------- |
| **按值传递**         | `vector<vector<int>> matrix`        | 创建完整副本，修改不影响原始数据，但可能有性能开销（拷贝整个二维数组） | 需要独立修改副本的场景 |
| **按常量引用传递** (推荐) | `const vector<vector<int>>& matrix` | 无拷贝开销，只读访问，安全高效                     | 只读取数据不修改的场景 |
| **按引用传递**        | `vector<vector<int>>& matrix`       | 无拷贝开销，可直接修改原始数据                     | 需要修改原始数据的场景 |

### C++中的内存释放与悬挂指针

==delete 的用法==

delete 后面跟的应该是一个内存的地址，用于释放这块内存，将内存还给 OS

（1）delete 释放单个对象的内存

```cpp

// 创建单个对象
MyClass* obj = new MyClass(); 
// 释放对象
delete obj;       // 正确用法
obj = nullptr;    // 推荐：避免悬挂指针

TreeNode* lchild = new TreeNode();
root->left = lchild;//将lchild指向的内存地址赋给root->left这个指针，此时lchild和root->left其实是指向同一块内存区域

delete lchild;//或者这里用delete root->left
root->left = nullptr;
lchild = nullptr;
```

（2）delete 释放多个对象的内存

```cpp
// 创建对象数组
MyClass* arr = new MyClass[10]; 

// 释放数组
delete[] arr;     // 注意 [] 符号
arr = nullptr;

int* numbers = new int[100];
delete[] numbers;  // 即使基本类型也需要 delete[]
numbers = nullptr;
```

==悬挂指针==

当使用 delete 释放某一块的内存之后，这块内存被交给 OS 可以被重新分配，但是，之前指向这块内存的指针的值仍然是这块内存的地址，相当于这个指针仍然指向这块内存，这个就是悬挂指针

由于这个指针不为空，所以其实它也可以被访问，但是访问或者修改它指向的内容就会出错，最好的方法是在用 delete 释放这块内存之后将指向这块内存的指针置空

### 一个用来知道 BFS 遍历到树的哪一层的技巧

![image.png](https://typora-1310242472.cos.ap-nanjing.myqcloud.com/typora_img/20250704210412.png)

这道题目关键在于两点：

（1）得剔除掉不必要的结点，不让他们加入到队列中，避免复杂度爆炸
（2）剔除结点接入到队列中的时候，层序遍历就不是一个完整的树，此时不能通过结点计数取 2 的对数来确定当前结点的高度，而是在 `while(q.size())` 循环内部的刚开始加上一个 `cnt = q.size()`，这个 cnt 就表示当前层的结点个数，然后在 while 循环内部再加上一个 for 循环用于遍历当前层的结点，这个 for 循环中加入的结点一定是下一层的结点，并且 for 循环会剔除当前层的结点，这样你下次再进入 while 循环的时候得到的 q.size () 就一定是下一层的所有结点个数了
（3）根据（2）这样 while 每次循环都是一层层的遍历结点，于是可以根据 while 循环的次数来判断层序遍历的层数了

```cpp
int h = 0;
while(q.size()){
	int cnt = q.size();
	h ++;//每进入while循环一次h ++ ，表示树的高度++，根结点是第一层
	//for循环用来遍历当前层的所有结点并将他们全部剔除
	//同时在for循环中加入下一层的结点
	for(int i = 0; i < cnt; i ++){
		int temp = q.front();
		q.pop();
		q.push(leftchild);
		q.push(rightchild);
	}
	//for循环结束之后当前层的结点就完全被剔除了，此时q中就只有下一层的结点了
	//再进入while循环的时候cnt就是下一层结点的个数了
}
```

### 1

![image.png](https://typora-1310242472.cos.ap-nanjing.myqcloud.com/typora_img/20250609154649.png)

这里保证数组 a 是从小到大排列，b 是从大到小排列
![image.png](https://typora-1310242472.cos.ap-nanjing.myqcloud.com/typora_img/20250609154918.png)

这种情况下 a 和 b 的元素逐个相加

（1）如果此时满足逐个相加 <= x，那么可以推出有这样一个排列成立

（2）如果此时不满足逐个相加 <= x，假设此时 ai + bi > x，即不存在一个 bi 与 ai 配对的排列满足题意

那么此时，如果将 bi 往前换，那么 ai 前面一定有一个 ak 配对 bk >= bi 要被换到后面与 ai 以及后面 aj 配对，显然此时 bk 都大于等于 bi 了而 ai + bi > x，那么 bk 往后面配对的时候也一定有 bk + a (i ~ j) > x，所以不存在一个 bi 与 ai 之前的元素配对的排列满足题意

如果将 bi 往后换，那 ai 后面一个要有一个 aj 与 bi 对应，但是 ai + bi > x，那显然 aj >= ai 也满足 aj + bi > x，所以不存在一个 bi 与 ai 之后的元素配对的排列满足题意

所以在这种情况下只要逐个相加有不满足的元素对，那么就不可能通过调整，使得 b 的一个排列与 a 逐个相加成立了，也就不存在一个排列满足题意

所以可以通过判断数组 a 是从小到大排列，b 是从大到小排列，逐个元素配对来等价判断是否有一个 b 的排列满足题意


### 2

![image.png](https://typora-1310242472.cos.ap-nanjing.myqcloud.com/typora_img/20250618154500.png)

如果可以通过调整变成互不相同的数，那么这些数一定可以形成一个严格递增的序列

于是我们可以先对数组从小到大排序，对于排序之后的数组，如果有一个策略使得其可以严格递增，那就等价于原数组有一个调整策略符合题意（因为排序之后元素本身没有变化，对排序之后的每个元素的调整可以直接放到原数组对应元素的调整，并且严格递增了，当然互不相同）；同样如果排序之后的数组不存在一个策略满足严格递增，那么原数组也没有一个策略满足题意了

**即对排序之后的数组进行调整得到一个严格递增的序列与原数组调整使得各个数互不相同具有等价性**

这里的策略是，对于相邻的两个元素 a[i]和 a[i + 1]，设 a[i]调整之后的数值是 last 且没有与前面的数发生冲突；那么 a[i + 1]就在 a[i + 1] - 1, a[i + 1], a[i + 1] + 1 这三个数中选择一个满足大于 last 的最小的数；这样可以留给后面的数的调整空间尽可能的大

如果按照这种策略调整完了之后，数组是严格递增的，那么对这些数在原数组中对应位置进行同样的调整，那当然就存在一个策略满足了题意；

下面来说明如果这种策略失败，那也不存在一个别的策略将排序之后的数组调整成严格递增，既然排序之后的序列没有一个策略将其调整成严格递增的，那这些数就不能调整成严格递增的序列，那原来的数组就不可能经过调整后重新排列获得一个递增的排列（有点小问题，不过就这样吧，不纠结了）

下面来证明当这种策略失败之后，没有别的策略可以将其调整成严格递增的

这种策略失败的情况是，a[i]调整为 last 的时候没有冲突，但是对于a[i + 1]，其可能调整的数值a[i + 1] - 1, a[i + 1], a[i + 1] + 1 都小于上一个数 a[i]的调整数值 last，那么这个时候，只可能有 a[i] = a[i + 1]才会出现这种情况，并且 last = a[i] + 1 = a[i + 1] + 1（因为如果 a[i] < a[i + 1]，那么 last 最大也才是 a[i] + 1 = a[i + 1]，a[i+ 1] 完全可以调整为 a[i + 1] + 1 来保证没有冲突）

那么对于 a[0] <= a[1] <= a[2] <= ... <= a[i] = a[i + 1]，假设还有一个别的调整策略使得冲突没有发生，也就是还有一个别的调整策略使得可以调整成严格递增的序列，那么此时对于 a[0] ~ a[i - 1]这些数，假设 a[k]是第一个与原策略调整之后不一样的数，原策略 a[k] = M 1, 新策略 a[k] = M 2，并且原策略 a[k-1] = N，由于 a[k]的调整只能是 a[k] - 1, a[k] a[k] + 1 三种可能，原策略调整为 M 1 保证了严格递增且M 1 的含义是三种可能中第一个大于 a[k-1] = N 的数，那么新策略必须保证 M 2 > M 1

也就是说，这个新策略与原策略相比，第一个不同的数 a[k]经过调整后必然是大于原策略的，那么a[k]后面的数，经过新策略的调整也必然不会比原策略小；因此对于 a[i]其经过新策略调整的数值有 last >= a[i] + 1，所以 last 还是 a[i] + 1，此时 a[i + 1]还是无法调整，出现矛盾

简而言之，就是如果原策略调整失败，那么新策略为了保证严格单增进行调整的时候会导致原来的数往大了调整，这会导致 a[i]还是会调整成 last，a[i + 1]仍然会调整失败，所以原策略调整失败之后不存在一个别的策略可以调整成功

所以原贪心策略将排序之后的数字调整成严格递增的序列具有等价性，这个策略可以，那就可以看，这个策略不行，那就不行

于是就可以通过对排序之后的数组使用这个策略来判断原来的数组是否有一个策略调整成互不相同的了
